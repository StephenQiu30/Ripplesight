# HotKey 文档

HotKey 是一个**公开资讯阅读站 + 个人舆情监控**工具，个人非商业使用。本目录同时是一个 Obsidian 仓库，也会发布成网站。

## 阅读顺序

给人和 AI 的建议顺序：

1. [PRD](product/01-PRD.md)：为什么做、为谁做、目标和版本规划。
2. 与任务相关的[能力](#能力)文档（`capabilities/`）：要做成什么样、现在到哪一步、怎样算完成。
3. 与任务相关的[决策](#决策)（`decisions/`）：必须遵守的规则。
4. [进度与优先级](product/02-进度与优先级.md)、[技术架构](product/03-技术架构.md)。

每份文档开头都有元数据（frontmatter）：`type`、`title`、`summary`、`status`、`updated` 等。AI 可以先读元数据，再决定打开哪份文档。

## 写作规则

1. **一份文件只讲一件事**：能力文档控制在约 6000 字符以内，决策和记录各控制在约 2000 字符以内，PRD 控制在约 12000 字符以内。
2. **用模板新建**：模板在 `templates/` 里，有能力、决策、验收记录、调研四种，元数据字段不能少。
3. **规则只写一处**：产品规则写在 `decisions/`，技术约定写在根目录的 PROJECT/AGENTS，进度只写在根目录的 BACKLOG。
4. **改决策要本人同意**：旧决策不删除，把 `status` 改成 `废弃`，并新建一条决策替代它。
5. **验收结果一次一份**：放在 `records/`，用 `capability` 字段指向对应能力，并同步更新该能力文档的 `status`。
6. **命名**：文件夹用英文（`product/`、`capabilities/`、`decisions/`、`records/`、`research/`、`templates/`、`views/`）；文档用“两位编号-中文名”，例如 `capabilities/04-评论舆情.md`；验收记录和调研以日期开头，例如 `research/2026-10-06-开源方案调研.md`。新文档取同目录下一个未用的编号，编号发布后不改、不复用。
7. **链接用标准相对路径** `[文字](路径.md)`，不用 `[[双链]]`。
8. 用简单的话写；除文件名编号和 PRD 中的 KR 外，不另起编号体系。
