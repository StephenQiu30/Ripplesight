# AI 任务协议

先读[需求与验证入口](04-需求与验证入口.md)，遵守根目录[工程规范](03-工程规范.md)。本页把 2026-10-07 用户反馈落实为阅读与执行约定；未填的业务答案仍待确认。

## 最小阅读路径

1. 读本轮用户消息和需求入口，确定阶段：需求核对、POC、demo 或正式实现。
2. 读[进度](01-进度与优先级.md)的当前检查点，确定本轮任务。
3. 只读相关能力、相关决策和一张验证卡；需要核对行为时再读对应源码和运行证据。
4. 跨模块依赖真正影响当前验证时，才追加架构或执行计划。无需先读全部历史文档。

## 开始执行前必须能够复述

| 必须说清 | 例子或要求 |
|---|---|
| 需求来源 | 用户哪句话、文档哪一节；分清原话与 AI 推断 |
| 用户的问题 | 谁在什么时候要完成什么，不从技术方案反推 |
| 本轮要证明的唯一事项 | 用一句能判断真假的话表达 |
| 本轮最小输入和输出 | 一个主题、一批来源内容、一份能查看的结果等；数量是提案时标明待确认 |
| 不在本轮的内容 | 与该假设无关的来源扩展、定时任务、报表、抽象层等 |
| 证据 | 真实数据出处、时间、操作步骤、结果位置及失败判据 |

缺少业务答案时，先整理差异和候选，继续不依赖答案的文档工作；不擅自补成完整需求。用户说“先别写代码”时，验证卡准备好也不开始编码。

## 文档状态不能代替验证

| 证据 | 能支持的结论 | 不能直接支持的结论 |
|---|---|---|
| 需求原话、已确认文档 | 要验证什么、边界是什么 | 实现已满足需求 |
| 源码和配置检查 | 存在某条实现路径、默认值是什么 | 实际环境已启用且跑通 |
| 单元测试、固定样本、构建 | 受控条件下逻辑或工程检查通过 | 真实来源可用、内容有价值 |
| 手工导入的真实样本 | 下游处理能对这一批内容工作 | 上游采集已接通、持续稳定 |
| 真实来源的本次完整运行 | 本轮场景走通，指定结果可核对 | 所有来源可用、长期稳定 |
| 用户操作与反馈 | demo 满足或不满足这次场景 | 已经完成全量产品验收 |

每项结论要能追到依据。正文引用相对文件链接和具体章节；回复用户时引用绝对文件路径及可定位的行号。不要只写“已完成”“全面通过”“架构已就绪”。

## 执行和交付

按[POC 验证卡](06-POC验证卡.md)限定范围。POC 获准后优先复用已有路径；为回答假设只做必要的一段，时间到或遇到关键失败时记录结果，再判断方向。真实外部请求仍遵守工程规范与已有授权边界。

交付应当包含：可操作入口或结果文件、输入来源、复跑步骤、实际输出、成功/失败结论及局限。用截图补充呈现，用原始结果和步骤说明发生了什么。空数据、固定样本和真实来源结果必须明确标注。

完成一张卡后，先回看原假设；有证据支持才提出下一张。不得自动扩成多平台覆盖、长期运行、完整仪表盘或重构项目。一次验证通过，只更新该验证结果，不自动把能力状态改为“可用”。
