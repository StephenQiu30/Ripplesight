# PRD：Ripplesight

本文是 Ripplesight 的总纲：为什么做、为谁做、做成什么样、怎样算成功、先做什么。每项功能的细节见[能力文档](../../index.md#能力)，共同规则见[决策](../../index.md#决策)。

**2026-10-07 当前范围**：用户明确要求关键词驱动的帖子与评论监控，判断相关性并考虑时效性；最终覆盖国内主流平台及 X、Instagram 等海外平台，POC 先验证国内主流平台。本轮基于免费项目重新整理功能/非功能需求、架构、数据库与验收设计，不启动业务实现。原话见[需求入口](../reference/04-需求与验证入口.md)。本文保留生效需求；下面明确标为“AI 提案”的平台清单、样例、规则与数值仍待验证，不因本文的 `status: 生效` 自动成为已确认需求。旧 V1/V2 目标保留为后续核对依据。

项目维护所用的 workspace 知识库见[专项 PRD](02-PRD-workspace项目知识库.md)：在 frontend 工作台统一阅读、权限、AI 检索与网页 / Obsidian 编辑，独立排期；业务报告与资料知识库仍按[05](../../capabilities/05-报告推送与知识库.md)执行。

本轮选型重心按最新用户指令转为 [GitHub 免费热点与评论采集调研](../../research/2026-10-07-GitHub免费热点与评论采集调研.md)：对比实时线索、关键词与评论采集、star、维护和可复用功能，**取数无必需付费 API 或服务是首要门槛**。原[商业竞品调研](../../research/2026-10-07-热点监控市场与竞品调研.md)保留背景；[用户旅程与优先级](../../research/2026-10-07-用户细分旅程与POC优先级.md)仍是待验证判断，均非真实采集或试用结果。

## 1. 摘要

Ripplesight 的当前产品主线是 **AI 辅助的关键词事件监控**：用户配置关心的主题，获得相关帖子及其评论，优先阅读相关且及时的内容，并能核对出处。按用户要求，先用 AI 行业主题举例；产品不据此限定为只监控 AI 行业。个人非商业定位沿用既有决策。

此前“公开资讯阅读站 + 个人舆情监控”的公开阅读、日报、负面告警目标继续保留，均不作为本次 POC 的必要交付。

## 3. 背景

用户需要在多个平台反复搜索，结果重复、同名噪声多，评论上下文分散；拿到热榜标题不等于取得主题原帖，刚抓取也不等于刚发布。现有开源方案能复用部分取数和阅读流程，但没有证据证明国内全平台免费、完整、持续可用。

[GitHub 调研](../../research/2026-10-07-GitHub免费热点与评论采集调研.md)改变了三个设计前提：费用与许可逐路径准入；搜索、详情、评论、增量分别验收；上游能力清单不代表本项目已接通。现有主题、任务、内容、评论与 Codex 骨架继续复用，不重建平台框架。

[源码差距](../../research/2026-10-07-热点事件需求核对.md)显示硬过滤漏召回、监控列表缺相关性排序、日期回退及评论增量证据缺口；本轮工程核对还发现相关性结果耦合情感字段，必须连同契约与数据库约束设计解耦，不能只改提示词。

## 4. 目标

### 当前 POC：找到相关帖子，并读到可追溯的评论

唯一业务假设：在明确的国内平台和时间范围内，关键词加相关性筛选能让本人从可核对的帖子与评论中找到值得跟进的内容。每个平台独立验证这条链路；单个平台成功不能代表全部国内平台通过。

**以下数值为 AI 提议的验收初值，执行前冻结在验证卡中；免费取数是用户已确认底线**。在每个平台首轮与次轮采集、以及一次用户 demo 后评估；不预设某个日历日期上线。

| 要回答的问题 | 验收初值与计算口径 |
|---|---|
| 免费取数是否成立 | 已确认底线而非 AI 数值提案：记录实际版本、选定路径及必需依赖；不购买数据 API、代理、打码、签名或账号，不以赠送/试用额度替代免费路径。费用或必需依赖不明则不准入；源码核对不能代替实际运行记录 |
| 帖子和评论是否取到了 | 每个平台至少 10 条真实去重帖子，至少 3 帖合计 30 条可读评论；每条均有原生标识、来源与时间状态，评论能定位原帖和直接父评论或明确的父链缺口。达不到时记证据不足，不能补造数据 |
| 最前面的内容是否相关 | 冻结候选池上 P@10 ≥80%，即前 10 条中人工判为“直接相关”的条数 / 10；同时报告纯关键词基线。返回不足 10 条不改分母宣称达标。AI 未改善时不宣称 AI 增益 |
| 是否漏掉已知相关内容 | 抽查过滤前候选和独立人工找到的同窗帖子；报告“可见样本内漏判/漏采”及原因。平台全量不可得时，不报告全网召回率 |
| 时间和更新是否可信 | 在有可信发布时间的结果上核对窗口边界；未知/异常时间误标为新内容为 0。单轮开始到结果可读暂定 ≤10 分钟；同时记录采集、模型等待与展示耗时，不把这个数当发现延迟 |
| 重复采集是否可靠 | 同一配置第二轮重复帖子/评论不新增一份；发现新评论时挂回原帖；没有新内容与采集失败分别呈现 |
| 用户是否能完成任务 | 本人在 demo 中配置一个主题、识别至少一条有价值的新信息、展开评论并打开原文；同时记录无关结果及反馈。人工用时先测基线，不虚构节省比例 |

评估协议、失败场景及阶段结论见[需求核对](../../research/2026-10-07-热点事件需求核对.md)，实际输入与结果写入[国内平台 POC 验证卡](../../research/2026-10-07-国内平台关键词监控POC验证.md)。10 帖是链路门槛，质量比较另需足量的校准集与评估集；仅满足前者不能宣称全部 POC 通过。资料不足属于“证据不足”；不能降低门槛后将同一轮改判为通过。

## 5. 用户群

POC 只服务第一位主题跟踪者：当他想了解一个事件的新进展和讨论时，集中找到相关帖子与评论。国内平台覆盖是本轮验证方向，海外是后续产品目标；“国内主流”的完整边界以 §7.2 清单核对，不承诺全站全历史采集。

| 用户群 | 他们要完成的事 | 限制条件 |
|---|---|---|
| **主题跟踪者**（首要：本人） | 持续盯住几个关心的主题；第一时间知道新动向；了解大家怎么评价；需要时能回头找到出处 | 一个人使用；本机部署；平台账号只用自己的；不能花钱 |
| **公开读者**（次要） | 不登录，快速读到当天值得看的资讯和事件，并能点开原文核实 | 只能看到发布账号允许公开的内容 |

暂不服务：团队协作、企业品牌监测、商业数据转售。

## 6. 价值主张

本次先验证“少翻无关内容、看清新旧、保留评论上下文与出处”。热度、相似度与相关性分别呈现；刚采到、点赞多或措辞相似，都不能单独说明它与用户关心的事件相关。

| 用户要做的事 | 获得什么 | 阶段与价值 |
|---|---|---|
| 跟踪主题 | 一个页面汇总已接入平台的命中及更新状态 | 当前 POC：减少分散搜索，覆盖和缺失明确，不保证不漏 |
| 理解讨论 | 评论原文、父链和时间 | 当前 POC：看懂上下文；情感分布与代表观点是后续目标，本次不验收 |
| 每天掌握大事 | 08:00 日报 + 今日社媒热点 | 后续目标，本次 POC 不验收 |
| 核实来源 | 打开原文，并看到来源和时间 | 当前 POC：能够核对出处，不把提供链接等同于已证实内容真假 |

差异化是待验证假设：在本人单账号、零第三方费用和本机运行下，提供可解释的相关结果、评论上下文与证据。商业产品已有类似功能；不以“竞品没有评论”、star 或开源名称证明优势。成功取决于真实可得性、阅读价值与维护负担。

## 7. 方案

### 7.1 用户流程

**当前 POC 的最小 demo（AI 提案）**

```text
填写主题含义、关键词和排除词 → 选择国内平台与时间窗 → 预览并执行一轮
  → 查看平台成功/空/部分/失败状态 → 看相关性、原文时间与采集时间
  → 展开原帖下的评论与父链 → 打开原文 → 标记相关/无关及理由
  → 同配置再跑一轮 → 识别新帖、新评论和失败 → 决定下一平台或调整规则
```

只复用一个结果列表、一个评论展开区和一次配置流程，不新建完整舆情驾驶舱。后续保留两条流程：公开读者浏览资讯/事件/刊物并跳转原文；主题跟踪者登录配置主题，经每小时采集与分析，在主题页阅读讨论，按已验收规则收到告警、日报/周报及知识库导出。具体频率和后续验收见对应能力文档，本次不整包执行。

### 7.2 关键功能

#### 功能性需求与优先级

按 `pm-execution:prioritization-frameworks` 使用 MoSCoW 分配当前验证范围，不编造 RICE 的用户数、信心或收益。下表为本轮设计基线提案，详细规则接续本节；“必须”是所选切片的完整性要求，非授权同时开发全部平台。

| 条款 | 用户可观察的行为与验收边界 | 当前优先级 |
|---|---|---|
| 来源准入与能力说明 | 配置显示关键词/详情/一级评论/回复/增量各自能力、免费路径、许可版本与未接入原因；未知费用不能启动 | 必须 |
| 主题与版本 | 创建、修改、预览、暂停、恢复与归档；主题含义、词组、平台、时间窗、预算保存为运行快照；修改不污染在途任务或旧结果 | 必须 |
| 查询与候选留存 | 显示平台实际查询与本地过滤区别；有界保存过滤前候选、命中/排除原因和查询出处，供复盘漏判 | 必须 |
| 执行与停止 | 一次启动返回运行标识并能查看进度；来源分别报告结果；暂停阻止后续调度，取消尽力终止在途任务；已落库结果保留 | 必须 |
| 原帖与证据 | 原生 ID、来源、原文或可取文本、时间依据和采集批次可核对；详情失败不能用搜索摘要冒充完整帖子 | 必须 |
| 评论与父链 | 按相关原帖和预算取样，展示根帖/直接父评论及缺口、排序与截断；短回复结合上下文判断，不只过滤评论关键词 | 必须 |
| 去重与增量 | 同源同 ID 幂等；跨采集器同一平台原帖关联，转载保留出处；第二轮必须能区分重新抓取与重读缓存 | 必须 |
| 相关性与排序 | 四档标签、理由与证据；情感可不执行；模型失败保留关键词基线及未分析状态，规则版本/模型版本可追溯 | 必须 |
| 结果阅读与反馈 | 按主题/平台/时间/相关性筛选，稳定分页；展开评论、打开出处、标注相关/无关及理由；归档不自动删除证据 | 必须 |
| 时间与覆盖说明 | 发布时间/首次发现/抓取/可读时间分开；未知日期单列；无结果、未接入、失败、预算截断分别展示 | 必须 |
| 热榜快照与排名变化 | 保存名次/线索变化辅助发现，不能代替关键词原帖与评论 | 应有，原帖链路后 |
| 连续调度与情感报告 | 既有每小时目标、告警和日报保留到后续阶段，未达门槛不启用完整产品流程 | 本次不验收 |


#### 当前平台范围

“国内主流全部支持、海外包括 X 和 Instagram、POC 只验证国内”来自用户；**下列枚举与推进顺序是 AI 工作清单，尚非用户确认的穷尽名单**。一个平台的“支持”至少分别回答：关键词发现帖子、取得文本与时间、采评论及父链、增量更新、相关性排序、显示失败状态。只支持热榜或导入链接不能标成完整关键词监控支持。

| 平台工作清单 | POC 的内容对象 | 验证安排提案 |
|---|---|---|
| 微博 | 帖子、长文可用文本、评论/回复 | 首个候选，先验证文本讨论链；若不可用记录原因，不用 HN 成果替代 |
| 抖音、小红书、B 站 | 视频/笔记的标题、说明与可取文本，评论/回复 | 接着逐个平台验证；视频画面和音频不在本次文本 POC 内 |
| 知乎、快手、百度贴吧 | 问答/文章、视频文本、主题帖及评论/楼层回复 | 国内覆盖工作清单；独立记录来源对象差异，不能用微博结果外推 |
| 今日头条、微信公众号、微信视频号 | 文章/内容说明及平台实际开放的评论 | 同列国内需求清单，获取方式和评论可得性是高风险待验证项，不能静默删掉以宣称国内已覆盖 |
| 百度、新闻网站等搜索/资讯入口 | 搜索结果、报道与热榜 | 是发现线索的补充来源，不能替代社交平台原帖和评论；具体站点清单待核对 |
| X、Instagram（ins）及其他海外主流平台 | 帖子及平台允许取得的评论 | 已确认长期覆盖方向；不纳入本次国内 POC，其余海外名单待定 |

Instagram 从旧冻结范围进入用户明确的长期目标；本次未启动接入，因此[冻结决策](../../decisions/11-冻结范围.md)的当前执行边界仍保留。未来启动时按决策流程修订，不由本轮文档自动解除所有海外或客户端冻结项。

#### 关键词示例与匹配约定

**教学示例，不是对真实近期事件的陈述**：监控“DeepSeek 新模型发布后的使用体验与故障反馈”。主题含义关注发布进展、功能、价格、效果与可用性，不关注只有品牌名的广告。用户可替换为任何事件。

| 输入 | 示例或约定（AI 提案） |
|---|---|
| 任一词 | `DeepSeek`、`深度求索`、`深求`；别名“深求”先人工确认，避免扩大误命中 |
| 全部词 | 首轮留空；填入后每个词都必须满足，不能把“发布、体验、故障”同时填入而误以为它们是任选 |
| 排除词 | 例如 `代充值`、`账号出售`；这是硬排除，会误杀揭露售号骗局的相关帖，预览必须展示被排除项 |
| 主题说明 | “希望看到新模型发布、真实体验和故障讨论；泛 AI 新闻或只有品牌名的广告不算直接相关” |
| 时间范围 | 首轮建议最近 72 小时，评估时固定窗口终点；不是保证此窗口内一定有上述事件或足量数据 |

匹配规则建议为：排除词优先；任一词至少命中一个；全部词逐个满足；别名作为对应词的候选表达。忽略英文大小写并规范空白，保留原文及命中片段；中文子串、缩写与跨语言误命中加入验证样例。原生查询无法表达同一规则时，用较宽查询取候选，再本地核对；显示实际查询和过滤字段。不得把热榜本地过滤显示成全站关键词搜索。

平台应先用用户审核过的关键词/别名召回候选，再判断内容是否真正讨论主题。**只对字面命中做 AI 重排，无法找回在上游被排除的近义表达**；近义词扩展应留版本、来源和人工审核记录，不能默默修改主题。

#### 相关性、相似度与去重

- **相关性**回答“是否在谈这个主题”：提议人工与 AI 共用“直接相关 / 弱相关 / 无关 / 信息不足”四档，附支持判断的原文片段和简短理由；模型无结果显示“待分析/失败”，不当作无关。
- **相似度**回答“两个文本有多像”：可辅助重排或提示重复，不能把复述、否认或旧闻都判为同一新事件；暂不承诺某个余弦阈值有效，也不预先引入向量数据库。
- **去重**先按平台原生 ID、规范原帖 URL 识别同一记录；近似转载只折叠提示，保留各原帖和评论。不同平台的相同措辞不合并作者或评论父链。
- **排序初值**：先按时间窗和硬规则筛选；“推荐”显示直接相关项，按可信发布时间倒序、原生 ID 固定破同分；弱相关与信息不足另区展示。“最新”也只在通过相关性门槛的集合内排序。评估期间保留基线次序；热度仅作参考，不用点赞盖过不相关。
- 优先复用本机 Codex 做有限候选的相关性判断；用同一候选池对照关键词基线。是否需要更细分数、语义召回或时间衰减，等误例和评估结果决定。AI 自报置信度不显示成经过校准的准确率。

#### 评论范围与时间约定

采评论先跟随相关原帖，再结合帖子和直接父评论理解“太贵了”“终于修好了”等回复；评论不必复述关键词。区分“属于这个讨论”与“包含对主题有用的信息”，无关灌水不因挂在相关帖下就成为代表观点。保留平台、原帖 ID、评论 ID、父评论 ID（或缺失原因）、文本、来源链接/定位方法、发布时间、首次发现时间、抓取时间、样本顺序与截断标记。删除/不可见/拉取失败不能都算零评论。

单帖建议先最多 20 条可读评论、每个平台最多 5 个重点帖；按来源可用的排序取样并记录热评/最新/默认及页数。父链缺失时明确提示，不猜补；该样本不能代表全平台舆论，本次不做情感占比、画像与代表性承诺。

| 时间概念 | 产品要求（AI 提案） |
|---|---|
| 发布时间 | 来源声明的原始时间，用于内容新旧；保留时间来源、精度及可信状态，不用抓取时间补成“刚发布” |
| 首次发现 / 抓取 / 可读时间 | 分别用于发现延迟、更新过程与处理耗时；展示字段含义，重复抓取不重置首次发现 |
| 窗口边界 | 以冻结的截止时间 T 和窗口 W，按半开区间 `[T-W, T)` 纳入可信发布时间；上游多返回边界内容时在本地统一过滤；统一存储时区，界面显示北京时间并允许核对原始时间 |
| 无日期、模糊日期、未来异常日期 | 进入“时间待核对”区域，不参加“最近 72 小时”达标统计；模糊时间保留可推定区间，不编造秒级精度 |
| 旧帖新评论 | 在本轮已选定的帖子集合内，第二轮按评论时间识别新增讨论；标“旧帖有新回复”，不重置帖子发布时间；未扫描旧帖的评论覆盖不作保证 |

内容年龄＝截止时间减发布时间；发现延迟＝首次发现减发布时间；处理耗时＝结果可读减任务开始。首次回填与持续监控的延迟分开报告；平台搜索索引延迟、评论排序限制及模型排队分别记录。

### 7.3 工程设计与非功能性需求

架构唯一说明在[技术架构](../reference/02-技术架构.md#12-关键词监控工程设计提案)，实体、字段、约束及建议差量在[数据库设计](../reference/07-关键词监控数据库设计.md)；`backend/database/schema.sql` 仍是唯一可执行建表源。本轮没有修改 DDL、接口或业务代码。

继续采用现有 FastAPI、Next.js、PostgreSQL、Worker/Scheduler、Outbox/Kafka 和本机 Codex；按需要选择已有本机服务与采集适配器。热榜、平台搜索、详情、评论用不同能力契约；不新增微服务、第二套任务队列或向量数据库作为 POC 前提。完整证据、状态机和交付关口见[验证与交付设计](../../research/2026-10-07-关键词监控验证与交付设计.md)。

下表费用、账号、凭据和隔离沿用既有底线；性能数值、工作量和恢复目标为 **AI 提案，执行前以本机基准冻结**，不宣称已达到 SLA。

| 非功能条款 | 可检验的目标与测量方式 |
|---|---|
| 费用可控 | 必需第三方服务费用为 0；登记来源依赖与版本，费用未知不请求，不自动启用收费降级路径 |
| 访问与隐私 | 所有主题、运行、候选、评论、分析及证据读取/重试均校验所属用户；跨用户及匿名越权样例返回拒绝；本人登录可见材料不自动进入公开阅读 |
| 凭据与模型隔离 | Cookie/Token 不入数据库明文、日志、前端或模型输入；采集文本为不可信数据，模型不能执行其中指令或调用外部工具；结构校验失败不进入有效分析 |
| 风控与预算 | 识别验证码、登录失效、限流后，该来源人工恢复前不启动新请求；重试仍占原预算，运行消耗不超过请求/页数/条数/时间限额，超限明确部分结果 |
| 数据正确与幂等 | 重复启动/消费/页回放不新增相同原帖或评论；同次请求不重复记账，真实重试仍消耗预算；父链缺口不伪补，规则变更可重现旧结果；时间窗统一 UTC 半开区间 |
| 实时性 | 可信源日期才计算发现延迟，回填与持续监控分报；单轮到可读初值 ≤10 分钟，超时展示部分结果；缓存响应时间不当发布时间，无日期误标新内容为 0 |
| 交互性能 | 本机 1,000 帖/10,000 评论、2 个并发读取，每个列表/评论首屏接口各至少 30 次；冷/热缓存分测，全部样本 P95 ≤2 秒且错误/超时为 0 才判该轮达标；采集与模型异步 |
| 恢复与一致性 | 成功提交的页在取消/重启后保留；只有完成确认的页推进检查点，查询范围未完成不前推完整水位；重复消费和超时恢复用故障样例验证 |
| 可观测性 | 每次运行可追到主题版本、查询、采集器版本、候选/过滤/分析数、截断/失败原因、耗时、模型用量和证据位置；日志无敏感值，空数据不冒充成功覆盖 |
| 可维护与替换 | 适配器仅处理来源差异，统一契约测试覆盖必需字段、时间与错误分类；固定上游版本与署名，替换采集器不改主题/评论的产品含义 |
| 留存与恢复 | 原文、候选、运行、分析、证据依既有留存策略联动清理，执行前记录期限；删除不留越权可读副本；首次变更前完成独立恢复核对，禁止在业务库直接执行建表脚本 |
| 易用与可解释 | 键盘可完成配置与阅读，桌面及 390px 显示核心状态；空/加载/部分/失败/未授权有明确含义，标签和时间可下钻核对，不用不可解释综合分数掩盖缺口 |

### 7.4 假设（需要验证）

当前最大假设是：零费用路径可持续取得国内原帖/评论；规则能召回足量候选；相关性分档改善阅读；时间和父链可追溯；本机资源与维护投入可接受。按真实风险、担忧过度和未讨论假设进行[风险预演](../../research/2026-10-07-关键词监控验证与交付设计.md)，每个关口分别记录通过、未通过或证据不足。

历史假设只保留为核对背景：情感 85% 目标尚未验证，失败不能自动换其他模型；单账号每小时采集不保证不会风控；20—50 条评论不保证代表总体，提高采样上限不能自动修复偏差；公开趋势页可用性、日报省时和本机 72 小时承载仍需实测。当前不以这些假设扩大采集、替换模型决策或恢复完整日报范围。

## 8. 发布

当前按“需求核对 → 国内首平台完整链路 → 其余国内平台逐项验证 → 同主题跨平台 demo → 根据证据决定继续/收缩/换来源”推进。每个平台复用同一张验证卡结构，先解决最大不确定项再开始下一项；不同时重写全部采集适配器。全部拟验收平台逐项有结论后才评审国内 POC；有平台阻塞就报告部分验证，用户未调整范围前不能宣布国内覆盖完成。

时间投入提案：每个平台首次可行性验证限半天（不含等待本人登录），到点提交成功/失败/证据不足的结果；评测和 demo 在取得足量样本后安排。尚无实测速度，不对“全部主流平台”作工期承诺。海外接入、全天调度、情感告警、日报、事件自动聚类、音视频理解和完整看板留待后续单独决定。下表是历史版本估算，不是本次 POC 排期。

| 版本 | 包含内容 | 预计时长 | 完成标志 |
|---|---|---|---|
| **V1 每日舆情** | 启用本机 Codex 分析；X 趋势 + 日报“今日社媒热点”；B 站与微博评论；4 个搜索来源 + 6 个热榜跑通；舆情告警 | 第一阶段，约 2—4 周 | KR1、KR3、KR4 达成，KR2 达到 3 个平台 |
| **V2 完整舆情** | 抖音、小红书评论；X 账号试点；舆情看板与主题热点页；72 小时稳定运行；公开阅读稳定；邮件推送 | 第二阶段，V1 之后约 3—5 周 | KR2、KR5、KR6、KR7 达成 |
