# PRD：Ripplesight

本文是 Ripplesight 的总纲：为什么做、为谁做、做成什么样、怎样算成功、先做什么。每项功能的细节见[能力文档](../../index.md#能力)，共同规则见[决策](../../index.md#决策)。

项目维护所用的 workspace 知识库见[专项 PRD](02-PRD-workspace项目知识库.md)：在 frontend 工作台统一阅读、权限、AI 检索与网页 / Obsidian 编辑，独立排期；业务报告与资料知识库仍按[05](../../capabilities/05-报告推送与知识库.md)执行。

## 1. 摘要

Ripplesight 是一个**公开资讯阅读站 + 个人舆情监控**工具，供个人非商业使用。不登录的人可以读到有出处、不重复的资讯；登录后，用户设好关心的主题，每小时自动拿到各平台的热点和评论，每天收到一份讲清“发生了什么、大家怎么看”的日报，负面情绪突然上升时会收到提醒。

## 3. 背景

**现在的问题**
- 想跟踪一个话题时，需要分别去 X、微博、抖音、小红书、B 站、知乎和新闻网站搜索，每天花很多时间，还容易漏掉。
- 搜到的内容大量重复，同一件事被转来转去。
- 光看帖子不够，还想知道评论区怎么说、情绪偏正面还是负面，但这些只能一条条去翻。
- 现成的工具要么太贵、面向企业（商业舆情系统，按年收费），要么只覆盖新闻和 RSS（Google Alerts、Feedly），基本不看中文社交平台的评论。

**为什么是现在**
- 本机已经能免费运行 RSSHub、SearXNG、Firecrawl、MediaCrawler 等开源组件，覆盖国内外主要平台，不需要购买 API。
- 本机 Codex 可以直接用来做相关性判断、情感分析和写摘要，不产生额外费用。
- Ripplesight 已有的采集、去重、事件、报告代码基本完成，缺的是：把各个平台真正接通，再把模型分析打开。

## 4. 目标

**目标一：让我每天花 15 分钟，就能掌握关心主题的热点和舆论风向。**

| 关键结果 | 基线 | 目标 | 衡量方式 |
|---|---|---|---|
| KR1 日报按时到达，并包含“今日社媒热点” | 0 天 | 连续 7 天，每天 08:00 前生成；每天 ≥10 个 X 趋势，每个附 ≥1 条报道 | 日报记录与抽查（[03](../../capabilities/03-每日社媒热点.md)） |
| KR2 能看到评论的平台数 | 1（HN） | ≥4 个平台，每个 ≥50 条真实评论 | 数据库统计与页面抽查（[04](../../capabilities/04-评论舆情.md)） |
| KR3 情感判断准确 | 未测 | 200 条人工标注样本上，准确率 ≥85%，负面召回率 ≥85% | 冻结样本评测（[04](../../capabilities/04-评论舆情.md)） |
| KR4 负面突增能及时发现 | 无 | 发生后 ≤65 分钟内站内告警，且不重复通知 | 真实触发记录（[04](../../capabilities/04-评论舆情.md)） |
| KR5 每天手动去各平台搜索的时间 | 第一周实测 | 比基线减少一半以上 | 本人每天记录用时 |

**目标二：让不登录的读者，读到持续更新、不重复、有出处的资讯。**

| 关键结果 | 基线 | 目标 | 衡量方式 |
|---|---|---|---|
| KR6 持续更新 | 未测 | 连续 72 小时，至少每 2 小时有新内容；采集有效完成率 ≥95% | 任务记录（[01](../../capabilities/01-公开资讯阅读.md)） |
| KR7 不重复、有出处 | 未测 | 抽查 50 条：重复 0 条，每条都能打开原文 | 人工抽查（[01](../../capabilities/01-公开资讯阅读.md)） |

**底线指标**（任何时候都不能突破）：第三方服务费用为 0；登录平台出现风控后，人工恢复之前新增请求为 0；凭据泄露事件为 0。

## 5. 用户群

| 用户群 | 他们要完成的事 | 限制条件 |
|---|---|---|
| **主题跟踪者**（首要：本人） | 持续盯住几个关心的主题；第一时间知道新动向；了解大家怎么评价；需要时能回头找到出处 | 一个人使用；本机部署；平台账号只用自己的；不能花钱 |
| **公开读者**（次要） | 不登录，快速读到当天值得看的资讯和事件，并能点开原文核实 | 只能看到发布账号允许公开的内容 |

暂不服务：团队协作、企业品牌监测、商业数据转售。

## 6. 价值主张

| 用户要做的事 | 获得什么 | 避免什么痛点 |
|---|---|---|
| 跟踪主题 | 一个页面汇总中外平台的命中内容，每小时更新 | 不用逐个平台去搜；不会漏掉某个平台 |
| 了解舆论 | 评论原文、情感分布、代表观点，每条观点都附原文引用 | 不用一条条翻评论；不会被 AI 编造的观点误导 |
| 每天掌握大事 | 08:00 日报 + 今日社媒热点 | 不用刷热搜 |
| 核实真假 | 每条内容都可以打开原文，并看到来源和时间 | 不会看到无出处的二手信息 |

**价值曲线**（高 / 中 / 低，定性判断，尚未经过用户访谈验证）：

| 维度 | Ripplesight | Google Alerts | Feedly | TrendRadar（开源） | 商业舆情系统 |
|---|---|---|---|---|---|
| 中文社交平台覆盖 | 高 | 低 | 低 | 中（热榜） | 高 |
| 评论与情感分析 | 中→高 | 无 | 低 | 低 | 高 |
| X 每日热点 | 中 | 无 | 低 | 低 | 中 |
| 出处可追溯 | 高 | 中 | 高 | 中 | 中 |
| 使用费用 | 0 | 0 | 中至高 | 0 | 很高 |
| 数据留在本机 | 高 | 低 | 低 | 高 | 低 |
| 配置门槛 | 中（需要本机部署） | 低 | 低 | 中 | 低（有服务团队） |
| 团队协作与规模 | 低（不做） | 低 | 高 | 低 | 高 |

**Ripplesight 胜在**：零费用、覆盖中外社交平台的评论、每条观点都能核对出处、数据留在自己电脑上。**主动放弃**：团队协作、企业级规模、零门槛的云服务。

## 7. 方案

### 7.1 用户流程

**公开读者**

```text
打开首页 → 浏览资讯流 / 精选 / 事件 → 打开单条 → 跳转原文核实
                └→ 查看公开日报、周报 → 查看模型榜
```

**主题跟踪者**

```text
登录 → 新建主题（关键词、排除词、别名）→ 预览命中情况 → 保存
  → 每小时：各平台采集 → 去重 → 判断相关性、情感、观点
  → 主题页：热点汇总 + 舆情看板（声量、情感、平台分布、代表评论）
  → 负面突增：站内告警 →（邮件，待配置）
  → 每天 08:00：日报（主题重点 + 今日社媒热点 + 舆情摘要）
  → 每周一 08:00：周报 → 导出到 Obsidian，之后可以检索和提问
```

### 7.3 技术

- 后端用 Python + FastAPI，Web 用 Next.js，数据存 PostgreSQL；后台任务由 Worker 和 Scheduler 两个独立进程执行。详见[技术架构](../reference/02-技术架构.md)。
- 所有外部数据都通过本机开源服务获取：RSSHub、SearXNG、Firecrawl、MediaCrawler、twscrape；模型只用本机 Codex。
- 复用开源项目的规则见[优先复用开源项目](../../decisions/08-优先复用开源项目.md)。

### 7.4 假设（需要验证）

| 假设 | 如果不成立 | 怎么验证 |
|---|---|---|
| 本机 Codex 的情感判断能达到 85% 准确率 | 换用其他本机模型，或只展示原文不做判断 | KR3 评测 |
| 本人单账号每小时采集一轮，不会被平台封号 | 降低频率，或改成只采热门帖子 | 各平台试运行 7 天，记录风控次数 |
| getdaytrends 等公开趋势页会持续可用 | 改用 trends24（经 Firecrawl），或只保留账号试点 | 连续 7 天的成功率 |
| 每帖 20—50 条评论足以反映舆论 | 提高上限，或按热度挑选评论 | 和全量评论的情感分布做对比抽查 |
| 日报能把每天手动搜索的时间减半 | 调整日报结构或推送时间 | KR5 每日记录 |
| 一台电脑就能扛住每小时的采集和分析 | 降低频率或减少主题数 | 观察 72 小时的资源占用和任务延迟 |

## 8. 发布

| 版本 | 包含内容 | 预计时长 | 完成标志 |
|---|---|---|---|
| **V1 每日舆情** | 启用本机 Codex 分析；X 趋势 + 日报“今日社媒热点”；B 站与微博评论；4 个搜索来源 + 6 个热榜跑通；舆情告警 | 第一阶段，约 2—4 周 | KR1、KR3、KR4 达成，KR2 达到 3 个平台 |
| **V2 完整舆情** | 抖音、小红书评论；X 账号试点；舆情看板与主题热点页；72 小时稳定运行；公开阅读稳定；邮件推送 | 第二阶段，V1 之后约 3—5 周 | KR2、KR5、KR6、KR7 达成 |
| **以后** | 知识库问答；模型榜真实发布；Codex 公告；Reddit（待官方 API 批准）；补充更多热榜 | 按需排期 | 各自能力文档的验收标准 |

时长是粗略估计：项目没有历史开发速度数据，而且很多步骤要等本人提供账号或凭据。各版本具体做什么、目前进度如何，见[进度与优先级](../reference/01-进度与优先级.md)。
