# PRD：全站页面需求

## 1. 摘要

把已重建的 Ripplesight 页面逐一连接到功能、数据、权限、接口、异常和验收，供人和 AI 按单个页面或完整旅程实施。本文件是[总 PRD](01-PRD.md)的页面专项细化，不另建产品方向或任务进度。具体需求以本目录下的 `product/pages` 为细节源，状态只在 [BACKLOG](../../../../BACKLOG.md)。

**用户已确认**：先把当前代码提交并推送 main，再分析每个页面需要什么，形成表格、需求、功能/非功能、详细数据库和接口设计，并持久化进项目。上一轮确认按指定 Figma 桌面稿重建、采用 shadcn 和 Vercel 工程规则。[原话与阶段](../reference/04-需求与验证入口.md)负责保留来源。

**事实基线**：代码 `4489b400`，52 个页面入口、247 个生成 API 函数、123 张建表定义；数量是源码盘点，不是可用能力数量。52 页拆出 185 项主要行为，每页包含规则表、现有调用和数据表、缺口、五状态与验收。页面按路由模板计数，动态 ID/刊期/页签不重复计作页面。设计稿主要画框之外的账户、管理、文档、说明页也纳入。

**文档状态**：生效范围仅指用户已确认的逐页整理方式、需求来源和约束；下列未确认的功能增量与数值明确作为提案保留，不能据元数据认定已获准实施。

**提案边界**：原型中的数据、比例、趋势和名称不构成业务证据；新接口/表、指标阈值、发布顺序均为可评审提案，未自动获得实现或真实外发授权。现有实现不因列入表格而被认定正确。本轮不改业务 API、DDL、采集器或分析提示词。

## 2. 联系人与职责

| 角色 | 责任与决策 |
|---|---|
| 需求提出者／本人 | 确认用途、页面优先级、公开策略、同步选择与体验验收 |
| 产品分析与实现代理 | 维护同一需求源，核对现有代码、列出缺口、按已授权切片实现与测试；不自称用户研究已完成 |
| 工程审查角色 | 按 AGENTS 核对权限、数据、契约和恢复；现有 Claude 审查要求仍适用 |
| 运行验收角色 | 在明确账号、来源和预算范围内验证真实流程，分别记录样本与真实证据 |

不在公开文档填写个人联系方式、用户 ID、Cookie 或生产连接信息。

## 3. 背景与机会

视觉页面已经连接公开资讯、个人监控及运营工具，但设计稿还包含当前 API 无法证明的概览、曲线、情感、平台趋势与云端备注。若仅沿页面逐项补数，容易把本页样本当全网统计、把私有热度带入公开页面、让收藏丢失许可边界，或制造第二套任务/存储。

本次设计围绕四个缺口：页面需要什么；现有数据实际能支持什么；缺失部分如何最小补齐；怎样证明它可用。既有国内免费关键词 POC 与小时运行证据仍按原记录判定，不因为页面更完整而扩称海外覆盖、评论全量、稳定 SLA 或情感准确率。

## 4. 目标与可衡量结果

以下是交付验收目标，不是已经测出的结果；无日历承诺，以各切片评审和实际运行窗口为准。

| 结果 | 判定方法与门槛 | 对应范围 |
|---|---|---|
| KR1 页面不遗漏 | 52/52 路由有唯一需求页，所有主要行为有规则和可操作验收 | 页面总表与每页文档 |
| KR2 数据可解释 | 所有显示计数/比例/曲线说明范围、窗口、分母、未知和版本；禁止示例值进入真实结果 | 首页、事件、榜单、监控、告警 |
| KR3 权限不穿透 | 匿名/本人/其他账号/运营身份矩阵中越权泄漏为 0；撤回后的正文、导出与聚合不可复活 | 公私读取及全部写操作 |
| KR4 契约可追踪 | 页面现有函数可定位方法、类型、后端；所有新增需求有合同、数据设计和失败恢复场景 | 247 函数与增量设计 |
| KR5 可持续交付 | 文档命名/链接/索引/构建/搜索有效；实施切片具备独立回滚与真实验收证据后才标能力可用 | 文档及发布门槛 |

耗时、容量、可访问性、恢复目标统一放在[非功能需求](../reference/10-全站非功能需求.md)。本文不复制另一组数字。

## 5. 用户细分与任务

| 用户／场景 | 核心任务 | 成功结果与限制 |
|---|---|---|
| 匿名公开读者 | 从今日热点发现事件、读资讯和固定刊物、核对模型榜 | 能回到来源；仅看当前允许公开的投影 |
| 个人主题跟踪者 | 配置关键词、检查来源、运行、读帖子与评论、关注变化 | 看懂命中/无结果/跳过/未知；只管理本人资源 |
| 内容与运营维护者 | 审核发布许可、来源和模型配置，查看成本/失败 | 独立运营授权、版本冲突与操作记录可见 |
| 项目文档维护者 | 阅读需求、编辑草稿、比较冲突、发布快照 | Git/Markdown 单一正文，允许清单控制，失败仍读上一完整快照 |

这些细分来自现有页面及本人用途，不是已完成访谈或市场验证。无额外企业租户、付费订阅或原生移动端需求。

## 6. 价值主张与完整旅程

| 旅程 | 页面顺序 | 可见价值与结束条件 |
|---|---|---|
| 发现到证据 | 首页 → 探索/公开专题 → 公开事件 → 资讯 → 原文/收藏 | 解释为什么值得读，事实与观点有出处；返回保留筛选 |
| 关键词到行动 | 登录 → 来源 → 新建主题/预览 → 运行回执 → 结果/评论 → 私有事件/告警/报告 | 规则、窗口、覆盖、版本和停止原因可核对；未知不能变成“没有舆情” |
| 阅读到复用 | 固定刊期 → 收藏选择 → 导出/Feed/Agent | 固定引用和许可保持一致，私人笔记不混入公开分发 |
| 审核到发布 | 私有资料 → 发布管理 → 公开读取 → 撤回 | 授权和内容修订生效，正文/摘要/媒体/聚合同步受限 |
| 需求到实现 | 文档目录/搜索 → 页面需求 → 接口/数据 → 草稿 → 发布 → 单个实施切片 | 无第二份进度；可定位源码和验收 |

### 共用功能和业务规则

| 规则 | 页面和实现要求 |
|---|---|
| 设计规范 | 按 Figma 主框架与 DESIGN 令牌；shadcn/Radix 及语义组件统一，保留当前路由、焦点和可访问名称；Vercel 规则用于读取并行、包体和服务端边界。设计示例不是数据源。 |
| 公私边界 | `/discover/stories` 是公开事件；`/events` 是本人事件；`/editions` 是内部刊期；`/reports/[reportId]` 的 daily/weekly/monthly 与私有报告 ID 是不同分支。不可按外观决定授权。 |
| 读写边界 | 打开或刷新页面不触发采集、模型调用或通知；真实写入明确按钮、版本和结果。返回页面不能重放提交。 |
| 结果可信度 | 来源、对象身份、发布时间/首次发现/观测分开；同对象去重；分析给证据和版本；空、未知、失败、跳过不同。 |
| 状态和恢复 | 每页正常/空/加载/错误/无权限；冲突保留草稿，取消不宣称撤回已执行外部动作，受理不等于完成。 |
| 个人保存 | 当前收藏与阅读在本机；云同步须主动选择，不能把新需求误读为现有云能力。撤回内容不从本机全文复活。 |
| 输出与阅读 | 长正文、表格、代码、引用、图表缺口可读；导出和 Agent 读取不绕过原权限；下载只包含所选可读数据。 |
