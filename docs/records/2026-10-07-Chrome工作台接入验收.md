# Chrome 采集接入工作台验收

## 做了什么

按用户“demo 跑通后接入真实前后端”的指令，使用 pm-execution:test-scenarios 组织验收。来源页新增账号受限的 Chrome 预设入口；主题页展示入库资料并链接原有评论详情；适配器接入原有搜索/评论执行器；宿主入口限定绑定账号、来源和任务类型。沿用现有 PostgreSQL 表、outbox、租约、预算及去重，不导入 demo JSON、不增加 DDL。

## 结果

- 最终独立库固定样本：单元、架构、认证与采集集成 1650 项通过；补充来源/主题/搜索/评论/预算集成 79 项通过、2 项跳过；包括根评论入库、跨账号 404、重复投递无外发、到期受理一次和风控暂停。不能作为真实平台证明。
- 全量后端曾执行至 358 通过、16 跳过和 5 失败后停止；5 个失败均在未改 main 基线复现，涉及覆盖及资料历史/搜索。全量检查未通过。
- 前端 950 项通过，lint、类型、格式、生产构建与客户端契约检查通过。认证修复见[注册流程记录](2026-10-07-登录注册流程修复.md)。
- 使用 Chrome 当前真实账号从来源页启用、创建 `DeepSeek · Chrome 实采` 并恢复小时监控。2026-10-07 20:09，正式 PostgreSQL 写入 2 个视频帖子；两帖根评论请求均真实执行，本轮保存 0 条，不能宣称已取得真实评论。
- 首次定时受理在子进程 3 秒启动限时失败，来源请求为 0；专用运行器启动限时改为 15 秒后，经页面重试，后台定时轮询执行成功。任务如实为 `partially_succeeded`，原因是有界单页抽样，非全量覆盖。
- 宿主 `com.ripplesight.chrome-monitor` 每 60 秒轮询既有小时日程；旧 demo 采集已停止，旧结果预览保留。当日旧 22 次请求已通过正式预算预留/结算计入，新首轮 6 次，共 28 次。日上限 60、静默 00–08 点继续生效。
- 桌面已看见两条真实资料，评论页错误后重试恢复为空态。随后发现长正文被 flex 压缩、页脚覆盖资料，已给正文容器补 `shrink-0`；52 项布局回归、lint、类型和构建通过。复核期间浏览器控制连续超时，前端重启后新标签页恢复，截图确认结果可读且页脚不再覆盖；证据为本机 `.tools/chrome-integration/results-desktop.jpg`。390px 完整验证未取得，临时视口已恢复默认，未将超时记为通过。
