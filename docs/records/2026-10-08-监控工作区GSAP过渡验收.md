# 监控工作区GSAP过渡验收

## 做了什么

本人要求先提交推送main，再继续实现。基础交互提交`0a9e18b7`已推送；本轮延续GSAP优化，处理结果、采集运行、编辑设置，以及进阶／报告设置的展开。验收先补在[DESIGN](../../frontend/DESIGN.md)。

保留按钮行、DOM键盘顺序、URL tab及内容挂载；语义面板和官方Radix Collapsible共用180ms高度／透明度过渡。遵循[GSAP官方React接入](https://gsap.com/resources/React/)的useGSAP、ref、contextSafe清理。快速反向从当前高度接续，逐帧测量内部高度，padding放在内部，结束恢复自然高度。减少动态效果直接切换。

关闭时焦点返回控制按钮，并应用inert／aria-hidden。进阶／报告字段保留草稿，关闭时fieldset禁用，排除隐藏必填字段的原生校验；提交非法值或服务返回422时重新展开并定位。复用字段的新建主题入口同步核对，业务payload和默认值不变。

- Web lint、双tsconfig typecheck、format:check、生产build通过。最终`pnpm test --maxWorkers=1`：123文件1023项，零失败、零跳过。新增草稿／URL／焦点和隐藏报告字段错误定位两项回归，保留版本冲突、422与重复写入保护。独立只读subagent另跑2文件12项通过，未发现确定性新缺陷。
- 首轮与本机其他工程及build并行时出现冷启动／交互超时，并发现依赖收起即卸载的旧断言。旧断言改为检查隐藏字段禁用，全量串行复跑通过，没有改超时或skip。首轮日志保存在本机，不把首次失败算作通过。
- 隔离生产8672和固定样本API8671：1440×1000、390×844分别检查正常、空、加载、错误、无权限，共10状态；唯一main、状态文字和无横向溢出断言通过。正常主题的结果为空，如实展示“还没有采集结果”。本机截图、几何和脚本在`.tools/monitor-motion-20261008/`。
- 浏览器快速反向保留同一input节点和草稿，URL恢复settings；内部焦点关闭时返回编辑按钮，隐藏面板inert。原生Tab依次经过结果、运行、编辑按钮，没有进入隐藏结果的刷新按钮；减少动态效果时立即结束并清除高度样式。
