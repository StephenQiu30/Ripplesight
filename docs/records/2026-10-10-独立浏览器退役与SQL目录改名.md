# 独立浏览器退役与SQL目录改名

## 范围

backend/browser原为可选Playwright/Chromium远程服务，Squid代理限制出口，默认关闭。源码消费核查确认BrowserRuntime唯一生产入口是probe-browser，业务采集没有调用它；因此按用户要求删除两项Compose服务、三个专用网络、浏览器Docker阶段、远程运行时、专用配置、探测命令及专用测试。CI同步移除专用跳过白名单，其余意外跳过仍失败。

浏览器会话凭据合同与browser_state_dir仍有消费者，报告导出另有本地Playwright用途，均保留。没有删除持久数据、业务采集适配器或接口。

backend/database改名backend/sql，schema.sql逐字不变，SHA-256为1044c53552a2bc828884ddbe9f10b13f3107af3338ac0b05a872a1c2dc2ce7ae。初始化挂载、Docker复制、维护和CLI备份恢复、CI、架构断言及现行文档均同步新路径。

## 验证

- uv run ruff check、ruff format --check、mypy通过；mypy检查437个源码文件。
- 普通pytest：1606通过、954跳过；跳过项缺少完整集成环境，不能计为通过。
- 独立hotkey_test_browser_sql_*空库执行新路径schema成功；test_database_schema与test_backup_restore共10项通过、零跳过。使用本机PostgreSQL18.4、匹配的pg_dump/pg_restore及独立19000端口临时MinIO，测试后数据库、进程和临时存储全部清理；未操作业务库或已有MinIO数据。
- 直接执行runtime CI中的开发/生产Compose一致性、基础设施分离及凭据隔离断言通过；应用仅保留backend、frontend、worker、scheduler、cli。
- 后端镜像ripplesight-backend:browser-sql-check构建通过；独立只读审查及git diff --check通过。文档索引和链接检查同步执行。

本轮只修改工程结构和退役无消费者组件，未重启已有业务服务、未执行真实平台采集、未重跑前端浏览器验收。用户随后授权将SQL目录改名与独立浏览器退役分别提交main并推送。普通测试仍有原有依赖弃用警告；独立集成结果不代表全部集成测试或PostgreSQL17环境验收。
