# 监控工作台体验接入

## 做了什么

根据[体验设计](../research/2026-10-07-监控工作台体验设计.md)，用户在提交推送后要求继续，将结果优先的结构接入真实前端。使用现有 shadcn/Radix Tabs、Collapsible、Item 等组件，不更换组件库。实际进度以 [BACKLOG](../../BACKLOG.md) 为准。

- 默认展示监控结果；采集与运行、主题设置、告警分成页签，当前页签写入 `tab` 查询参数，保留其他参数，非法值回到结果页。
- 页签内容保留挂载并正确隐藏，切换不丢未保存草稿、校验状态、手动采集的幂等请求和受理结果；业务写请求、权限和版本冲突处理保持原逻辑。
- 桌面主题列固定窄宽，移动端可收起；已有主题、归档筛选、分页和旧详情链接保留。
- `active` 展示为“定时已启用”，与正在执行某一次任务区分。每项资料展示实际来源、对象类型、发布时间、采集时间及内容/评论入口。
- 核对源码发现资料接口按记录 ID 分页，并非最新时间排序；修正文案为“当前页最多 5 条资料”，不再误称“最近 5 条”。现有来源可能同时返回帖子与评论，按 `object_type` 区分。
- 网络刷新失败保留已显示内容并提示可能过期；401/403 清除旧内容。采集页继续说明仅有当前手动受理反馈，不伪装为自动任务历史。

## 怎么复核

打开本机 8666 的已有主题；默认查看结果，切换“主题设置”填写临时草稿，再切回结果与设置核对。切换“采集与运行”应看到手动受理范围说明；复制包含 `tab=settings` 的 URL 重新打开应进入设置。窄屏使用“切换监控主题”展开列表，检查主题和结果仍可访问。
