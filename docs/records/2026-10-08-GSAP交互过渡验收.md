# GSAP交互过渡验收

## 做了什么

来源：本人反馈实际UI/UX体验不好，明确要求使用GSAP React优化需要过渡的地方。[设计规范](../../frontend/DESIGN.md)先补充本轮验收，再实现：侧栏／正文220ms同步宽度切换、移动主题列表180ms高度过渡、页面180ms与4px轻微入场。保持官方shadcn Sidebar／Resizable／Radix Collapsible；GSAP 3.15.0与@gsap/react 2.1.2采用官方useGSAP、组件ref、contextSafe及卸载清理，许可单独记在THIRD_PARTY_NOTICES。

侧栏动画逐帧更新官方面板的真实尺寸；仅过渡或中途接手期间放开48–224px的折叠间隙，释放后恢复48px或224–320px。快速反向从当前尺寸接续，拖动不加缓动。主题列表保留挂载，收起后inert／aria-hidden，并把内部焦点交回触发按钮；桌面始终展示列表。页面不等待退场、不通过key重挂内容。减少动态效果时直接完成；监听运行中的偏好变化。

## 结果

- Web lint、双tsconfig typecheck、format:check、生产build通过。全量123文件1021项测试通过，新增2项针对隐藏焦点／输入保留与减少动效／桌面恢复的回归。首次默认并发运行中既有design-system ESLint冷启动超出5秒；使用`pnpm test --maxWorkers=2`重跑全部用例，不改超时、断言或skip。
- 实际8666只更新前端依赖与热加载源码，保留后端与业务库。鼠标240→278px、278→290px均跟手；搜索输入Ctrl+B不折叠，390px→桌面恢复同一个输入节点与278px偏好；移动正文无页面横溢。这里的真实公开事件为空，未把固定样本当成真实数据。
- 隔离生产预览8672与只读样本API8671：1440×1000和390×844分别核对正常、空、加载、错误、无权限，共10状态；状态文字、唯一main、正文高度和无页面横溢断言通过，截图／几何保存在本机`.tools/motion-20261008/`。身份和主题仅为该隔离服务的固定样本。
- 生产逐帧捕获连续240→48及快速反向→240，正文边界始终等于侧栏宽度加1px；输入节点、内容与焦点保留。动画约65ms后派发浏览器指针事件，接手前后尺寸保持一致，向右45px后侧栏等量增加，释放落到合法宽度；键盘中途ArrowRight从139.39px到211.34px，释放224px。原生方向键、Home／End另做检查，减少动效立即切到48px。复核脚本先重置隔离浏览器的测试偏好到240px，避免将之前224px的记忆宽度误当产品回归。
- 移动主题列表0→194.5px连续展开，关闭约70ms时反向可恢复同一列表节点；关闭后高度0、inert与aria-hidden，提交关闭状态后首个绘制帧焦点已回到按钮。切到桌面时，即使Radix状态closed，列表仍194.5px且可访问。首页→探索的实际导航捕获24次样式变化，内容始终可见，结束清除transform／opacity。
- WCAG 2A／2AA扫描核对桌面与移动交互；全规则扫描仍有分隔条不属于landmark的best-practice提示，官方分隔条保留直接子节点结构与完整ARIA尺寸属性。自动扫描不等于完整人工可访问性认证。
- 独立只读subagent发现原先临时CSS宽度的中断跳变；改成真实面板尺寸后复审未发现新确定性缺陷，指针与键盘接手另由实施者在浏览器核验。

本轮是过渡交互验收，不代表全站产品流程、真实登录、采集提供方或长期运行已通过；公开资讯能力继续为部分可用。验收时改动尚未提交推送；本人随后明确授权先提交推送main，再继续扩展交互优化。

## 怎么复核

在frontend执行`pnpm lint`、`pnpm typecheck`、`pnpm format:check`、`pnpm test --maxWorkers=2`、`pnpm build`。在8666打开首页，用折叠按钮连续反向、动画中拖动分隔条、输入框Ctrl/Cmd+B，并在系统开启减少动态效果。监控主题移动端验证列表收起／展开及切回桌面；原生键盘操作不应丢失焦点。

本机样本证据与复核脚本：`.tools/motion-20261008/check-motion.py`、`check-states.py`、逐帧JSON与截图；API在`/tmp/ripplesight-sidebar-check/mock-api.mjs`，只读样本不进入产品代码。检查完成后关闭临时服务与独立浏览器会话。
