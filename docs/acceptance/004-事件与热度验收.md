## EV-004-001（2026-09-28，Plan014 候选与稳定身份受控技术切片）

对应 Design004 §3—4/6—7、PRD004 `FR-004-001`、Plan014 `SPEC-014-DATA-001—004/JOB-001—002`。新增 `events` 领域：`analysis` 提供当前提示词下已判相关的版本身份，`content` 提供当前版本、真实来源和首次发布时间（缺失时用首次发现），`monitors` 提供当前关键词规则；`events` 只组合 DTO 并持有候选、成员、事件及事务。候选需共同命中关键词、72 小时窗和 PostgreSQL `pg_trgm` 标题相似度≥0.4；相似度只建立待模型确认的候选。候选指纹固定排序版本、窗口和提示词版本，最多 20 成员，模型提示词限制 24,000 字符。首次事件保存稳定 ID、修订、标题/摘要与来源成员；成员保留原内容版本和代表评论 ID，复核来源使用内容身份外键。重复确认返回同一事件；候选和主题锁、唯一当前归属索引阻止重叠候选覆盖人工归属。模型调用在数据库事务外，预算与调用记录复用 `ai` 领域，提交前再次核对当前版本及归属。

新增包显式架构登记测试先因缺少 `events` 失败，登记后通过。隔离 PostgreSQL 17 新库执行完整事务 `schema.sql`，`pg_trgm` 创建及 ORM 映射验证通过。受控集成样本使用 HN、Reddit、Mastodon 合成内容：两个相近标题形成候选，近似但不同事件及 72 小时外内容不进入候选；测试覆盖候选拒绝、未知成员/空标题、两个重叠候选并发提交、数据库拒绝重复当前归属与伪造来源、模型返回前人工分配、模拟预算拒绝及人工重试。测试中不调用真实 Codex，也不请求真实来源。`HOTKEY_EVENTS_CLUSTER_ENABLED` 默认关闭；即使原有分析开关开启，事件扫描不读事件表，Worker 也拒绝事件模型调用。

本地 PostgreSQL 17/pg_trgm 全量后端 **1016 passed、18 skipped、2 warnings**，Ruff check/format 和 mypy 通过；18 项本地跳过含未提供的 Kafka/MinIO 环境。随后补齐备份清单中的事件三表，并修正 21 条候选的分批余数及跨 72 小时相似链；新增边界单元测试通过。最终技术提交 [`63a820b2`](https://github.com/StephenQiu30/hotkey-server/commit/63a820b2843e31056e4010178940bd195e36659d) 的远端 [backend](https://github.com/StephenQiu30/hotkey-server/actions/runs/36438285903) 在隔离 PostgreSQL 17/Kafka/MinIO 环境完成 **1034 passed、8 skipped、2 warnings**，Ruff check/format、mypy、架构测试和备份恢复集成测试均通过；[contract](https://github.com/StephenQiu30/hotkey-server/actions/runs/36438285884) 与 [runtime](https://github.com/StephenQiu30/hotkey-server/actions/runs/36438285959) 工作流成功。`CHK-014-G4-001` 通过。本条只证明受控数据、幂等与并发边界。未取得 M1 已验收的真实三平台样本，B 站尚未通过 M2；没有真实 Codex 模型请求、真实事件归并或产品人工复核。Plan015 人工修订、Plan016 热度和 Plan042 页面仍待实施，`CHK-014-103/G5` 与 `AC-004-001` 保持未通过。
