# 46 任务记录

需求编号：`REQ-46`。来源：OR-03，确定程度见[00 产品目标与边界](../requirement/00-产品目标与边界.md#原始需求与来源登记)。优先级：核心。本文定义目标与验收，实际状态只在根目录 BACKLOG。

## 用户任务

任务所属用户在“想知道请求超时后是否完成以及失败在哪”的场景中，需要查看异步运行与失败回执，以便判断工作是否完成及失败在哪里。

## 范围与业务规则

运行、实际执行轮、请求尝试、预算周期分开；逐轮归属可证明，零请求取消也有执行记录；累计与单轮返回/观察/唯一身份/四类独立，迟到、重放、历史未知不猜测。

- BR-46-01：累计和单轮不同快照不能相减，upstream未知不从保存数推算。
- 共用权限、读取/写入状态及安全边界引用[00 产品目标与边界](../requirement/00-产品目标与边界.md#跨功能规则)、[10 权限与数据生命周期](../requirement/10-权限与数据生命周期.md)；本文件不复制第二份规则。

输入：本人运行ID、执行轮、请求/观察回执、预算政策与窗口、筛选和详情读取。所需业务输入合同（编号表示归属，不要求对应页面先完成）：02执行、03观察、47恢复。输出为下表可观察结果；配置、受理、执行和外部效果分别取证。

## 可验证验收用例

### AC-46-01 解释异步工作进度

- **Given**：一个运行含零请求取消轮及部分保存失败轮。
- **When**：读运行和执行轮回执。
- **Then**：两实际轮均可见；零请求取消不假造请求；失败指出阶段和已保留部分。
- **反例**：受理不能等同完成，业务失败不能当成功零条。

### AC-46-02 区分累计与单轮结果

- **Given**：同一运行两轮且有一页重放，观察有明确request归属。
- **When**：分别复算累计、单轮及预算窗口。
- **Then**：重放不移归属，单轮和累计各有快照/分母；预算窗口不当轮次；缺历史归属为未知。
- **反例**：不得用累计相减生成轮次差分或把旧观察归入新轮。

### 边界验收补充

Given limit10已用8预留2，政策降到5后同窗重试；When 请求新预留；Then 窗口不新建，remaining0及超占用原因可见，新请求拒绝。未知消费保守占用且不释放。

### 列表逐轮摘要边界

任务记录、来源覆盖窗口、主题手动运行受理任务及资料发现记录，只在有明确关联任务ID时按需读取逐轮摘要。读回任务身份和已知类型必须与关联一致；无任务不请求，无执行记录与历史归属未知分开。摘要属于所关联整个任务的各执行轮，不代表当前覆盖窗口、主题整轮或单份材料的独立增量；不跨任务、轮次或分母加总。失权/404或关联不符清除旧摘要，暂时刷新失败可保留并明确过期，收起或资源替换后忽略迟到响应。读取、重试读取与展开不得发起采集。此边界细化FR-46-01/02与AC-46-01/02，四类计量沿用FR-03-02。
