# 00 产品目标与边界

需求编号：`REQ-00`。来源：OR-01，确定程度见[00 产品目标与边界](../requirement/00-产品目标与边界.md#原始需求与来源登记)。优先级：核心。本文定义目标与验收，实际状态只在根目录 BACKLOG。

## 用户任务

个人监测用户在“不断搜索仍难以理解事件变化”的场景中，需要沿主题追溯监测结果，以便减少重复搜索并持续理解关注变化。

## 范围与业务规则

从关键词、可读原帖评论，到具体事件、新事实、持续跟踪和提醒构成同一主题下可追溯的闭环；国内主流平台POC先行，最终覆盖国内主流与X、Instagram等目标。

- BR-00-01：只有摘要或模拟发送不能通过闭环验收。
- 共用权限、读取/写入状态及安全边界引用[00 产品目标与边界](../requirement/00-产品目标与边界.md#跨功能规则)、[10 权限与数据生命周期](../requirement/10-权限与数据生命周期.md)；本文件不复制第二份规则。

## 可验证验收用例

### AC-00-01 闭环结果

- **Given**：主题T已有规则、两轮采集、事件修订及自然提醒证据；角色为个人监测用户。
- **When**：沿提醒反查主题规则、查询、正文版本和事实依据。
- **Then**：沿同一主题核对配置、材料、事件和提醒证据；任一链路缺失就不能宣称闭环可用。
- **反例**：只有页面或摘要而无原文和运行证据时不通过。

### AC-00-02 范围控制

- **Given**：主题T已有规则、两轮采集、事件修订及自然提醒证据；角色为个人监测用户。
- **When**：沿提醒反查主题规则、查询、正文版本和事实依据。
- **Then**：核心交付不依赖辅助页面全部完成；辅助需求有独立验收。
- **反例**：保留需求不得自动解释为本期全部实现。

### AC-00-03 证据分层

- **Given**：主题T已有规则、两轮采集、事件修订及自然提醒证据；角色为个人监测用户。
- **When**：沿提醒反查主题规则、查询、正文版本和事实依据。
- **Then**：每项验收能说明证据来自何种环境、数据和时间范围。
- **反例**：测试样本或手动执行不得冒充自然监测。


## 已确认边界

- 仅供个人非商业使用；不增加企业多租户、付费套餐或原生客户端。
- 第三方服务费用为零，不购买 API、代理、打码或云端模型；计费不明的路径也不启用。相关性、情感、观点和写作使用本机 Codex app-server，限流时延后处理，不丢任务。
- 只读取公开或本人账号可见内容，不发帖、点赞、评论、私信，不访问私密账号或群组。登录平台用本人单账号低频采集，默认每小时一轮，评论有上限；验证码、登录失效或限流时停止，等待人工恢复，不换账号、代理或打码。
- X 不用官方 API；公开趋势和本人账号试点分别确认，源内容删除后同步清理本地数据。Reddit 只走官方 API 与 OAuth，申请获批前不发请求。
- 凭据只留本机配置或独立浏览器配置目录，不进入代码、日志、URL、导出、快照或数据库明文。个人资料按会话 owner 隔离，公开读取必须符合当前许可。
- 对外分发（RSS、只读 API、MCP/Agent Markdown、SEO/IndexNow、分享海报）、Facebook/Threads、Flutter App、通用浏览器采集和飞书推送不属于当前实施范围。Instagram 和 OpenRouter 按[平台接入](08-平台接入.md)保留为有条件扩展，不因需求梳理自动启用。
- 产品不提供 Codex 重置公告统计与管理页面。
- 项目文档直接使用本仓库 Markdown/Git 和 Obsidian；不建设在线文档站、网页编辑、快照或发布平台。业务报告的 Obsidian 导出仍有效。
- 优先复用开源项目：MIT 代码可按许可改编并署名，GPL/AGPL 仅参考设计或独立运行，无许可证不用；商用前须重新核对非商业组件。

## 跨功能规则

- BR-COM-01：需求定义用户结果；代码、页面和既有表结构仅为现状证据。每个编号只有一套现行规格，错误旧方案删除，不能以兼容现状为理由保留。设计选择及范围取舍明确标为提案或待评审。
- BR-COM-02：读取不隐式采集、分析、发送或发布。写入须显式操作、归属检查、预期版本和业务幂等标识；超时未知先核对受理结果，冲突保留输入。
- BR-COM-03：成功零集合、未知、未分析、部分完成、延期、失败、撤权分别呈现。刷新故障保留仍可读旧内容并标过期，失权则清除；资源切换取消或忽略过期响应。
- BR-COM-04：当前权限贯穿详情、计数、历史、附件、缓存与导出；公开读取只用白名单投影，运营角色不自动获得私人正文。
- BR-COM-05：时间使用带时区UTC、窗口左闭右开；数字给出作用域、分母、窗口和版本。发布时间、观察/接收/分析时间分开，缺失不造值。

### 原始约束与设计决策分界

个人非商业、当前第三方零费用、本机模型、只读合法可见内容、风控停止、凭据不外泄及冻结范围，是现有材料已经记录的执行边界；未被用户明确调整前继续生效。它们不证明当前架构、数据库、组件组织或页面设计正确。用户确认的是核心优先，不能外推为批准收费、解冻平台、迁移业务库或重建客户端。

页面路由、首屏行数、栏宽、刷新间隔、分页大小、数据库表名、消息系统及算法均属于设计选择。由用户结果、容量基线、成本和迁移风险重新论证；实现方便不能成为删掉原始业务目标的理由。

## 术语与系统边界

| 术语 | 本轮定义 |
|---|---|
| 主题 | 用户要长期跟踪的监测意图与配置，不等于具体事件 |
| 查询 | 一个来源能够执行的召回表达及其限制；本地精筛不扩大平台召回集合 |
| 材料 | 可识别来源与原生对象的原帖、文章、评论或回复；同文不一定同身份 |
| 线索 | 信息不足以确定具体事情或缺少交叉证据的候选，不等于错误材料 |
| 事件 | 有主体、动作和时间等辨识信息且由材料支持的一件具体事情 |
| 事实 | 可定位证据的陈述；保留声称、未证实、确认、反驳与纠正区别 |
| 新事实 | 相对某个事件修订真正增加或改变信息的事实，不包括重复报道和摘要改写 |
| 热点 | 按冻结规则与可比观察范围达到门槛的事件，不等于平台热榜条目 |
| 覆盖 | 某来源、查询和窗口内可证明取得的集合及缺口，不是全网召回率 |
| 观察时间 | 来源对象状态被观察的时刻；与发布时间、接收时间和分析时间分开 |
| 送达 | 用户实际收到；提供方接受和系统记录成功不能单独证明送达 |

系统输入为本人配置、获准来源的可见材料、模型结构化结果与通知渠道回执；输出为材料、事件、新事实、可比趋势、回执和提醒。平台索引、账号准入、模型限额及提供方送达能力属于外部依赖，必须显示其限制。用户配置、运行证据及授权判断属于系统责任，不能推给外部依赖。

## 需求追踪与变更规则

`OR → REQ/FR/BR/NFR/AC → PRD/US ↔ 目标设计 → PLAN/T → 验证与BACKLOG证据` 为追踪链。FR/AC/US使用相同序号；每项计划任务列出具体产物和完成判据。跨编号依赖以业务输入判断，不以现有包依赖替代。

需求新增、修改或删除先写原因、影响的场景/数据/验收和安全边界，再调整同编号PRD、设计与PLAN。设计中的表字段、接口参数和状态只能追溯到某条 FR 或 NFR；无法说明用途的持久结构不进入目标模型。最终实施选型与迁移必须单独评审，目标设计不证明源码、运行服务或业务数据库已经变更。

GOV-00为范围与证据治理要求，属于本轮交付约束，不是新增产品功能。
