# 38 个人事件列表

需求编号：`REQ-38`。来源：OR-04，确定程度见[00 产品目标与边界](../requirement/00-产品目标与边界.md#原始需求与来源登记)。优先级：核心。本文定义目标与验收，实际状态只在根目录 BACKLOG。

## 用户任务

个人监测用户在“找出关注主题中有新进展的事件”的场景中，需要筛选本人主题事件和新进展，以便发现关注主题的新事件与进展。

## 范围与业务规则

按主题/时间/分类/状态检索本人事件，区分新事件、旧事件更新和未知，排序保留相关性时效及覆盖解释。

- BR-38-01：热度高不代表已确认。
- 共用权限、读取/写入状态及安全边界引用[00 产品目标与边界](../requirement/00-产品目标与边界.md#跨功能规则)、[10 权限与数据生命周期](../requirement/10-权限与数据生命周期.md)；本文件不复制第二份规则。

输入：本人主题/事件类型/状态/时间筛选及排序/cursor。所需业务输入合同（编号表示归属，不要求对应页面先完成）：04、05、09。输出为下表可观察结果；配置、受理、执行和外部效果分别取证。

## 可验证验收用例

### AC-38-01 发现本人主题中的事件

- **Given**：一个新事件、一个旧事件更正、一个证据不足线索；角色为个人监测用户。
- **When**：筛选本主题并查看新增事实。
- **Then**：区分候选/线索/事件及可读证据范围；过滤与计数同作用域。
- **反例**：候选数不冒充已确认事件总量或热点数。
