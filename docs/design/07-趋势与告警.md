# 07 趋势与告警

需求依据：[07 趋势与告警](../requirement/07-趋势与告警.md)；工作拆解：[07 趋势与告警](../plan/07-趋势与告警.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

真实24小时统计唯一相关原帖、可识别作者、新事实及独立平台互动；首次热点、重要新事实/重大更正、异常增长分别定义。首次仅是最小交付切片，不能替代完整提醒意图。

1. **可比趋势**（FR-07-01）：每点有窗口、来源集合、覆盖、规则版本；缺失留缺失，不补零。
2. **首次热点提醒**（FR-07-02）：同一规范事件跨规则版本不重复首次提醒；证据、窗口、规则和目标可核对。
3. **交付语义**（FR-07-03）：至少一条自然达标提醒由本人实际收到；没有送达回执时保留未知并记录人工验收。
4. **重要新事实与重大更正提醒**（FR-07-04）：同一事实进展只生成一次业务提醒，重大更正可提醒且引用真实修订。
5. **可比异常增长提醒**（FR-07-05）：缺基线/断采/来源变化为不可比，返回抑制原因；可比达标才生成提醒。

## 状态、交互与失败恢复

发送超时unknown先核对；静默结束重查过期及许可；accepted不等于delivered。验收场景：E首次达标，随后转载三条和一项重要延期更正；规则换版、换目标；覆盖中断；评估首次/事实/增长条件并重放、离开通知静默后发送；预期：首次按owner+规范事件继承+类型去重，换版本/渠道不再首次；更正按事实版本和更正关系去重；中断覆盖不触发增长。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 数据库设计

目标关系模型；字段、键、查询索引和生命周期由同编号需求推导。类型为候选表达，正式DDL需验证枚举、长度、外键、容量、迁移与回退；本轮不执行建表。共享owner复合引用和当前版本指针规则见00。

## 提醒生成、静默与发送并发

- 首次去重键为owner+规范事件及所有前身的首次热点身份，不含规则版本或渠道。合并/拆分读取05的继承与纠错依据；先联合锁定规范身份再判断已有消息，不能只靠不同旧ID各自唯一键。
- 重要事实消息以事件继承+事实进展/更正身份去重，重复来源、正文改写和单纯事实状态复核不自动造新进展。增长消息绑定明确可比窗口；冷却及最低样本在评估中冻结，历史重评必须独立显式操作。
- 通知静默只由notification_target_versions.quiet_policy定义，规则不另存第二套静默。生成消息冻结target_revision、not_before、expires_at；离开静默后重查当前关注/许可/规则/目标版本/验证/预算及有效性，过期或被替换目标的旧消息取消或暂缓，不无界补发。
- 发送以CAS从pending/deferred领取execution_token及递增claim_revision，并建立一条started发送尝试；同消息只允许一个未收尾尝试，外发前再查目标版本验证和当前启用。提供方调用在事务外。
- 领取过期或调用后崩溃转unknown，不自动接管重发；先核对提供方或本人证据。人工决定重试要记录依据、重复风险及新尝试，不能承诺跨外部系统严格exactly-once。accepted不等于delivered。

## 当前版本完整性

当前指针采用复合FK：`alert_rules(owner_id,id,current_version)→alert_rule_versions(owner_id,rule_id,version)`。身份首次建立与初版、后续新版本/修订与当前指针/审计同事务；循环关系在DDL采用可延期约束并在提交前验证。不能用应用中随意选最大版本替代当前有效版本。

## 关注事件的生成与取消

公开读者先登录，再对当前可读公开事件显式关注；这只建立个人关注/提醒规则，不让订阅者读取事件拥有者的私有证据或触发其采集。公开后续提醒只消费已发布的更新投影；撤权/取消立即阻止未开始发送。私人事件的topic规则可覆盖全部本主题，显式事件关注通过follow_id缩小范围，规则与关注开关共同判断。

关注时间后新增进展数/最近进展时间按许可内事实修订派生，与收藏/已读分开；重新关注默认仅未来，不重置首次去重史。发送前校验follow仍active、目标规范身份及公开许可。合并迁移与事件纠错回执同边界处理，历史送达不改写；跨owner例外只存在上述公开关注链，其他个人关联仍执行同owner复合约束。

### 评估输入与关注合并合同

- input_manifest.schema_version明确输入格式。主题规则冻结topic_id及事件归属，受理事务校验事件同owner且属于该topic。事件规则冻结follow_id、follow_version、followed_at、目标规范身份与状态审计依据；必须与指定alert_rule_versions.follow_id及其冻结目标一致，不能套当前alert_rules投影。主题规则的follow字段为空。指纹包含关注代际和起点，重新关注只评估新起点后的进展，旧关注期评估不得复用发送。
- 公开关注另冻结public_entry_id、public_revision及该公开修订映射的event_owner_id/event_id/event_revision；服务验证发布owner、事件映射和该固定修订已发布/生效。measurement及消息content_snapshot只从这一白名单投影生成，不能使用内部最新修订、私人计数或未发布事实。公开映射不完整则unknown/不可发送，不回退读取内部事件补齐；发送前重新验证当前许可和公开状态。
- 合并事务锁定全部前身关注、规范目标关注及受影响规则。旧关注保留稳定ID和原event引用，标superseded并指向唯一survivor；已有规范事件关注优先作为survivor，否则建立规范目标行。旧评估/送达历史保持旧ID和冻结输入，受影响规则追加新版本迁到survivor，同事务审计，联合前身通知史去重。不能删除受历史FK引用的旧行，也不能把多行都改成同一event违反唯一键。
- survivor只有在至少一个前身仍active且当前许可允许时才能active；所有前身已取消/不可用时保持cancelled/unavailable，合并不能复活关注。起点与进展范围由仍active前身的有效关注区间合并，取消历史不丢。未外发旧代际消息取消后再按当前规则受理评估；已有送达事实不改写。

提醒目标topic_id/follow_id随alert_rule_versions不可变冻结；alert_rules只保存当前投影。合并迁到survivor时追加新规则版本并切当前指针，旧版本保留旧follow引用；受理和历史核对使用指定rule_version目标，发送仍检查当前状态授权，不能将过期旧目标重新激活。
