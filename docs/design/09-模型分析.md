# 09 模型分析

需求依据：[09 模型分析](../requirement/09-模型分析.md)；开发交接：[09 模型分析](../prd/09-模型分析.md)；agent工作拆解：[09 模型分析](../plan/09-模型分析.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

相关性、相似度/排序、情感、观点独立输出。相关性和事件关系核心优先；情感观点保留重评。排序考虑语义相关与时效，并显示依据及时间字段，不能把布尔判定当最相关排序。

1. **独立分析维度**（FR-09-01）：无效输出保留失败；信息不足保留不足；未分析不归中性。
2. **上下文与证据**（FR-09-02）：短回复不必复述关键词；引用必须存在于实际可读输入。
3. **延后与重算**（FR-09-03）：用户可分辨未处理、延期、失败和有效结论；程序计算计数/比例。
4. **相关性与时效排序**（FR-09-04）：每项有排序依据和采用的时间字段；人工标注的相关/新旧样本可复核，未知不伪装新鲜。

## 状态、交互与失败恢复

限流延后不丢任务；正文变化重算；排序算法及门槛先校准再冻结。验收场景：原帖Alpha发布，评论终于来了；缺父链样本；相关性有效但情感失败；字符串true与虚构引文；按冻结正文、父链、规则、提示和模型配置分析并排序后，缺上下文可insufficient；情感失败不丢相关材料；字符串布尔或不存在引文invalid；排名不由任意高互动冒充。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 数据库设计

目标关系模型；字段、键、查询索引和生命周期由同编号需求推导。类型为候选表达，正式DDL需验证枚举、长度、外键、容量、迁移与回退；本轮不执行建表。共享owner复合引用和当前版本指针规则见00。

### `analysis_runs`

用途：一次有冻结输入的分析请求，不把不同维度合并成一个成功位。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| topic_id | UUID | 否 | 主题 |
| rule_version | BIGINT | 否 | 规则版本 |
| dimension | VARCHAR(32) | 否 | relevance、sentiment、viewpoint、event_relation等 |
| input_manifest | JSONB | 否 | 主题ID/规则版本及实际规则、原帖/目标评论/可得父链与版本清单 |
| input_fingerprint | BYTEA | 否 | 输入身份 |
| prompt_version | VARCHAR(128) | 否 | 提示合同版本 |
| model_configuration | JSONB | 否 | 模型与非秘密配置快照 |
| model_configuration_fingerprint | BYTEA | 否 | 规范化模型配置摘要；幂等键显式字段 |
| state | VARCHAR(24) | 否 | pending、running、deferred、valid、invalid、failed、unknown |
| created_at | TIMESTAMPTZ | 否 | 受理时间 |
| finished_at | TIMESTAMPTZ | 是 | 未终结空 |

键与完整性：PK(id)；UNIQUE(owner_id,id)；owner、topic_id、rule_version、完整语义输入指纹、维度、提示版本及模型配置指纹共同构成幂等键；复合FK主题规则。

查询与索引候选：owner_id,dimension,state,created_at；input_fingerprint。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：模型/输入变更另建分析；正文编辑把旧结果标为非当前，保留历史证据。

### `analysis_results`

用途：校验后的维度结果及证据位置。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| analysis_run_id | UUID | 否 | 分析请求 |
| result_state | VARCHAR(24) | 否 | valid、insufficient、unknown、invalid |
| value | JSONB | 是 | 结构化判断；非有效态不伪造值 |
| reason | TEXT | 否 | 可读理由 |
| citations | JSONB | 否 | 实际输入版本及合法引文定位 |
| created_at | TIMESTAMPTZ | 否 | 保存时间 |

键与完整性：PK(id)；UNIQUE(owner_id,id)；UNIQUE(owner_id,analysis_run_id)；复合FK分析请求。

查询与索引候选：owner_id,analysis_run_id。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：结构不符/不存在引用归invalid；相关性bool不和情感状态绑定。

分析幂等反例：同一材料同时被Alpha和Beta主题分析，必须分别绑定各自主题规则。只因原文/模型/提示模板相同不得跨主题复用相关性；完整输入摘要包含主题规则、对象版本、可得父链、维度与实际配置。

## 分析与排序合同

analysis_runs唯一键明确为(owner_id,topic_id,rule_version,input_fingerprint,dimension,prompt_version,model_configuration_fingerprint)。input_manifest包含schema_version及实际正文/父链版本、查询与规则引用；结构与跨owner引用由受理事务验证，输入变化不得复用旧结论。相关性/情感/观点各维度独立有效、insufficient、invalid、failed、deferred/unknown。

排序输入保留相关性理由、相似度依据、采用的发布时间/事件发生时间/首次观察时间及未知状态；使用哪个时间必须可解释。排序结果包含方法版本、特征来源、范围/快照，必要物化仅为可重建投影。算法与权重依据分层人工样本校准；新鲜但无关不靠高时效强行进入结果，重要旧帖新评论可按讨论更新时间进入明确的更新排序。

重新分析显式受理并有预算；编辑正文或补父链形成新输入摘要。模型无效输出不写有效结果，引文必须存在于冻结输入且当前许可允许；模型不决定计量或将声称升级为确认。
