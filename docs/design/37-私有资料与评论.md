# 37 私有资料与评论

需求依据：[37 私有资料与评论](../requirement/37-私有资料与评论.md)；开发交接：[37 私有资料与评论](../prd/37-私有资料与评论.md)；agent工作拆解：[37 私有资料与评论](../plan/37-私有资料与评论.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

原帖、根评论、父评论、回复目标和失父状态分开；有界分页与已采/总数/缺口说明。显式评论刷新及加入/移出跟踪集合可操作，旧帖发布时间不变；分析按版本核对。

1. **理解材料与讨论上下文**（FR-37-01）：对象身份、正文版本、来源与时间可核对；短回复结合实际父链解释。
2. **核对分析并主动刷新**（FR-37-02）：分析版本与实际输入绑定；刷新独立受理、预算及停止检查。

## 状态、交互与失败恢复

读详情、展开已存评论不隐式联网采集或模型分析。验收场景：旧帖有根评论20/总数100、回复5及一条缺父评论；读父链、展开分页、刷新讨论并加入/退出跟踪后，缺父标未知而不伪造根；刷新新评论可追到请求；退出后不再自动刷新。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 持久化边界

消费上述归属实体，不新增一套重复材料或事件真源。只读筛选/导航可留客户端；用户主动保存的数据须按相应业务身份和许可管理，未定义消费路径的字段不持久化。
