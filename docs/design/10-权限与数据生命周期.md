# 10 权限与数据生命周期

需求依据：[10 权限与数据生命周期](../requirement/10-权限与数据生命周期.md)；开发交接：[10 权限与数据生命周期](../prd/10-权限与数据生命周期.md)；agent工作拆解：[10 权限与数据生命周期](../plan/10-权限与数据生命周期.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

服务端按owner及当前许可投影；标题、计数、附件、历史修订、导出和派生物都受约束。撤权立即不可读，清理异步可追踪；源确认删除与临时读取失败分开；备份恢复先重放删除账本。

1. **访问隔离**（FR-10-01）：替换ID、cursor、附件或导出引用均不能获取他人内容及计数。
2. **许可与删除**（FR-10-02）：撤回后新读取立即不可得；物理清理完成与失败可追踪。
3. **最小化与安全**（FR-10-03）：恶意Markdown/HTML/URL与凭据混入样本被拒绝或清理。

正常运行保护随实际业务入口先行，完整账本接管与旧备份恢复按条件交付，当前优先级以BACKLOG为准。需求规定的是隔离、当前许可、决定可靠保存及恢复不复活；独立PG、全链读取、P/J/V和journal-first是下面选择的技术方案，可按用户风险与成本重新评审。后置工程不撤销BR-10-01独立最小记录，也不撤销已接入权威的强制校验。恢复尚未可用时，恢复目标保持业务隔离，不开放旧身份、对象及任务。

## 状态、交互与失败恢复

删除账本存非正文最小标识并独立保护；清理失败不得重新公开。正常验收分别核对A/B/匿名读取、当前/历史/附件/导出、撤权后的新分析与发送以及恶意输入，预期无标题/计数/正文/字节泄漏。旧备份恢复是独立条件分支：重放并复核当前身份、政策、对象与副作用前不得开放；其未完成不妨碍单独审查正常访问和输入安全，也不能据此关闭完整恢复要求。

在线独立权威以锁外P→J→V准入：新业务只读快照冻结完整输出与依赖，关闭后读取独立完整链，再以新业务快照重建并比较全部证明，变化有限重做。持锁写方重取锁后复核同一完整依赖，变化先释放锁，不跨独立I/O持锁；拥有事务入口不得擅自rollback已有调用事务。权威不可用与材料deny/unknown分开传播，API503，Worker按连接暂态/配置永久故障分别有限退避或停止；不能转为空列表或404。详情正文之外的历史、计数、引用和主题映射同样须有证明；无证明段导致整详情安全不可用，不能借最新观察授权旧历史。B1b实施分片、精确输出边界与反例在[PLAN-10内嵌SPEC](../plan/10-权限与数据生命周期.md#b1b-锁外权威与完整复核-spec)维护，不建立另一套实施合同。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 数据库设计

目标关系模型；字段、键、查询索引和生命周期由同编号需求推导。类型为候选表达，正式DDL需验证枚举、长度、外键、容量、迁移与回退；本轮不执行建表。共享owner复合引用和当前版本指针规则见00。

### `access_policies`

用途：来源/材料当前可读和可公开范围，作为安全判定而非副本正文。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 所属账户 |
| resource_kind | VARCHAR(32) | 否 | binding、object、public_entry等 |
| resource_id | UUID | 否 | 被保护身份；服务验证类型与归属 |
| version | BIGINT | 否 | 政策版本 |
| is_current | BOOLEAN | 否 | 每保护资源恰有一条当前政策，事务切换；无政策默认拒绝 |
| effective_from | TIMESTAMPTZ | 否 | 生效时刻；延迟公开未到时不开放 |
| read_scope | VARCHAR(24) | 否 | owner、public、denied |
| content_scope | VARCHAR(24) | 否 | full、summary、metadata、none |
| license_reference | TEXT | 是 | 当前许可依据 |
| revoked_at | TIMESTAMPTZ | 是 | 撤回时间 |
| updated_at | TIMESTAMPTZ | 否 | 更新时间 |

键与完整性：PK(id)；UNIQUE(owner_id,resource_kind,resource_id,version)；UNIQUE(owner_id,id)；部分UNIQUE(owner_id,resource_kind,resource_id) WHERE is_current；更新锁定同资源，追加新版本并原子切标志；政策内容不可覆写，is_current仅当前指示。

查询与索引候选：owner_id,resource_kind,resource_id,version DESC。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：撤回使新读取拒绝，不能从较旧版本回退；多态引用无法单一FK，服务和检查共同约束。

### `retention_policies`

用途：按来源及数据类别限定保留与物理清理期限。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| binding_id | UUID | 是 | 来源特例；空为默认 |
| version | BIGINT | 否 | 政策版本 |
| is_current | BOOLEAN | 否 | 每owner/连接或默认范围/data_class唯一当前政策 |
| effective_from | TIMESTAMPTZ | 否 | 生效时间 |
| data_class | VARCHAR(24) | 否 | structured、raw、media、derived |
| requested_days | INTEGER | 否 | >=0 |
| source_max_days | INTEGER | 是 | 来源上限未知时空 |
| effective_days | INTEGER | 否 | 已知上限时取较小值 |
| cleanup_deadline_seconds | BIGINT | 是 | 需基线与许可冻结的物理清理时限 |

键与完整性：PK(id)；UNIQUE(owner_id,id)；UNIQUE NULLS NOT DISTINCT(owner_id,binding_id,data_class,version)；部分UNIQUE NULLS NOT DISTINCT(owner_id,binding_id,data_class) WHERE is_current；复合FK可选连接；数值非负且effective_days<=已知上限。

查询与索引候选：owner_id,binding_id,data_class,version。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：策略变化可缩短寿命，不能恢复已撤权正文；到期立即不可读和物理清理分开。

### `deletion_requests`

用途：用户删除、源删除、撤权和保留到期的清理回执。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| operation_id | UUID | 否 | 幂等操作 |
| resource_kind | VARCHAR(32) | 否 | 目标类别 |
| resource_id | UUID | 否 | 目标身份 |
| reason | VARCHAR(32) | 否 | user、source_deleted、revoked、expired |
| state | VARCHAR(24) | 否 | pending、running、partial、completed、failed |
| requested_at | TIMESTAMPTZ | 否 | 逻辑删除时刻 |
| completed_at | TIMESTAMPTZ | 是 | 全部必要目标成功后填写 |

键与完整性：PK(id)；UNIQUE(owner_id,id)；UNIQUE(owner_id,operation_id)；completed与completed_at一致。

查询与索引候选：state,requested_at；owner_id,resource_kind,resource_id。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：受理时关闭可见性；物理失败不得回滚可见性，重试只处理未完成目标。

### `deletion_targets`

用途：跨关系库、对象文件与缓存的清理目标。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| owner_id | UUID | 否 | 用户 |
| deletion_id | UUID | 否 | 清理请求 |
| target_kind | VARCHAR(32) | 否 | relational、object_file、cache、derived |
| target_reference | VARCHAR(512) | 否 | 脱敏目标标识 |
| state | VARCHAR(24) | 否 | pending、running、succeeded、failed |
| attempt_count | INTEGER | 否 | >=0且有重试上限 |
| last_error | VARCHAR(64) | 是 | 脱敏错误 |
| completed_at | TIMESTAMPTZ | 是 | 成功时间 |

键与完整性：PK(owner_id,deletion_id,target_kind,target_reference)；复合FK清理请求。

查询与索引候选：state,attempt_count；owner_id,deletion_id。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：关系对象删除使用明确顺序；不让外部文件失败释放受限读取。

## 权限矩阵与生命周期执行

| 角色/内容 | 公开许可投影 | 本人监测正文 | 配置/纠错/删除 |
|---|---|---|---|
| 匿名 | 仅当前白名单及许可范围 | 拒绝 | 拒绝 |
| 本人 | 按当前公开许可 | 本人且来源仍允许的范围 | 本人显式操作并校验版本 |
| 他人 | 同匿名公开范围 | 拒绝 | 拒绝 |
| 运营 | 按职权查看诊断/主动反馈 | 默认拒绝，诊断不含正文 | 仅被授权的运营资源 |

权限判定按账户归属、来源约束、逐内容例外和公开许可共同取最严格范围；逐内容允许不能突破来源拒绝。access_policies选择当前is_current行并校验effective_from/撤回；未来公开不提前授予，缺政策拒绝。retention按来源特例覆盖默认，effective_days不超过已知来源上限；未知许可限制不得据‘未知上限’无界保存。

来源政策收紧在业务事务中写当前不可读政策；资源删除按下文journal-first独立确认后再幂等投影与登记清理，覆盖正文、原响应、媒体、派生分析/向量/缓存/导出可控副本及失效引用，各目标独立回执。已被用户下载到系统外的文件无法保证远程抹除，要如实说明。

删除账本和最小tombstone需独立于可回退的业务备份可靠保存，内容限owner、资源/原生标识摘要、删除原因/时间/操作及必要期限，不保留被删正文或秘密。恢复先隔离服务、恢复基础数据，再重放完整覆盖范围的删除/撤权账本并复查派生物、附件及身份，最终追赶当前高水位后才评审开放。不能只重放备份时间之后的记录：先持久化账本、尚未提交业务事务的intent可能早于备份一致性点。账本不可用或覆盖不足时保持隔离，不能让备份复活已删除内容。

## 独立账本与恢复方案

从BR-10-01及恢复反例选择独立PostgreSQL实例/专库作为账本权威，使用独立凭据、备份和保留生命周期，不放入业务dump或业务资源FK级联。相比业务库outbox，它不会随同一旧备份回退；相比当前MinIO bucket或本机普通日志，它能在单事务中控制连续序号、幂等与head。实际部署须证明故障域；同机专库只证明独立回退域，不能声称设备故障隔离。没有独立实例准入证据时不接管在线删除。R1负责交换合同与隔离复演，R2-A增加独立事务及可信导出消费者；具体交换字段/摘要算法在[PLAN-10 R1 SPEC](../plan/10-权限与数据生命周期.md#r1-账本输入验证与隔离重放复演)唯一维护。

| 权威数据 | 最小关系与完整性 | 生命周期及查询 |
|---|---|---|
| ledger head | ledger_id/epoch PK；规范化版本；当前sequence/digest；覆盖基线及最旧可恢复边界 | 只在账本事务推进，不由业务库回写；epoch重建与自身恢复须独立审查 |
| restrictive events | PK(ledger_id,epoch,sequence)；UNIQUE(ledger_id,epoch,owner_id,operation_id)；目标UUID或版本化原生摘要、动作/原因/时间、previous_digest/digest | 无正文、密钥、密码、邮件代码和业务FK；同operation冲突拒绝，幂等返回原收据；未有覆盖替代证明前不截断 |
| backup anchors | 唯一backup_id及archive/schema digest绑定ledger/epoch和覆盖基线 | 时间不是连续性证明；缺有效anchor或覆盖不足的备份不可开放 |
| recovery barriers | 外部目标身份/epoch、阶段、应用水位和追赶判据 | 不从旧dump恢复为open；回执不是开放令牌，授权须全入口共同消费 |

R2-A将最小head/events落入独立账本库的`restriction_journal` schema，独立DDL见PROJECT；原子受限函数负责连续分配、幂等和head更新，读角色不具有追加权限，运行角色不能改历史或重新初始化。backup anchors/recovery barriers仍是后续目标关系，不在本切片批量建表。具体物理字段、事务与验证合同见[PLAN-10 R2-A SPEC](../plan/10-权限与数据生命周期.md#r2-a-独立事务及可信重放消费者-spec)。不能在业务schema中建一份同名账本就声称独立。

在线限制变更采用账本先行的保守deny：先独立持久确认，所有对应读取/采集授权实时受该deny约束，再幂等更新业务投影。业务写失败不补偿为allow；未知确认按operation读回，账本不可用保持安全拒绝。重新授权需新版本及现时依据，不能撤销删除tombstone或因恢复旧allow覆写deny。R2-B实施前逐入口冻结资源拒读的全消费者和故障反例；来源/连接/账户级动作及原生身份规范化另冻结，不能用新UUID绕过原生身份限制。R1与R2-A只确认owner/type/UUID的资源拒读合同。

恢复状态为quarantined→base_verified→ledger_verified→replayed→dependencies_verified→caught_up→release_review。任何缺失/损坏/断档、未知版本、清理失败或权威不可用均保持隔离，阶段推进不隐含开放。最终切换须冻结写入、追赶当前head、验证全投影及副作用围栏后才能产生绑定目标/epoch的开放许可；恢复期间新撤权不能丢失。账本保留须覆盖全部仍可恢复备份，合法清理提高最旧可恢复边界；RPO/RTO和物理保留数值由后续基线及演练冻结。

身份恢复不能仅清空session：旧密码、第三方绑定、删除/停用账户和credential_version同样可能回退。R3要求外部当前账户状态/凭据版本权威与重新验证授权；缺权威时整个恢复身份入口关闭，不允许凭旧备份密码/OAuth/邮件自动恢复账户。API、Worker、Scheduler、Kafka/outbox、模型/通知、维护业务动作、缓存/索引和附件入口均须消费相同隔离屏障。附件只能恢复到独立私有bucket/凭据，不恢复旧公开ACL或预签名能力。

R1只在随机新临时库中验证指定完整快照并投影资源拒读，目标无业务入口且最终删除，不提供promotion。创建先禁连接、移除PUBLIC权限；非测试需独立维护角色并排除业务角色的管理员/成员旁路。拒绝带对象清单的候选；不连接对象/队列，不执行清理或登录。结果明确integrity_verified/replay_verified的有限范围与固定service_open_permitted=false。人工checkpoint只能支持受控复演，不能证明独立权威或生产故障域。

独立权威接管方案选择每个最后准入点直接验证独立当前账本，不使用业务投影水位或允许缓存。逐入口、错误/重试及并发反例见[PLAN-10 R2-B SPEC](../plan/10-权限与数据生命周期.md#r2-b-在线入口与依赖闭包-spec)；在该方案内B1～B4准备消费者，B5最后切换删除生产者，不启用部分双写或失败回退。全消费者接J是独立deny生产权威的切换门槛，不是全部正常业务开发的统一前置；未接J路径仍必须证明当前owner/许可/ALL与副作用保护，已接J路径不回退。

依赖证明以实际observation为准：source_v1为明确来源叶节点，observations_v1必须有非空显式边；未知basis拒读，不借同版本/同文/新来源推断。所有新采集固定Job来源上下文；编辑来源guid/url_fallback与普通原生ID/网页身份区分，旧记录不回填。provenance约束、重放及旧分支清理在B1a冻结。ContentVersionInput继续承担明确版本输入及清理，不替代观察证明。

## 列表、固定修订与导出状态投影

报告列表和详情采用相同的全部冻结输入许可检查；最新修订不可读时不回退较旧修订。先过滤不可读报告再填充分页，拒读记录不产生游标，已撤权游标不能继续定位。导出状态读取与下载均复核冻结输入，不返回受限材料数量或文件大小、摘要等元信息；操作诊断通过不含材料正文的任务回执核对。

事件当前与固定修订成员仅投影当前可读集合，分页及member_count/readable_member_count使用同一集合，不返回受限成员身份、版本、来源或隐藏数量。partial只说明证据不完整，不提供拒读材料的具体分母；派生标题/摘要仍按全部历史输入许可约束，不能以剩余可读材料替代原证据。

事实接口同样仅返回当前可读成员；完全没有可读成员的事实及其根事实引用不投影。任一冻结输入撤权时，自动修订差分返回`delta_state=unavailable`且`delta=null`，不能用带受限身份的unknown项、隐藏材料数量或可读子集伪装完整分区。

## 平台原生趋势的隔离迁移准备

此操作是当前候选升级准备，遵守PROJECT §6；不能直接向有数据业务库执行schema.sql或仅ALTER某一列。预检对业务库强制REPEATABLE READ/READ ONLY，盘点全表/列/约束/当前任务与来源状态，连接字符串、身份/凭据、备份和材料不进Git/日志。列映射覆盖整个候选schema及全部表，不能只处理热榜provenance。新增可空无依据字段保留NULL，未知计量/身份/分析维度不能补0或伪造许可；新增非空列必须逐项核对合法默认或显式转换，没有映射即阻断。

实施窗口的顺序：明确冻结所有写入口/API/Worker/Scheduler/Outbox/维护及外部发送，确认无租约/未决外部效果；取得一致性备份、当前拒读/撤权/删除限制及身份版本。先在随机新隔离恢复库按原结构实际恢复并核对全表行数/关键摘要/外键/序列；再建另一空库、仅执行候选完整schema，经已评审列映射导入并核对全表/约束/预算窗口和任务。循环引用不得靠禁用外键或复制旧allow解决，须单独评审两阶段映射；缺失表和新非空字段不得盲用默认。业务库只读盘点不是备份或恢复验证。

所有恢复/升级目标不连接业务身份、业务API/Worker/Scheduler、队列、对象及通知；无业务角色CONNECT、无生产DSN/外发凭据，只有隔离核对入口。最终追赶并复核当前拒读、owner/固定依赖、身份/会话/停止、作业租约/预算/副作用围栏后，才可另行批准切换。先撤真实公开grant及停采集，再部署匹配服务和客户端；无依据旧榜保留NULL并拒读。回退也要追赶新增限制和身份版本，不恢复旧授权、发送或采集；任何核对失败保持目标隔离。备份/恢复影响所有数据，不能据本切片源码测试声称已可切换。
