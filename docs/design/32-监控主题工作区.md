# 32 监控主题工作区

需求依据：[32 监控主题工作区](../requirement/32-监控主题工作区.md)；开发交接：[32 监控主题工作区](../prd/32-监控主题工作区.md)；agent工作拆解：[32 监控主题工作区](../plan/32-监控主题工作区.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

主题规则摘要、启停、最近成功、24h命中桶、来源条数/时间、运行缺口及事件新进展可核对；全体统计不从当前页估算。

1. **理解主题监测状态**（FR-32-01）：主题状态与运行状态分开；每个指标可回到作用域和证据。
2. **管理监测生命周期**（FR-32-02）：草稿、版本冲突、停止保证和当前任务关联保持可核查。

## 状态、交互与失败恢复

暂停不清空证据，也不自动补发旧通知。验收场景：主题T部分来源失败，24h有两桶数据；另一主题暂停；切主题、编辑规则、暂停与恢复；预期：只读不采集；缺口独立；操作回执指向新版本与运行授权。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 持久化边界

消费上述归属实体，不新增一套重复材料或事件真源。只读筛选/导航可留客户端；用户主动保存的数据须按相应业务身份和许可管理，未定义消费路径的字段不持久化。
