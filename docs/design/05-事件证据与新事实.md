# 05 事件证据与新事实

需求依据：[05 事件证据与新事实](../requirement/05-事件证据与新事实.md)；工作拆解：[05 事件证据与新事实](../plan/05-事件证据与新事实.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

事实用明确陈述及证据版本表达；来源声称/支持/确认/争议/反驳/撤回分开。确认需主体、时间、依据，不能由模型置信度决定。纠错保留修订、合并继承和拆分连续性。

1. **事实与进展**（FR-05-01）：新事实能定位材料版本和引用；重复报道不增加事实数量。
2. **修订与纠错**（FR-05-02）：冲突不覆盖；历史修订可复核，但读取仍执行当前许可。
3. **热点判据**（FR-05-03）：热点理由列明实际测量值、分母、阈值版本和证据缺口。

## 数据归属与接口

业务关联/消费合同：04事件修订、03正文版本、10许可。

| 设计归属 | 候选实体/存储 | 本能力关系 |
|---|---|---|
| [04 热点事件识别](../design/04-热点事件识别.md#数据库设计) | `events`、`event_revisions`、`event_evidence` | 同owner引用，当前许可投影 |
| [05 事件证据与新事实](../design/05-事件证据与新事实.md#数据库设计) | `fact_claims`、`fact_evidence`、`event_fact_links`、`event_corrections`、`fact_claim_versions` | 同owner引用，当前许可投影 |

读操作返回资源身份、版本、作用域、许可范围及缺口；筛选cursor绑定当前用户和条件。写动作按[00 产品目标与边界](../design/00-产品目标与边界.md#接口与异步合同设计)使用预期版本和operation_id。本文只定义本模块语义，不绑定既有路由、框架、队列或组件实现。

## 状态、交互与失败恢复

证据编辑触发重评；合并联合首次提醒历史，拆分不因新ID自动提醒。验收场景：r1宣布发布；随后两条转载与发布者延期更正；两个操作都以r1为前置；生成事实差分并并发提交纠错后，延期只计一项更正，转载不增加事实；首个生成r2，后一个冲突；历史通知保持原送达事实。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 数据库设计

目标关系模型；字段、键、查询索引和生命周期由同编号需求推导。类型为候选表达，正式DDL需验证枚举、长度、外键、容量、迁移与回退；本轮不执行建表。共享owner复合引用和当前版本指针规则见00。

### `fact_claims`

用途：事实陈述身份及证实/反驳状态；模型置信度不能等同确认。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| current_version | BIGINT | 否 | 当前不可变事实版本 |
| claim_fingerprint | BYTEA | 否 | 语义规范化身份；只能候选去重 |
| created_at | TIMESTAMPTZ | 否 | 首次记录时间 |

键与完整性：PK(id)；UNIQUE(owner_id,id)；当前版本复合指针；不将语义哈希设唯一确认约束。

查询与索引候选：owner_id,created_at；owner_id,claim_fingerprint候选索引。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：更正建立新事实关系和事件修订；源删除不自动抹去更正，但证据可读性重新评估。

### `fact_evidence`

用途：一条陈述与支持/反驳材料版本的精确关系。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| owner_id | UUID | 否 | 用户 |
| fact_version | BIGINT | 否 | 冻结事实版本 |
| fact_id | UUID | 否 | 陈述 |
| content_version_id | UUID | 否 | 证据版本 |
| stance | VARCHAR(24) | 否 | supports、contradicts、mentions |
| citation | JSONB | 否 | 引文定位及原文摘要标识 |
| source_independence | VARCHAR(24) | 否 | original、repost、unknown |

键与完整性：PK(owner_id,fact_id,fact_version,content_version_id,stance)；复合FK事实版本和正文版本。

查询与索引候选：owner_id,content_version_id；owner_id,fact_id。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：多条转载不自动构成独立多源证实；撤回后引用不可继续返回。

### `event_fact_links`

用途：每个事件修订下的事实及真正的新增/更正分类。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| owner_id | UUID | 否 | 用户 |
| event_id | UUID | 否 | 事件 |
| revision | BIGINT | 否 | 修订 |
| fact_version | BIGINT | 否 | 冻结事实版本 |
| fact_id | UUID | 否 | 事实 |
| change_kind | VARCHAR(24) | 否 | existing、new、corrected、refuted、withdrawn |
| previous_fact_id | UUID | 是 | 更正/反驳所针对事实 |
| previous_fact_version | BIGINT | 是 | 与previous_fact_id同空或同非空 |
| reason | TEXT | 否 | 相对前修订变化依据 |

键与完整性：PK(owner_id,event_id,revision,fact_id)；fact_version仅用于复合FK，每个修订对同事实只选一个版本；复合FK事件修订、事实版本及可选前事实版本。

查询与索引候选：owner_id,event_id,revision,change_kind。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：相对特定前修订统计，不以新增材料数或模型改写当事实增量。

### `event_corrections`

用途：人工合并/拆分/移动的版本化纠错证据。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| operation_id | UUID | 否 | 幂等操作 |
| actor_id | UUID | 否 | 操作者 |
| expected_revisions | JSONB | 否 | 涉及事件的预期版本 |
| action | VARCHAR(24) | 否 | merge、split、move、correct |
| input_references | JSONB | 否 | 同owner事件/事实/材料清单 |
| result_references | JSONB | 否 | 新修订与身份继承关系 |
| reason | TEXT | 否 | 必填纠错理由 |
| created_at | TIMESTAMPTZ | 否 | 操作时间 |

键与完整性：PK(id)；UNIQUE(owner_id,operation_id)；actor_id→accounts；清单在事务内校验owner及版本。

查询与索引候选：owner_id,created_at DESC,id。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：不删除历史通知；合并抑制重复首次提醒，拆分是否新提醒按规则明确决策。

### `fact_claim_versions`

用途：将事实状态、更正与确认依据冻结在版本中，避免反证改写历史。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| owner_id | UUID | 否 | 用户 |
| fact_id | UUID | 否 | 稳定事实身份 |
| version | BIGINT | 否 | 事实版本 |
| statement | TEXT | 否 | 该版本的实际陈述 |
| state | VARCHAR(24) | 否 | alleged、supported、confirmed、disputed、refuted、withdrawn |
| confirmation_basis | JSONB | 是 | confirmed必须具有确认主体/依据/时间 |
| supersedes_fact_id | UUID | 是 | 明确更正目标 |
| supersedes_fact_version | BIGINT | 是 | 更正目标版本，和ID同空或同非空 |
| created_at | TIMESTAMPTZ | 否 | 版本建立时间 |

键与完整性：PK(owner_id,fact_id,version)；复合FK事实身份及可选被更正事实版本；版本>=1；确认依据检查。

查询与索引候选：owner_id,fact_id,version DESC；owner_id,supersedes_fact_id。

生命周期：旧状态不可覆盖；event_fact_links/fact_evidence都绑定明确fact_version，读取历史仍执行当前许可。

## 当前版本完整性

当前指针采用复合FK：`fact_claims(owner_id,id,current_version)→fact_claim_versions(owner_id,fact_id,version)`。身份首次建立与初版、后续新版本/修订与当前指针/审计同事务；循环关系在DDL采用可延期约束并在提交前验证。不能用应用中随意选最大版本替代当前有效版本。

## 事实与纠错的事务设计

事实是陈述与依据关系，不用“多篇文章”直接推出确认。来源编辑、反证和撤回触发相关结论重评；当前事实状态随新事件修订呈现，旧修订保留当时依据并服从当前可读许可。事实状态采用fact_claim_versions不可变版本，事件修订与证据关系绑定fact_version；不得原地更新身份表让历史r1看起来已经知道r2的反证。

合并/拆分在一次事务内锁定所有涉及事件的预期revision，写新修订、成员/事实关系、纠错证据与规范身份继承。随后通知去重按前身联合判断；趋势保留原窗口/成员集合或明确重算版本。对象身份、原文版本和历史送达事实不被纠错改写。
