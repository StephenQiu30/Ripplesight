# 01 关键词配置

需求依据：[01 关键词配置](../requirement/01-关键词配置.md)；开发交接：[01 关键词配置](../prd/01-关键词配置.md)；agent工作拆解：[01 关键词配置](../plan/01-关键词配置.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

配置任一词、必含词、排除词、语言、来源能力、对象范围、查询窗口及单轮上限；合法但无就绪来源的配置可保存为草稿，新主题默认未启用，启用和运行另行校验。

1. **定义监测意图**（FR-01-01）：空规则、词组冲突与无可执行来源各自得到原因；用户可修改。
2. **解释查询语义**（FR-01-02）：同一组规则在不同来源的实际范围可逐项核对。
3. **规则版本与预览**（FR-01-03）：编辑后旧预览失效；并发保存冲突保留草稿；历史任务保留旧规则。

## 状态、交互与失败恢复

正向词全空或必含与排除直接矛盾拒绝保存；规则冲突保留输入。验收场景：草稿任一Alpha/Beta、必含发布、排除招聘；A含Alpha发布、B仅Alpha、C含Alpha发布招聘；保存草稿、在已存样本上预览，再单独请求启用后，只命中A；B缺必含、C排除；保存与预览的外部请求均为0；无就绪来源阻止启用但保留草稿。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 数据库设计

目标关系模型；字段、键、查询索引和生命周期由同编号需求推导。类型为候选表达，正式DDL需验证枚举、长度、外键、容量、迁移与回退；本轮不执行建表。共享owner复合引用和当前版本指针规则见00。

### `topics`

用途：用户的长期监测意图与生命周期。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| name | VARCHAR(256) | 否 | 名称；非空 |
| current_rule_version | BIGINT | 否 | 当前规则版本 |
| status | VARCHAR(24) | 否 | draft、active、paused、archived |
| status_revision | BIGINT | 否 | 每次状态变更递增 |
| created_at | TIMESTAMPTZ | 否 | 创建时间 |
| updated_at | TIMESTAMPTZ | 否 | 更新时间 |

键与完整性：PK(id)；UNIQUE(owner_id,id)；owner_id→accounts；current_rule_version及status_revision>=1。

查询与索引候选：owner_id,status,updated_at DESC,id。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：归档不删除历史；状态变更使旧执行授权失效。

### `topic_rule_versions`

用途：监测意图的不可变可解释规则。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| topic_id | UUID | 否 | 所属主题 |
| owner_id | UUID | 否 | 用户 |
| version | BIGINT | 否 | 规则版本 |
| match_any | JSONB | 否 | 任一词组数组 |
| match_all | JSONB | 否 | 必含词组数组 |
| exclude | JSONB | 否 | 排除词组数组 |
| language_policy | JSONB | 否 | 语言与未知处理 |
| source_snapshot | JSONB | 否 | 来源语义解释快照；实际关系由topic_rule_sources约束 |
| object_scope | JSONB | 否 | 原帖/评论匹配范围及字段语义 |
| window_policy | JSONB | 否 | 来源可执行窗口及用户选择 |
| limits | JSONB | 否 | 查询数、请求数、材料/评论上限 |
| created_at | TIMESTAMPTZ | 否 | 版本时间 |

键与完整性：PK(owner_id,topic_id,version)；复合FK主题；三组词均为数组；至少一组正向规则非空。

查询与索引候选：owner_id,topic_id,version DESC。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：不可原地改写；来源关系以topic_rule_sources关联表约束，解释快照不是独立关系真源。

### `topic_rule_sources`

用途：使主题规则的来源选择具备数据库可约束的归属和版本关系。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| owner_id | UUID | 否 | 用户 |
| topic_id | UUID | 否 | 主题 |
| rule_version | BIGINT | 否 | 规则版本 |
| binding_id | UUID | 否 | 来源绑定 |
| binding_version | BIGINT | 否 | 冻结来源配置 |
| capability | VARCHAR(32) | 否 | 选用能力 |
| ordinal | INTEGER | 否 | 稳定执行次序；>=0 |

键与完整性：PK(owner_id,topic_id,rule_version,binding_id,capability)；复合FK→topic_rule_versions及binding_versions；禁止跨owner。

查询与索引候选：owner_id,binding_id；owner_id,topic_id,rule_version,ordinal。

生命周期：替代仅JSON保存来源关系的候选；JSON只保留解释快照。配置改变必须产生新版本，执行时仍重验当前准入。

## 当前版本完整性

当前指针采用复合FK：`topics(owner_id,id,current_rule_version)→topic_rule_versions(owner_id,topic_id,version)`。身份首次建立与初版、后续新版本/修订与当前指针/审计同事务；循环关系在DDL采用可延期约束并在提交前验证。不能用应用中随意选最大版本替代当前有效版本。

## 规则求值与查询规划

依次执行：输入规范化与冲突校验 → 本地规则真值预览 → 按来源能力规划有限召回 → 解释召回缺口及本地精筛 → 显式保存不可变规则 → 执行受理冻结快照。来源能力改变不无声重写用户规则；真实执行时重新准入，必要时返回跳过原因。

匹配是确定性规则判断，相关性是独立语义判断，二者不合成一个无法解释的分数。对象类型/字段范围及规范化版本属于规则合同；预览结果绑定草稿摘要，输入变化后失效。来源绑定采用topic_rule_sources关系表，以复合外键防止跨owner关联；JSON只保留解释快照，不能声称JSON外键已生效。


## 草稿保存与执行启用

保存只校验规范化规则、已声明搜索能力的来源键及本人订阅流引用；未知来源或跨账户引用拒绝。连接未配置、政策撤回、订阅流停用或预算不足不丢弃合法草稿。readiness仅描述当前来源状态，不代表已启用或已通过真实采集验收；预算在显式启用与执行受理时检查。

新主题暂停且不创建执行调度或任务。关键词及采集配置发生有效变化时，已有活动主题原子保存不可变新版本并暂停，记录带新规则版本的暂停状态序号、禁用旧调度，使旧采集围栏失效；用户明确启用后按当前来源最小间隔重建/更新调度。只修改名称或报告设置不改变采集规则版本，重复保存不制造新版本或状态事件。保存和本地预览均不生成任务、外发或预算预留。

启用请求必须携带用户已审阅的`expected_version`，服务端在主题行锁内先比较冻结版本再检查来源/预算；陈旧版本返回版本冲突且不启用调度。缺少版本不得默认启用当前版本，重复启用也须符合相同版本。来源 readiness 是当前只读提示，保存原样草稿可刷新提示但不创建执行或规则版本。
