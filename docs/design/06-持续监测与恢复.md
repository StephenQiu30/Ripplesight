# 06 持续监测与恢复

需求依据：[06 持续监测与恢复](../requirement/06-持续监测与恢复.md)；开发交接：[06 持续监测与恢复](../prd/06-持续监测与恢复.md)；agent工作拆解：[06 持续监测与恢复](../plan/06-持续监测与恢复.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

调度以不可变政策生效区间、稳定锚点和启停历史重建应执行窗口。暂停采集、停止分析和停止通知是不同控制；采集暂停立即阻止后续采集请求，不撤销已经发生的外部事实。

1. **自然调度**（FR-06-01）：至少两轮自然运行形成回执；窗口无执行必须有跳过或漏轮原因。
2. **停止保证**（FR-06-02）：领取前、请求前及重试前检查状态；恢复不复活已停止的旧运行。
3. **有界恢复**（FR-06-03）：恢复保留冻结输入及已提交材料；模型延后可追踪且不丢数据。

## 状态、交互与失败恢复

不得从已生成窗口倒推完整分母；通知静默不阻止采集，采集静默不自动禁止通知。验收场景：每小时调度，服务离线跨两窗口；恢复前主题已暂停；另一运行第1请求在途第2未发；恢复服务并核对窗口，再提交采集暂停和后续恢复；预期：历史应执行窗口标missed或合法paused并给依据；第2请求不发；恢复建立新授权，不复活旧任务。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 数据库设计

目标关系模型；字段、键、查询索引和生命周期由同编号需求推导。类型为候选表达，正式DDL需验证枚举、长度、外键、容量、迁移与回退；本轮不执行建表。共享owner复合引用和当前版本指针规则见00。

### `topic_schedules`

用途：启用频率、到期与静默政策，不把页面刷新当调度。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| topic_id | UUID | 否 | 主题 |
| current_version | BIGINT | 否 | 指向不可变schedule_versions政策 |
| next_due_at | TIMESTAMPTZ | 是 | 下一应执行时间 |
| enabled | BOOLEAN | 否 | 显式启用 |
| status_revision | BIGINT | 否 | 独立启停授权代际，>=1；不等于政策version |

键与完整性：PK(id)；UNIQUE(owner_id,id)；复合FK主题；每主题当前调度唯一。

查询与索引候选：enabled,next_due_at部分索引；owner_id,topic_id。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：暂停不删除应执行历史；恢复有界，不能无条件补发积压。

### `schedule_windows`

用途：每个应执行窗口的业务事实，包括未执行原因。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 用户 |
| schedule_id | UUID | 否 | 调度身份 |
| schedule_version | BIGINT | 否 | 冻结政策版本 |
| due_at | TIMESTAMPTZ | 否 | 应执行时刻 |
| window_start | TIMESTAMPTZ | 否 | 查询左边界 |
| window_end | TIMESTAMPTZ | 否 | 查询右边界 |
| state | VARCHAR(24) | 否 | due、accepted、skipped、missed |
| reason_code | VARCHAR(64) | 是 | 静默/预算/准入/漏轮原因 |
| run_id | UUID | 是 | 实际受理的运行 |
| recorded_at | TIMESTAMPTZ | 否 | 记录时间 |

键与完整性：PK(id)；UNIQUE(owner_id,id)；UNIQUE(owner_id,schedule_id,due_at)；复合FK→schedule_versions(owner_id,schedule_id,version)；window_start<window_end。

查询与索引候选：owner_id,due_at DESC,id；state,due_at。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：未执行仍保留回执；不得补造历史成功或假运行。

### `schedule_versions`

用途：冻结调度政策，使应执行窗口可以恢复当时的采集静默、时区与到期判断。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| owner_id | UUID | 否 | 用户 |
| schedule_id | UUID | 否 | 调度身份 |
| version | BIGINT | 否 | 政策版本 |
| effective_from | TIMESTAMPTZ | 否 | 政策生效时间；同schedule严格递增 |
| anchor_at | TIMESTAMPTZ | 否 | 稳定调度锚点，用于离线重建窗口 |
| interval_seconds | BIGINT | 否 | >0且遵守来源低频边界 |
| timezone | VARCHAR(64) | 否 | 明确时区 |
| collection_quiet_policy | JSONB | 否 | 禁止开始采集的窗口 |
| expires_at | TIMESTAMPTZ | 是 | 到期时刻 |
| created_at | TIMESTAMPTZ | 否 | 政策建立时间 |

键与完整性：PK(owner_id,schedule_id,version)；复合FK→topic_schedules(owner_id,id)；schedule_windows以(owner_id,schedule_id,schedule_version)引用该版本。

查询与索引候选：owner_id,schedule_id,version DESC。

生命周期：不可原地改写；当前启用状态与下次到期位置是运行状态，和历史政策分开。

## 应执行窗口与启停历史

schedule_versions不可变，每一政策版本有效区间为[effective_from,min(自身expires_at,下一版本effective_from))，空到期或无下一版视作对应无上界；到期与下一版生效间的空档不产生应执行窗口。每次主题/调度启停与audit_events写同事务，审计结构必须含scope、before/after状态、status_revision、effective_at及operation_id；受影响的政策版本明确可查。调度器由政策区间+授权启停区间+锚点重建应执行集合，不能仅统计已有schedule_windows。

恢复时为离线期间应执行但无受理证据的窗口补记missed；合法暂停、采集静默、到期记skipped并给当时依据。默认不密集追赶，确需回补时先重新受理有界查询；UNIQUE(owner,schedule,due_at)防重复。时区规则变更亦新版本。状态修订用CAS递增，旧轮不能因重新启用恢复授权。

通知静默唯一归属07的目标版本，schedule只管采集静默。分析与通知的停止控制各自校验；主题归档对后续通知的影响按发送前当前关注状态重新核对。在途请求只记录真实回执，不宣称能撤销已发生请求。

## 当前版本完整性

当前指针采用复合FK：`topic_schedules(owner_id,id,current_version)→schedule_versions(owner_id,schedule_id,version)`。身份首次建立与初版、后续新版本/修订与当前指针/审计同事务；循环关系在DDL采用可延期约束并在提交前验证。不能用应用中随意选最大版本替代当前有效版本。

初始创建调度与主题也须同事务写授权历史起点（before=null、after=初态、status_revision=1、effective_at=创建时刻）。后续启停CAS递增各自status_revision，政策版本变化独立递增version；历史审计不得清理到破坏仍需验收窗口的分母重建。
