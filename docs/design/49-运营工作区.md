# 49 运营工作区

需求依据：[49 运营工作区](../requirement/49-运营工作区.md)；开发交接：[49 运营工作区](../prd/49-运营工作区.md)；agent工作拆解：[49 运营工作区](../plan/49-运营工作区.md)。以下为目标设计，未据此改变代码或业务数据库；共享架构、事务及选型原则见[00 产品目标与边界](../design/00-产品目标与边界.md)。

## 设计目标与业务流程

展示业务失败、预算used/reserved/remaining、通知未知及质量诊断；审计操作/原因/结果与必要字典维护，反馈处理权限单列，默认不暴露私人正文。

1. **诊断核心运行问题**（FR-49-01）：回执能回到具体运行和原因，敏感信息脱敏。
2. **审计维护与反馈处理**（FR-49-02）：维护显式受理、权限校验和审计；失败及未知不误报成功。

## 状态、交互与失败恢复

当前页不能估计全局连续失败。验收场景：预算 used8/reserved2/limit10且改限额5；一条未知通知；查看诊断、审计及反馈处理后，remaining按当前上限扣占用且不为负可用额度；降额阻止新预留；未知可核对。

界面先呈现完成任务所需的事实与限制，再给出动作和回执。遵循[11 质量评测与验收](../design/11-质量评测与验收.md#共享状态与反馈)的共用状态、焦点和过期响应规则；无外部读取的静态内容不套远程加载状态。数量、分页、排列由内容规模和性能基线决定，不继承旧固定页数/栏宽。

## 数据库设计

目标关系模型；字段、键、查询索引和生命周期由同编号需求推导。类型为候选表达，正式DDL需验证枚举、长度、外键、容量、迁移与回退；本轮不执行建表。共享owner复合引用和当前版本指针规则见00。

### `audit_events`

用途：必要写操作及管理行为的最小审计。

| 字段 | 候选类型 | 可空 | 业务含义与规则 |
|---|---|---|---|
| id | UUID | 否 | 主键 |
| owner_id | UUID | 否 | 被操作数据所属用户 |
| actor_id | UUID | 否 | 操作者 |
| operation_id | UUID | 否 | 操作幂等身份 |
| effective_at | TIMESTAMPTZ | 否 | 业务状态实际生效时间，调度授权可重建 |
| state_transition | JSONB | 是 | 启停类必填：scope、before/after、status_revision、政策版本；带schema_version |
| action | VARCHAR(64) | 否 | 行为类型 |
| resource_reference | JSONB | 否 | 类型/身份/版本，不存秘密正文 |
| reason | TEXT | 是 | 纠错/维护等需必填 |
| result | VARCHAR(24) | 否 | accepted、completed、failed、unknown |
| created_at | TIMESTAMPTZ | 否 | 操作时间 |

键与完整性：PK(id)；UNIQUE(owner_id,operation_id,action)；actor_id→accounts；敏感操作原子写审计。

查询与索引候选：owner_id,created_at DESC,id；actor_id,created_at DESC。 索引用真实查询基线复核，不能把索引存在当性能达标。

生命周期：审计保留期独立确认，删除后不保留可恢复的个人正文。
