# 02 关键词热点

## 1. 要解决的问题

用户关心某个主题（产品、公司、事件），不想分别去各个平台搜索。设好关键词后，应该每小时自动拿到各平台上的相关热点，并且知道哪个平台没找到、哪个平台出了故障。

## 2. 功能

- 创建主题：关键词支持“任一词 / 全部词 / 排除词”与别名，保存前可预览已有材料的命中情况。
- 每小时自动采集，主题页按热度汇总各平台的命中：帖子、热榜条目、X 趋势、评论量。
- 每条命中都标明来源平台、获取方式（平台原生搜索 / 本地关键词过滤 / 热榜）与更新时间。
- “没找到”“失败”“未授权”“未接入”分开显示，不混为空结果。

## 3. 做法

| 来源类别 | 平台 | 获取方式 |
|---|---|---|
| 关键词搜索 | Hacker News、Google News、SearXNG（本机）、RSS/Atom | 原生搜索或本地过滤 |
| 国内热榜 | 微博、百度、知乎、B 站热门、36Kr、澎湃 | 本机 RSSHub，保存快照与排名变化 |
| 社交平台 | X、微博、抖音、小红书、B 站 | 见 [03](03-每日社媒热点.md) 与 [04](04-评论舆情.md) |
| 补充热榜 | 参考开源项目 newsnow（MIT）逐个补充 | 每个新源单独准入 |

- 主题数据在 `monitors`，采集任务在 `sources` + `jobs`，热度计算在 `events`。
- 热度按现行公式计算，并显示各来源的贡献与缺失字段；不可比较的数据不标“降温”。

## 4. 现状

| 项 | 状态 |
|---|---|
| 主题创建、关键词规则、每小时自动采集 | 可用 |
| Hacker News 搜索 | 可用：两个账户有真实帖子命中 |
| Google News、SearXNG、RSS、六个热榜 | 部分可用：代码完成；“四个搜索来源 + 六个热榜”在同一时间窗的真实短窗验证未通过 |
| 社交平台入口目录与零付费门禁 | 部分可用：目录与门禁完成，尚无任何社交平台的真实采集 |
| 主题热点汇总页 | 未开始 |

## 5. 验收标准

1. 同一主题至少 3 个不同平台有真实命中，热度排序可以按公式复算。
2. 四个搜索来源和六个热榜在同一个 24 小时窗口内各自有真实结果，或明确记录的失败/空结果。
3. 连续 72 小时内，每小时采集的有效完成率 ≥95%，从到期到页面可读的中位时间 ≤10 分钟。
4. 失败、空结果、未授权三种情况各至少出现一次，并在页面上被正确区分。

## 6. 不做什么

- 不保证全站、全历史覆盖；本地过滤不冒充平台原生搜索。
- 不接 Instagram、Facebook、Threads（已冻结）。
- 不为凑数据提高采集频率。
