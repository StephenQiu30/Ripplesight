# 02 关键词热点

2026-10-07 设计范围已重整：当前以[总 PRD 的国内 POC](../product/prd/01-PRD.md#当前-poc找到相关帖子并读到可追溯的评论)为准。本页保留后续持续监控目标和历史状态；没有新增真实验证结果，不以 `部分可用` 证明当前平台链路通过。架构、数据库和验收分别在[技术架构](../../PROJECT.md#12-关键词监控工程设计提案)、[数据库设计](../product/reference/07-关键词监控数据库设计.md)、[交付设计](../research/2026-10-07-关键词监控验证与交付设计.md)。

## 1. 要解决的问题

用户关心某个主题（产品、公司、事件），不想分别去各个平台搜索。设好关键词后，应该每小时自动拿到各平台上的相关热点，并且知道哪个平台没找到、哪个平台出了故障。

## 2. 功能

**当前 POC 的功能设计**（提案，尚未实现差量）：

- 来源按关键词、详情、评论/回复、增量分别说明能力；记录免费路径、许可和版本，不把热榜本地过滤显示为全站搜索。
- 主题说明、词组、别名、窗口和预算形成不可变运行快照；修改、暂停、恢复与归档不改写已有结果。纯本地预览与需要在线取数的预览分开。
- 有界保留过滤前候选及查询/命中/排除原因，能解释漏采和误判；评论另见 [04](04-评论舆情.md)。
- 相关性四档、未分析/失败状态及原文理由分开；先显示相关且时间可信内容，未知日期单列，规则与排序版本可追溯。热度不代替相关性。
- 同一操作重试不制造重复结果；新一轮确有抓取才更新采集批次。分页使用固定结果依据；取消保留已提交数据，完整窗口未确认不前推水位。
- 用户可按平台/时间/相关性筛选、核对出处并反馈；各来源成功、无匹配、部分、失败与停止原因可见。

本节不另定义数值阈值，功能条款和非功能要求引用 PRD；每轮预算以执行卡冻结。以下为**后续持续监控**范围：

- 创建主题：关键词支持“任一词 / 全部词 / 排除词”与别名，保存前可预览已有材料的命中情况。
- 每小时自动采集，主题页分别展示相关结果与热度汇总：帖子、热榜条目、X 趋势、评论量；不以热度覆盖主题相关性。
- 每条命中都标明来源平台、获取方式（平台原生搜索 / 本地关键词过滤 / 热榜）与更新时间。
- “没找到”“失败”“未授权”“未接入”分开显示，不混为空结果。

## 3. 做法

| 来源类别 | 平台 | 获取方式 |
|---|---|---|
| 关键词搜索 | Hacker News、Google News、SearXNG（本机）、RSS/Atom | 原生搜索或本地过滤 |
| 国内热榜 | 微博、百度、知乎、B 站热门、36Kr、澎湃 | 本机 RSSHub，保存快照与排名变化 |
| 社交平台 | X、微博、抖音、小红书、B 站 | 见 [03](03-每日社媒热点.md) 与 [04](04-评论舆情.md) |
| 补充热榜 | 参考开源项目 newsnow（MIT）逐个补充 | 每个新源单独准入 |

来源选型见[GitHub 专项研究](../research/2026-10-07-GitHub免费热点与评论采集调研.md)。MediaCrawler、WeiboSpider 为国内取数候选；NewsNow/DailyHotApi 只补热榜，RSSHub/SearXNG 逐路由验证。公众号、视频号、头条完整链路仍有缺口。表中来源不是当前全部接通清单。

- 主题数据在 `monitors`，采集任务在 `sources` + `jobs`，热度计算在 `events`。
- 热度按现行公式计算，并显示各来源的贡献与缺失字段；不可比较的数据不标“降温”。

## 5. 验收标准

**当前 POC**按 PRD 目标、[执行卡](../research/2026-10-07-国内平台关键词监控POC验证.md)与交付设计逐平台留证。以下四项是历史持续监控验收，不作为首个切片的前置，也不因新文档通过自动达成。

1. 同一主题至少 3 个不同平台有真实命中，热度排序可以按公式复算。
2. 四个搜索来源和六个热榜在同一个 24 小时窗口内各自有真实结果，或明确记录的失败/空结果。
3. 连续 72 小时内，每小时采集的有效完成率 ≥95%，从到期到页面可读的中位时间 ≤10 分钟。
4. 失败、空结果、未授权三种情况各至少出现一次，并在页面上被正确区分。

## 6. 不做什么

- 不保证全站、全历史覆盖；本地过滤不冒充平台原生搜索。
- 当前不接海外；X、Instagram 已是长期目标，未因本次国内设计自动解除冻结或启动接入。
- 不为凑数据提高采集频率。
