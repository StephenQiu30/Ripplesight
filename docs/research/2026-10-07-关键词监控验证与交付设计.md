# 关键词监控验证与交付设计

本文应用 `pm-execution:outcome-roadmap`、`test-scenarios`、`pre-mortem`，把已研究的免费路径转成可验证的交付设计。需求及指标唯一原文是[总 PRD](../product/prd/01-PRD.md)，技术约束和架构设计在 [PROJECT](../../PROJECT.md)，数据结构提案在[数据库设计](../product/reference/07-关键词监控数据库设计.md)；选型证据引用 [GitHub 调研](2026-10-07-GitHub免费热点与评论采集调研.md)。本页不复制另一套需求，不建立任务状态表。

**当前仅设计，不实施、不采集、不变更数据库或部署。** 工作包、相对工作量、职责和阶段关口均为 AI 提案，不代表已经派发、获准运行或承诺上线日期。实际任务优先级及状态只维护在 [BACKLOG](../../BACKLOG.md)。后续执行沿用[需求入口](../product/reference/04-需求与验证入口.md)、[AI 任务协议](../product/reference/05-AI任务协议.md)及[工程规范](../../AGENTS.md)；已确认的国内优先和免费取数方向不重复询问。

## 从建设功能转为验证结果

要使本人能够从配置的关键词出发，读到相关且时间可信的国内帖子与评论，并判断这些信息是否值得继续跟进。国内主流平台是整体目标，单平台只是最小验证切片；海外平台保留后续目标。未取得真实证据的平台不得用其他平台结果代填。

| 常见建设清单 | 本轮要验证的结果 | 判断依据 |
|---|---|---|
| 接入一个高 star 爬虫 | 本人在零第三方取数费用的边界内取得可核对的原帖与评论 | 固定版本、许可与依赖清单，以及真实来源运行记录；不是 README 或 star |
| 增加更多平台图标 | 每个平台哪些环节可用、哪些缺失都能被解释 | 按关键词发现、详情、评论、父链、时间、增量分别给结论 |
| 上 AI 相似度 | 本人少读无关内容，模型判断可回到证据核对 | 同一冻结候选池对照关键词基线，四档相关性及误例；不增加未经校准连续分数 |
| 做实时刷新和自动调度 | 本人能分清新帖、新回复、缓存、旧闻及来源失败 | 真实抓取批次、来源时间依据、发现与处理耗时；不从刷新按钮推导实时 SLA |
| 做一个完整舆情看板 | 本人能配置、读结果、展开评论、核实原文并反馈 | 一条可操作 demo 及用户原话；情感占比、告警和日报不是该结果的前置 |

## 阶段工作包与依赖

每次只选一个有明确输入、输出与停止条件的切片。阶段顺序表达证据依赖，不是自动按表推进的任务队列；入口可以根据已有可信证据跳过重复工作，但不能省略对应关口。

| 结果阶段及工作包 | 可复核交付物 | 进入条件与依赖 | 放行条件及未达到时的动作 | 建议职责 | 相对工作量 |
|---|---|---|---|---|---|
| 需求和免费路径能够被一致复述 | PRD 条款、逐平台候选与费用/许可证明、单卡输入输出；待定问题只保留真正影响执行者 | 最新用户指令与 GitHub 证据；核对实际采用版本，不套用上游其他版本 | 首卡平台、主题、窗口、预算、来源模式、模型配置、验证条件可核对；费用或许可未知的路径不准入 | Stephen 定边界；产品/架构设计者整理；Claude 后续审查 | 1—2 单位 |
| 首个平台的数据身份与运行状态可信 | 现有实体映射、必要的契约/结构差异、固定样本回放、幂等与失败证据 | 前项及架构/数据库设计；仅在获准实施后修改最小业务切片 | 原帖/评论身份、时间、直接父链或缺口、候选来源、规则版本可追溯；相关性与情感字段解耦；结构断言和相应检查通过 | Codex 实施与自查；Claude 审查 | 2—4 单位 |
| 首个平台免费取得真实帖子和评论 | 一张[国内 POC 卡](2026-10-07-国内平台关键词监控POC验证.md)、真实批次、脱敏数量、来源与停止原因 | 前两项、有效的执行授权与本人登录；只使用准入路径 | 按 PRD 逐项记录结果；登录、风控、费用、许可或字段失败即停该项。样本不足不补造、不扩请求凑数 | Stephen 提供登录；Claude 真实验收；Codex 按任务修复 | 首次可行性探测沿用 PRD 半天上限；后续必要修复另估 1—3 单位 |
| 相关性和时效性确实改善阅读 | 冻结校准/评估池、四档人工标签、关键词基线对照、时间统计、误例和模型失败记录 | 足量真实候选及规则/内容/模型版本；首批数据无免费依赖缺口 | 分别判断数据量、质量、漏采与时间；AI 没有增益就如实记录。模型额度不足时保留待分析原文，不切付费模型 | Stephen 判定业务相关性；Claude 组织验收；Codex 实现必要处理 | 2—4 单位 |
| 本人能走完首个平台的两轮 demo | 配置→结果→评论→原文→反馈→次轮的可复跑操作记录 | 前述最小路径；实际新抓取批次可辨；部分结果可解释 | 达到 PRD 用户任务条件；两轮不重复入库；观察到真实新回复才验证评论增量。失败与无新内容分开 | Stephen 操作并反馈；Claude 记录；Codex 处理确认缺陷 | 1—3 单位 |
| 国内平台覆盖逐项有结论 | 每个平台独立的输入、运行、质量和缺口证据；同主题跨平台阅读对照 | 首平台形成可信方法；下一平台费用/许可/账号与获取方式单独准入 | 按 PRD 工作清单逐项评审；头条、公众号、视频号仍无合格路径时保留缺口。不能自动删平台或用热榜替代评论 | Stephen 决定范围调整；Claude 验收；Codex 逐卡实施 | 有准入路径的平台每项暂估 2—5 单位；未知路径不估完整接通工期 |
| 决定是否进入小范围持续使用和正式能力 | 有界运行方案、维护成本、队列/失败/恢复指标及正式验收材料 | 用户价值和目标平台证据足够；运行窗口、频率、资源预算另行约定 | 按工程规范区分代码完成和能力可用；只有真实记录支撑才更新能力。运行门槛未满足时缩小并行量或暂停来源 | Stephen 决定继续；Claude 验收；Codex 实施必要加固 | 小范围持续验证与加固暂估 2—4 单位，观察等待另计 |

相对工作量的基准假设是“熟悉现有代码者的一段半日净工作”；区间包含设计、实现、自查与一次修复，**不是日历工期**。项目没有历史速度，本人登录等待、平台恢复、真实内容产生与模型排队均另计。前两个获准切片记录实际净耗时后校准；一次探测到点交付成功、失败或证据不足，不能拿修复估算自动延长该轮。

未确定净可用容量之前不建立 Sprint 承诺。未来每轮拟选工作量不得超过该轮净容量的 80%，其余作为返工缓冲；平台未知路径不能作为零工作量塞入容量。不把每个平台区间直接相加承诺“全部主流平台何时上线”，也不沿用旧 V1/V2 排期自动开工。

职责按现有工程分工建议：Stephen 决定方向并提供账号条件；Claude 审查及真实验收；Codex 在获准任务内实现与测试。本轮用户委托的产品设计不改变后续分工。审查者或登录条件不可用时先完成独立的设计/固定样本工作，不将尚缺的关口记为通过。

## 验收场景设计

以下是待执行方案，不是测试通过记录。除明确标“真实”者外，均使用固定样本与隔离环境，不靠触发真实风控制造用例。角色默认：Codex 实现/自测、Claude 审查/验收；本人操作和业务标注另列。后续每次实施只选相关场景，不能因表格存在就新增整个测试平台。

数据库检查仅用 `hotkey_test_<后缀>` 独立库，完成后按规范删除；不得连接业务库。所有证据写源码版本、配置/规则版本、执行时间和证据性质，真实原文保留在受控本机位置，公开知识库只登记必要脱敏事实。不保存 Cookie、Token、连接字符串或无关用户画像。

| 场景与验证目标 | 前提与角色 | 操作步骤 | 预期结果 | 证据 |
|---|---|---|---|---|
| 免费依赖不明不能默许准入 | 固定版本依赖清单；构造必需付费、费用未知、免费直连、可选广告四种配置 | 逐项核对许可和实际取数路径→选择各配置→尝试创建采集任务 | 必需付费/未知路径被拒绝且不发外部请求；可选付费模块关闭并可核对；免费 key 不凭“有 key”误拒，也不凭赠送额度通过 | 准入理由、配置差异、模拟请求计数；真实阶段补实际依赖证明 |
| 关键词歧义、硬排除与别名 | 同名负例、真实讨论、售号广告、反售号讨论及不含字面词的近义正例 | 预览任一/全部/排除组合→运行本地筛选→查看候选与排除原因→修改别名再预览 | 实际查询和本地过滤区分；误杀可见；未进入候选的正例不能声称由重排找回；空或冲突配置的处理与 PRD 一致 | 规则版本、输入输出及漏采发生阶段 |
| 运行中变更主题规则与错挂候选 | 同一主题两个规则版本，旧任务尚未完成；另有同 owner 的旧观测与不同查询 | 启动旧版本任务→保存新规则→查看两次结果→尝试把旧观测或错查询挂到新运行 | 已运行任务保留冻结版本；新规则只作用于后续任务；候选必须匹配本轮查询/规则/采集批次，历史输入只有显式复用或导入才允许，不能算新实采 | 任务、候选、查询、观测来源与分析的版本关系 |
| 评论父链与部分采样 | 一级评论、二级回复、缺父、被删/不可见、零评论及截断样本 | 展开“终于修好了”等短回复→定位原帖和直接父目标→查看排序/页数/上限 | 短回复不因无关键词被直接丢弃；根线程不冒充直接父评论；未知关系不猜补；不可见/失败不写零评论；样本不推断总体舆论 | 关系字段、界面状态、采样记录和来源定位 |
| 四档相关性及情感解耦 | 同一冻结评估池、关键词基线；人工标注隐藏算法标签；含直接相关且无情感结果样本 | 标注四档与原文片段→分别生成基线和模型结果→按 PRD 计算指标→保存无情感的相关项 | 质量结果按既定分母报告；信息不足/模型失败不等于无关；无情感不阻断相关性保存，POC 不被迫执行情感分析 | 标注文件、基线/模型对照、契约与数据库约束结果；无 AI 增益也保留 |
| 时间窗口与未知日期 | 冻结 UTC 半开窗口 `[start,end)`；含两端边界、跨时区、相对时间、无日期和未来异常 | 规范时间→过滤→分别查看原始值、时间依据和北京时间显示→复算耗时 | start 纳入、end 排除；未知/异常不进入最近发布达标集合；相对时间保留精度；重抓不改首次发现；处理耗时不充当发现延迟 | 边界样本、各时间字段、排除原因与计算式 |
| 同源重跑、并发与跨帖相似文本 | 同一原帖/评论重复页、两个并发任务、同文不同原生 ID | 并发写入→重复消费同一消息→再次采同一 ID→展开两个相似帖评论 | 同一作用域的原生身份不重复入库或重复记账；正文变化可保留版本；不同帖和跨平台原帖不合并作者/父链 | 唯一约束、任务/预算前后计数、内容及版本对照 |
| 页提交与完整覆盖水位 | 固定三页数据，第二页失败；模拟“数据提交前”“提交后确认前”中断 | 分别注入中断→恢复同配置任务→核对数据、页检查点和完整覆盖记录 | 已提交页保留；未提交页可重放而不丢/不重；只有满足设计的完整性条件才推进相应水位；受限搜索、截断或空热榜不能标全站完整覆盖 | 事务边界、恢复前后检查点、覆盖原因和唯一记录计数 |
| 暂停、取消和超时 | 任务已提交一页、下一页进行中，含 worker 子进程 | 分别暂停主题、取消运行、触发超时→观察在途及后续调度→按有效授权恢复 | 暂停阻止后续调度，在途运行可按冻结预算结束；取消/超时才回收进程组并确认终止；均保留已提交数据，未确认完整范围不推进水位；恢复受租约和剩余预算约束 | 任务状态、进程回收、请求计数、租约与水位 |
| 稳定阅读分页与源游标异常 | 同时间/同标签跨页样本；固定阅读结果版本；重复或失效的来源游标 | 第一页后写入新帖/分析结果→继续旧版本分页→显式刷新；另回放重复/失效源游标 | 同一阅读快照不重不漏，新结果经刷新可见；版本失效时明确要求重开，不混用排序；源游标无进展或失效停止该范围，不无限循环或前推完整水位 | 分页键/版本、去重计数、异常原因、请求预算及水位 |

## 风险预演与关口动作

采用 pre-mortem 的思考方式：假设首批真实 demo 未带来价值，回看可能漏掉的原因。这里不假设十四天后上线、不设置营收目标；按“真实风险、被夸大的担忧、尚未说清的隐忧”分类。严重性和负责人都是设计提案，实际处置状态仍只写 BACKLOG。

| 类型与风险 | 对用户结果的影响 | 动作与建议负责人 | 关口与紧迫性 |
|---|---|---|---|
| 真实风险：免费软件背后仍需付费数据、签名或模型 | 违反免费取数底线，无法持续复跑 | Codex 固定路径/版本和必需依赖；Claude 复核免费证据；Stephen 决定不满足时调整范围，不能购买兜底 | 来源准入前必须解决；未知按不准入 |

## 交付记录与范围调整

后续每张卡至少交付：需求/设计引用、执行授权与输入版本、真实或固定样本说明、最短复跑步骤、逐项结果、证据位置和不能证明的范围。工程检查只执行实际改动对应项；文档校验/构建、受控测试、真实来源验收和本人操作反馈分开报告。

优先缩减一轮请求数、所选帖子数或同时验证的平台数，使切片可执行；这只改变本轮投入，不自动降低质量门槛或删除总体平台目标。首轮样本不足则记录证据不足；如确需调整验收条件，先记录原因和新的适用轮次，不能事后改分母把旧失败改成通过。

当候选费用/许可变化、来源连续失效或用户觉得维护成本过高时，保留既有证据与最后成功时间，选择换免费路径、暂停该来源、调整目标或停止投入。任何部署、数据库切换、提交发布和正式能力声明继续遵守现有授权与验收流程；本文不会触发它们。
