# PRD：全站页面需求

## 1. 摘要

当前任务以Figma桌面稿为页面依据，从layout、基础组件到首页、探索、事件、日报、榜单、监控、收藏和登录重新实现。旧前端已被用户明确否定，不能作为保留视觉或撤销需求的基线。源码/生成API/schema只负责证明哪些服务可复用、哪些数据尚未开放。

逐页文档分别列出原稿字段/展示数量、现有合同、需要持久化的用户动作及缺口。统计/情感/关注/已读是设计需求，不因旧页面没有而删除；但不预建通用平台，也不把设计示例写入产品。

## 2. 联系人与职责

| 角色 | 职责 |
|---|---|
| 需求提出者 | 决定产品取舍、核对实际页面体验，提供必要账号/模型配置 |
| Codex | 从页面和服务核对字段、状态、数据依赖；实现已授权修复、精简与测试 |
| Claude | 沿用工程规范的独立代码审查与真实验收；未执行时不得记为通过 |

## 3. 背景与机会

现有主流程是公开阅读和个人关键词监控。过去设计把云同步、操作账本、情感聚合、批次系统等当成默认前置，容易先建设大量页面没有使用的数据结构。现在把每个控件连接到现有响应字段，把查询派生值和持久业务事实分开，优先维护能工作的最小闭环。

## 4. 目标与可衡量结果

| 目标 | 验收依据 |
|---|---|
| 每个主页面的数据有出处 | 任一显示字段可定位实际组件、API响应和存储或派生计算；数量注明本页、窗口或全量 |
| 每个写操作有明确结果 | 输入、持久字段、授权、冲突和结果未知的处理可解释；保存/受理/完成不混淆 |
| 消除无依据扩展 | 由原稿交互推导最小合同；每个新增或保留结构有明确读写方 |
| 不破坏正在使用的服务 | 正常/空/加载/错误/撤权，旧链接、权限、版本和运行恢复仍有验收依据 |

不以文档、表或接口数量考核完成，不将固定样本通过等同真实采集可用。

## 5. 用户细分与任务

公开读者需要从热点找到可信材料并沿来源阅读；个人跟踪者需要配置关键词、知道运行是否有效、读到帖子与评论；维护者只在来源失败、许可撤回或配置变化时使用辅助管理；项目维护者通过同一份Markdown需求支持开发。没有新增企业租户、付费订阅或原生客户端需求。

## 6. 价值主张与完整旅程

| 旅程 | 最小成功结果 |
|---|---|
| 首页/探索 → 事件/文章 → 原文 | 标题、摘要、来源、时间与许可一致，缺数据不编造统计 |
| 收藏 → 搜索 → 所选导出 | 本机ID可恢复，只导出选择且仍可公开的信息 |
| 登录 → 来源 → 新建主题 → 运行 → 结果 → 评论 | 配置保存、任务受理、实际采集、分析就绪分别可辨；失败能定位和恢复 |
| 日报/榜单 → 固定期/模型 → 引用证据 | 同一修订或计算轮次可追溯，不把历史版本拼成当前结果 |
| 页面需求 → 接口/数据 → 单个实施切片 | 需求能约束实现，历史扩展不能反过来扩大范围 |

### 共用功能和业务规则

- 页面布局用现有shadcn/Radix和语义组件；各页使用同一标题、输入、错误和空态规范。不为旧固定header保留未使用分支。
- 公开列表只读许可投影；个人资料按会话owner隔离。公私详情相似不能合并授权边界。
- 主题三个入口共用TopicsWorkspace；资料正文、评论、事件和报告引用共用内容身份与版本，不按页面复制。
- URL保存查询/页签；临时选择和草稿在组件；本机收藏/阅读位置在localStorage；业务配置和结果才写持久库。
- 统计用当前查询范围，不把首页50事件上限或主题最近5条外推为全站总量；null和真实0不同。
- RSS、MCP/Agent、海报等仍受冻结决策约束。源码已有入口只表示兼容存在，不代表重新授权扩建。

### 数据与接口交付

[接口设计](../reference/08-全站页面接口设计.md)按当前读取/写入路径定义合同；[数据库设计](../reference/09-全站页面数据库设计.md)给出字段、关系、键、查询与删除要求；[非功能要求](../reference/10-全站非功能需求.md)定义有界性能和错误/权限行为；[验收场景](../reference/11-全站验收场景.md)覆盖真实用户旅程。现有接口与表字典仅为查证材料，不是建设清单。

### 能力追踪、取舍和假设

Figma的全站统计、24小时曲线、情感、关注、多类型收藏和告警已读仍是需求；现有服务缺失时保留对应空态，按最小合同分切片接入。通用账本、并行批次状态机和默认云同步不作为前置。具体取舍见[收敛方案](../reference/14-页面驱动的收敛方案.md)。物理删表须核对消费者、迁移与恢复，不因前端重建直接执行。

## 8. 发布顺序与关口

先按原稿重建布局和主页面、用Figma单页合同替换旧视觉方案；再按阅读/监控的一条真实路径修补已证实缺口；最后根据实际瓶颈决定按需聚合、批量读取或辅助模块退役。没有固定日期和整包V1/V2扩建承诺。

每次只交付一个可以独立验证、回滚的变化。源码检查、受控样本、独立库、真实平台、连续运行和用户体验分别记录；进度唯一来源为BACKLOG，不在本PRD另建执行账本。
