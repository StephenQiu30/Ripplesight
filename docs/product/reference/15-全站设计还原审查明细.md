# 全站设计还原审查明细

后续修复与完整双尺寸扫描见[全站验收矩阵](16-全站验收矩阵.md)；下文保留初次问题与当时证据。

## 做了什么

开始审查前，核对main与origin/main都为`e7e886a479822b97573274e9bc407af733ae5e2e`，执行推送返回Everything up-to-date；已有重建代码没有遗漏的未提交修改。

按本人要求使用agent-browser 0.33.0，访问[页面PRD](../prd/03-PRD-全站页面需求.md)列出的52个路由的代表路径，保存截图、控件快照、正文与几何信息。以本聊天此前从[Figma桌面文件](https://www.figma.com/design/DfWRfnw965ocH6lmlSYGgs)导出的10张稿为比对快照：8个核心桌面页面、公共状态和移动首页。桌面1440×1000，核心窄屏390×844。未把缺少单页原稿的辅助页面判为已还原。

本人允许临时测试会话或绕过登录，并说明POC无需认证、登录页面可以保留。本轮采用独立浏览器中的合成会话检查页面，没有创建真实用户，没有改写实际会话/认证接口。运营令牌页面只检查入口，不把普通临时会话当作运营权限。

真实8666开发容器出现OOM断连后，在8776启动同一生产构建、连接真实8667后端补查23个路径；另在8766/8767使用同一前端构建与只读固定样本，补查有数据的核心布局和个人页面。合成样本依据现有API响应形状准备，仅用于版式；不写入业务数据库，不调用采集/收费模型。未检查真实身份写入、运营配置、私密文档发布或真实来源连续运行。

## 结果

**设计还原未通过。** 固定侧栏302px、正文起点350px、核心标题32px、日报标题48px等基础布局与稿接近；登录图形和表单灰色面板已复现。核心窄屏的正文与文档宽度没有超过390px，本机收藏备注可用键盘保存，刷新后仍显示。这些局部结果不能抵消下述差异，也不能说明所有辅助页面已完成重建。

### 正常数据与交互缺口

首页四指标、情感比例、历史曲线与X趋势仍无正常数据；首页目前注明48小时热度，与原稿24小时口径仍需接齐。事件关注和事件收藏禁用，代表评论/情感/平台讨论分布未形成完整正常状态。探索的事件、评论及情感检索没有形成正常闭环。模型榜长上下文禁用，变化/公告侧栏未形成原稿的数据密度。监控小时图、平台检索量与时间、最近告警和全部已读缺完整数据；收藏仍主要支持资讯，事件/评论/日报与关注列表未完成。

这些应按原稿的最小页面合同接入；未知值显示空态是正确的数据诚实性，但不是设计及功能已完成。辅助页面仍有原有业务表单/Token入口；没有对应单页原稿时，只能确认共用外壳和可读状态，不能认定历史冗余已经清理完。

首页另复核空、503错误、403无权限状态，区块边界没有一起消失；本轮没有重跑全站每页五状态矩阵。归档样本初版缺kind/next_before_key，产生undefined链接，已修正样本并排除为产品缺陷；隔离正常归档仍未通过。真实后端归档空态、月份日历和正确链接已独立核对。录制工具切换上下文造成的收藏样本丢失也未列为产品缺陷；重新建立样本后，备注保存与刷新确认通过。
