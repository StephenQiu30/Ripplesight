# 页面驱动的收敛方案

用户最新纠正：旧前端本身就是历史冗余，不能据它撤销原稿需求。以 [Figma](https://www.figma.com/design/DfWRfnw965ocH6lmlSYGgs) 为布局、组件和页面的依据；源码、API和schema用来核对可复用依赖，不能反过来决定原稿该不该存在。本文替换上一版“以旧页面证明没有需求”的判断。

## 三层边界

| 层 | 应采取的动作 | 不应混淆 |
|---|---|---|
| 原稿需求 | 逐页列出展示、数量、操作和状态 | 没接口不等于没需求 |
| 本轮前端 | 清理旧视觉组合、重建布局/组件/页面；已存在合同继续工作 | 空态不等于完整功能可用 |
| 服务接入 | 先明确统计分母/窗口/许可/写入主体，优先查询和现有实体 | 设计出现一块图表不等于需要一张新表或新平台 |

## 逐页替换

| 页面 | 删除的旧组合 | 原稿结构 | 服务承接 |
|---|---|---|---|
| 全站layout | 可折叠图标侧栏、重复页头、阅读全局页脚 | 固定302px侧栏、224px导航、48px正文边距；390px顶/底栏 | 会话、公开入口、管理更多菜单保留 |
| 首页 | 资讯主流、专题推荐、个人工作台CTA | 4项全站指标、6事件首屏、负面提醒、上升5/X趋势6/日报 | 现有事件和刊期；全站指标、24h曲线、情感和趋势缺口 |
| 探索 | 旧高级筛选面板和重复摘要卡 | 大搜索、4类型/时间/情感/排序、结果+平台主题侧栏 | 资讯搜索有效；全量事件/评论检索和情感待合同 |
| 事件 | 相关事件/海报侧栏 | 事实概览、热度、时间线、来源；讨论侧栏 | 公开修订/来源有效；观点/情感/关注缺口 |
| 日报 | 卡片式目录、重复材料墙 | 要点、社媒表、事件双栏、舆情、订阅/目录/往期 | 固定刊期/引用有效；社媒及舆情快照缺口 |
| 榜单 | 额外价格/证据大卡 | 4维度、排名表、本周变化和Codex公告 | 固定run有效；长上下文/跨期变化缺口 |
| 监控 | 默认4页签 | 330px列表+连续关键词/命中/平台/规则/最近告警 | 草稿/运行/结果移到次级操作；24h命中/已读缺口 |
| 收藏 | 阅读历史/分类管理主界面 | 类型、排序、选择工具栏、带备注行、关注/导出侧栏 | 资讯本机收藏及备注；事件/评论/日报收藏与关注缺口 |
| 登录 | 旧垂直位置、额外帮助页脚 | 1040px双栏、556px品牌/420px表单、4页脚链接 | 现有三种验证与回跳有效 |

## 保留与收敛决定

- 备注是原稿明确交互，已用本机纯文本实现，不需要云同步平台。事件关注、多类型收藏也是明确需求，不能因旧实现不存在而撤销；当前仍标未接入。
- 全站统计、24小时情感与命中、已读状态需要最小合同设计，不能用本页长度、48小时值或评估列表替代。优先在现有事实/观察/匹配/评估上查询，再按测量决定是否物化。
- 不新增通用操作账本、独立采集批次状态机、每页面数据副本、搜索会话表或企业多租户。现有jobs、版本、租约、outbox与许可具有真实运行职责，继续保留。
- 未进入原稿的后台入口暂存更多菜单，按消费者证据分切片退役；不直接物理删表。暂停写入、历史读取、外键、备份恢复和独立库迁移验证必须先明确。
- 真实来源范围继续遵循准入与冻结决策；视觉还原不触发海外新采集、付费调用、邮件外发或原生客户端建设。

## 实施顺序与验收

先对原稿重建前端并记录服务空位；再按页面闭环接入最小服务。首页/事件共用一份公开聚合口径；监控命中从匹配与时间查询；收藏/关注只存用户动作；已读只存用户与评估的关系。具体字段和约束见[数据库](09-全站页面数据库设计.md)，请求与失败语义见[接口](08-全站页面接口设计.md)。

每个主页面检查1440px/390px、正常/空/加载/错误/无权限、键盘与旧深链接。工程检查、受控样本、真实业务、用户视觉认可和Claude审查分开记录；不能把前者当后者。只有BACKLOG保存完成状态。
