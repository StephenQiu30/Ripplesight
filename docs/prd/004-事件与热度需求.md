# 事件与热度需求

本文从 [总需求 001](001-热点舆情监控平台需求.md) 保留的 PRD 001 v3.0 基线按 M3 拆出，原基线对应 [Design/Epic 004](../design/004-事件与热度设计.md)；候选执行入口为 [Plan014](../plan/014-事件候选与稳定身份执行计划.md)，其余能力按本文、Design004 与 [BACKLOG](../../BACKLOG.md) 后置排期时补步骤。v1.1 根据历史 Research048 补充方向下的事件发现、分来源热度解释、覆盖可比性和代表证据要求；调研原文已删除，可从 Git 历史查阅。新增需求仍属 M3 后续，Design 定标细则与本轮执行步骤须在排期时补齐。需求状态 `approved` 不表示实现或产品验收通过。

## 1. 目标与范围

**目标**：研究者从已验收的跨平台内容查看同一事件及热度变化，必要时人工合并或拆分。

以 AI 等关注方向为入口，在具体事件中查看相关报道、事件进展、热度变化及代表帖子与评论的原文证据。M1 先完成原始内容、评论、热榜、相关性、阅读与覆盖闭环；事件组织、人工修订及热度仍按 M3 后续切片推进。本次新增 FR-004-003—006 / AC-004-002—005 不扩大 [Plan058](../plan/058-M1短窗POC演示与扩围执行计划.md) A/B 的范围或完成条件。

**不包含**：把单条热榜命中直接当事件；未通过 M2 的 B 站内容；报告、知识库写入与渠道送达。

不新增来源或技术架构，不以市场覆盖宣传承诺全网事件或全量评论；不修改现行 v1 热度公式、来源初始权重与升温阈值，不增加未经校准的降温规则。M3 代表评论与已有引用展示不包含 M4 的新观点生成和质量验收。

## 2. 用户场景与状态

- 从已验收的不同平台帖子查看同一事件的代表内容、来源分布及热度口径。
- 发现自动归并不准时人工合并或拆分，再核对事件成员及升温标注；单条热榜命中仍只是输入。
- 在 AI 方向下查看具体事件及后续报道，区分同一模型的不同发布事件、同名实体和待归并候选，再从事件卡进入代表原帖与评论。
- 比较热度前先核对来源、窗口和可见指标；来源失败、停用或覆盖不足时查看原因，不把采集量减少解释为事件降温。

当前匿名 Demo 直接进入业务页面，不要求账户、登录或用户会话；业务 `owner_id`/`created_by` 仅维持历史业务 UUID 分区，按 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-当前-demo-的访问与数据分区) 解析唯一分区，不能作为用户身份。未来 ToC 账户及多用户隔离见 [PRD001 §2.1 后置账户需求](001-热点舆情监控平台需求.md#21-未来-toc-用户登录需求后置)，当前 Demo 与受控证据不能证明多用户 AC 已通过。页面保留加载、空、业务错误与重试状态；以上场景按本里程碑 FR/AC 与总需求 NFR 核对。

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-004-001 | 事件归并 | 跨平台相似内容归并为事件，保存标题、摘要、首次出现时间、平台分布、热度、情感分布和代表帖子与评论；支持人工合并/拆分 |
| FR-004-002 | 事件热度与升温 | 程序综合互动量、帖子数和来源权重计算热度并记录口径版本，标出新出现、快速升温；报告引用事件时附计算口径，不得把热榜条目自动视为事件 |
| FR-004-003 | 方向下事件发现与事件卡 | 在已验收来源的相关内容中，按 AI 等关注方向查看已确认事件、新出现、快速升温及事件进展；支持方向内关键词、来源和时间窗筛选。事件卡显示稳定身份、标题、摘要、关联关键词、首次发现时间、来源分布、代表帖子、热度状态与最近更新时间，并可进入成员及证据。首次发现时间不冒充事件实际发生时间；同一模型的不同发布和同名实体须按事实区分，后续报道归于对应事件。重复发现不生成重复卡；候选不足仍按现行确认规则保留待归并/待复核，空事件结果区分无相关内容、待归并和覆盖不足。人工合并/拆分沿 FR-004-001，不新建通用修订能力。 |
| FR-004-004 | 分来源热度与 v1 贡献解释 | 沿用 [Design004 §6](../design/004-事件与热度设计.md#6-调度执行与截止) 的 v1 公式、初始权重、近 3 小时增量与此前 24 小时基线、升温阈值及不足判定，展示公式版本、事件修订、窗口、输入观测时间、分来源帖子数、赞/评/转/浏览及缺失标记。按来源解释互动部分贡献，全局帖子数加成单列，不能把每来源帖子加成相加替代原总值。评分只说明当前来源与窗口下的观察热度，不称全网绝对热度；不把平台归一化、搜索兴趣、独立来源数或增长率悄悄加入 v1，也不改变帖子数的既有输入语义。 |
| FR-004-005 | 覆盖缺口与趋势可比性 | 事件趋势说明来源 × 能力 × 时间窗的覆盖与缺口。来源停用、失败、限流、预算截断、指标缺失、来源集合变化、窗口缺口或事件修订不可比时，展示受影响来源、窗口与原因；受影响的趋势比较标为不足或不可比，不把未知量、漏采或观察范围变化解释为降温，也不据此制造升温结论。保留旧快照及其输入口径，不能改写历史掩盖覆盖变化；缺失贡献和全部未知为 null 的处理仍沿现行 v1。 |
| FR-004-006 | 代表帖子与评论的原文和样本边界 | 事件代表帖子、评论及已有观点引用须关联来源内容身份/版本、原帖与可定位证据，区分评论与回复；只有原帖链接时标明原帖定位，不能伪称可直接定位评论。说明采样窗口、实际获取样本数、来源可见总评论数及缺失情况，未知总数保留未知；评论计数不等于评论正文，样本观点不称全平台用户观点。原始评论阅读由 M1 承接，M3 只展示代表证据及已有引用，不要求新增 M4 观点生成或提前通过其模型质量验收。 |

FR-004-003—006 的页面、数据、输入可比性和证据合同见 Design004、Design048；实现和真实产品验收状态分别见 BACKLOG、Acceptance。

## 6. 验收标准与退出条件

**证据门槛**：表中列出的等级须分别具备。受控测试验证状态机、边界与故障；真实运行验证实际来源、外部依赖和持久结果；产品验收按本条样本、连续窗口或用户核对口径作结论。低一级证据不能替代高一级；“代码已合入”本身不属于通过证据。

**退出条件**：真实三平台同事件、人工合并/拆分和升温口径可核对。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。
