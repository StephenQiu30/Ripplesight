# PRD004 事件与热度需求

设计见 [Design004](../design/004-事件与热度设计.md)。

## 1. 目标与范围

**目标**：从已验收的跨平台内容查看同一事件及热度变化，在归属不准时人工合并或拆分。

**用户问题**：同一发布的转载、后续进展和同名实体容易混在一起，来源漏采又可能造成热度下降的假象。用户应能看清事件包含哪些事实、依据来自哪里、趋势是否可比，并能纠错。减少重复阅读是价值假设；没有人工标注样本前不承诺归并准确率或代表全网讨论。

**不包含**：把单条热榜命中当事件；未通过 M2 的 B 站内容；报告、知识库与渠道送达；新增来源或技术架构；修改 v1 热度公式、初始权重与升温阈值，或增加未经校准的降温规则；M4 的新观点生成和质量验收。

## 2. 用户场景

- 查看不同平台帖子组成的同一事件的代表内容、来源分布及热度口径。
- 自动归并不准时人工合并或拆分，再核对成员和升温标注。
- 在 AI 方向下查看具体事件及后续报道，区分同一模型的不同发布、同名实体和待归并候选，从事件卡进入代表原帖与评论。
- 比较热度前核对来源、窗口和可见指标；来源失败、停用或覆盖不足时查看原因，不把采集量减少当降温。

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-004-001 | 事件归并 | 从已验收来源的有效相关内容形成候选，确认后保存标题、摘要、首次出现时间、平台分布、热度、情感分布和代表帖子与评论；标题相似不直接确认，证据不足保持待复核。成员、判断与代表证据关联固定内容版本；人工合并/拆分保留操作者、原因、修订和旧结果，重复执行不产生重复事件或覆盖人工决定。情感或评论缺失保留未知和样本边界 |
| FR-004-002 | 事件热度与升温 | 程序综合互动量、帖子数和来源权重计算热度并记录口径版本，标出新出现、快速升温；报告引用事件时附口径；热榜条目不自动视为事件 |
| FR-004-003 | 方向下事件发现与事件卡 | 按关注方向查看已确认事件、新出现、快速升温及进展，支持关键词、来源和时间窗筛选。卡片显示稳定身份、标题、摘要、关联关键词、首次发现时间、来源分布、代表帖子、热度状态与最近更新时间，可进入成员与证据。首次发现时间不冒充实际发生时间；同一模型的不同发布和同名实体按事实区分；重复发现不生成重复卡；空结果区分无相关内容、待归并和覆盖不足 |
| FR-004-004 | 分来源热度与 v1 贡献解释 | 沿用 [Design004 §6](../design/004-事件与热度设计.md#6-调度执行与截止) 的 v1 公式、初始权重、近 3 小时增量与此前 24 小时基线、升温阈值和不足判定；展示公式版本、事件修订、窗口、输入观测时间、分来源帖子数与赞/评/转/浏览及缺失标记。按来源解释互动贡献，全局帖子数加成单列；评分只说明当前来源与窗口下的观察热度，不悄悄加入其他指标 |
| FR-004-005 | 覆盖缺口与趋势可比性 | 来源停用、失败、限流、预算截断、指标缺失、来源集合变化、窗口缺口或事件修订导致不可比时，展示受影响来源、窗口与原因，趋势标为不足或不可比；不把未知量或漏采解释为降温，也不据此制造升温；保留旧快照及其口径 |
| FR-004-006 | 代表证据的原文与样本边界 | 代表帖子、评论和已有观点引用关联内容身份/版本、原帖与可定位证据，区分评论与回复；只有原帖链接时标明。说明采样窗口、实际样本数、可见总数及缺失；未知总数保留未知，样本观点不称全平台观点 |
| FR-004-007 | 同一事实、后续进展与背景区分 | 成员标明与事件的关系：同一事实的多来源报道、有新事实的后续进展、只提供背景或不相关。实体相同、标题近似或时间接近都不单独证明同一事实；不同型号/版本发布不能误并。信息流可折叠重复报道，新进展独立可见；关系关联成员版本、判断依据与人工修订，证据不足保留待复核；自动重跑不覆盖人工归属 |

事件、卡片、贡献解释、可比性与引用合同见 Design004；事实标识、根事实/直接进展和冲突处理另见 [Design008](../design/008-完整业务设计.md)。

## 5. 非功能需求

适用共享 NFR：NFR-001-101、102、104—108；无专属 NFR。

## 6. 验收标准

**退出条件**：真实三平台同事件、人工合并/拆分和升温口径可核对。

真实质量核对在获准模型与来源就绪后进行：冻结来源、版本、规则及模型判断，人工逐项核对同事实正例、同实体不同发布、近似但无关、后续进展与背景反例，保存原文依据、模型判断、人工结论和纠错原因。结构化输出合法、任务成功或候选数量不代表关系判断正确；无标注基线时不虚构质量数字。

| ID | 前提 | 操作 | 期望 | 证据等级 |
|---|---|---|---|---|
| AC-004-001 | M1 来源有已验收的真实跨平台样本；B 站仅在 M2 通过后纳入 | 用三平台同事件样本归并、人工合并或拆分 | 同一事件在 3 个平台的内容归为一项，人工合并/拆分与升温标注可核对；热榜快照和事件笔记不能替代 | 真实运行；产品 |
| AC-004-002 | 有 AI 方向的同事件跨来源内容、重复发现、后续报道、同模型不同发布、同名实体和无关内容 | 归并后筛选并查看事件卡与进展，再人工纠错并执行后续扫描 | 每个确认事件只有一个当前身份；不同发布与同名实体按事实区分，后续报道归入正确事件，无关内容不进入；卡片字段与持久记录一致；候选不足保持待复核；人工纠错可追溯，重复操作不重复修订，自动处理不覆盖人工结果；空结果原因可区分 | 受控；真实运行；产品 |
| AC-004-003 | 固定事件修订、来源集合、输入观测与公式版本；含可见、部分未知、全部未知指标，以及当前 3 小时与此前八个完整 3 小时基线段 | 计算并查看总热度、分来源贡献和升温解释 | 总值可按 v1 复算，分来源贡献加全局帖子数加成等于总值；全部互动未知为 null，不显示为 0；当前增量须大于 0 且达到基线三倍；阈值边界、基线不足、均值不大于 0、缺窗及修订不可比按现行规则处理 | 受控；真实运行；产品（可复算） |
| AC-004-004 | 先有可比窗口，后出现停用、失败、限流、预算截断、指标缺失、来源变化、缺窗或修订变化 | 查看趋势并与此前窗口比较 | 受影响来源、窗口及原因可见，比较显示不足或不可比；采集减少或未知指标不标降温，也不生成无依据的升温；旧快照保留；恢复后须重新满足基线与可比条件 | 受控；真实运行；产品 |
| AC-004-005 | 有原帖、评论、回复、仅有计数及缺失正文的样本 | 从事件详情阅读代表帖子/评论并打开引用 | 引用关联正确的身份/版本，回复不冒充原帖；仅有原帖定位时清楚标注，仅有计数时不虚构正文；样本窗口、数量、总数或未知、缺失原因可核对；不替代 M4 观点验收 | 受控；真实运行；产品 |
| AC-004-006 | 有同一发布的多篇转载、同实体不同版本、后续争议/修正、仅背景及人工排除样本 | 自动归组、查看进展、人工纠错后重跑 | 重复报道可折叠，新进展可单独阅读，背景不冒充发布事实；不同版本不误并；关系、引用和修订可追溯，重跑不覆盖人工纠错；无证据关系保持待复核；不替代 AC-004-001 | 受控；真实样本与产品 |

AC-004-002—006 不降低 AC-004-001 或 M1/M2 前置门槛；受控模型结果不能证明真实事件发现或观点质量。
