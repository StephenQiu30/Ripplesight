# PRD008 完整业务需求

设计见 [Design008](../design/008-完整业务设计.md)。采集、事件、报告、通知及分发的要求分别由 PRD002/004/005/006/007 持有，本文只定义其余完整业务要求和跨领域归属。

## 1. 范围

保留原有主题规则、来源版本、帖子与评论父链、热榜快照、覆盖和预算、证据生命周期、失败恢复、日报及 Obsidian。公开首页与说明保留 SEO；资讯、专题、已许可日周月刊和已发布模型榜无需登录；个人工作区按 Design001 §9.2 隔离；运营管理员身份独立，不与采集账号或报告收件人混为一体。

业务链路：信源配置/采集/外部摄入 → 材料身份与修订/正文质量/媒体 → 预筛/精选评分/结构化/中文写作/全文翻译 → 事实与故事/人工修订/独立参与者热度 → 全部动态/精选/搜索/分类主题/本机收藏已读 → 日周月刊 → RSS/API/MCP/Markdown/SEO/分享 → 内容通知/运维告警/调用回执/恢复/备份。模型榜与 Codex 公告监控各自拥有采集、状态、读取、页面和定时执行闭环。多数链路改编自 AIHOT，偏差与对齐计划见 [PLAN009](../plan/009-AIHOT参考对齐偏差计划.md)。

“完整”指获准启用后真实用户操作与持久结果一致，不复制上游缺陷、商标、部署拓扑或供应商。真实调用暂停或凭据/费用/许可未定时，功能须实现受控路径并显示禁用原因；未执行的真实验证保持未通过。

| 用户任务 | 要解决的问题 | 应获得的结果 |
|---|---|---|
| 匿名阅读公开资讯 | 不确定页面是否持续更新、模型异常后还有什么可读 | 真实标题、来源摘要、原文与时间，更新和缺口可见；不依赖账户或模型 |
| 登录后关注关键词并阅读报告 | 不知道规则实际取得什么，难以整理某日某周的材料 | 规则、命中材料、评论及个人日周报可追溯；已知、待分析与采样范围清楚 |
| 比较模型、跟进公告及分享 | 排名、价格或预测缺少时点和依据，分享内容可能失去许可 | 已发布榜单的来源与方法、公告原话与复核状态可核对；分享固定版本且仍获准的内容 |
| 维护公开发布和运行 | 故障、撤权、未知结果或备份失败后难以确认影响 | 在独立运营权限下定位来源、任务、版本和预算，执行可审计的纠错、撤回与恢复 |

**假设**（以真实运行与使用反馈验证，未验证前不宣称结果）：指定来源能在获准用途、频次与预算内持续提供材料；关键词、别名与日周报能帮助实际研究（OPEN-001-110/112）；评论样本足以支持相应讨论说明；来源、模型、对象存储和渠道在启用范围内满足合同。

**非目标**：全平台、全历史或全部评论覆盖；跨设备收藏同步；用户实际 Codex 配额到账保证；复制上游品牌、重建服务栈或另建正文库、队列和收费账本。既有暂停与启用条件不变。

## 4. 退出条件与发布门槛

所有源处理器、业务状态、定时任务、HTTP/MCP/RSS 出口、生成客户端、页面和管理员操作逐项可追踪，无仅配置、仅枚举或仅占位的完成项。受控测试覆盖正常、失败、并发、撤回、修订、幂等、预算与重启；真实 PostgreSQL/Kafka/对象存储与浏览器验证接入；真实来源、模型质量、渠道送达和持续窗口单独留证。原 HotKey 操作与数据回归无损后才撤下被替代路径。

处理器或投影缺失是实现缺口；已有路径缺真实来源、权限或连续窗口是验收缺口，两者分别核对。

| 能力 | 面向用户发布的门槛 |
|---|---|
| 公开基础资讯与个人日周报 | AC-002-015、AC-005-013 及相关原 AC；来源、发布分区与个人归属明确 |
| 模型榜 | 获准来源、固定快照与身份可追溯；同版数据、每日四次到期与页面按 AC-008-001 |
| Codex 公告 | X 凭据、用途与费用上限获准后才读真实公告；按 AC-008-002；未获准时零请求 |
| 月报与本机收藏 | 按 AC-008-003、AC-008-004；月报生成、导出、送达分别给结论 |
| 媒体与分享 | 媒体、字体与标识用途获准；按 AC-008-005；读取不补抓未获准媒体 |
| 公开页面与内容出口 | 按 AC-008-006 与所属出口 AC；IndexNow 回执不证明收录 |
| 运营管理与可靠性 | 按 AC-008-007、AC-008-008；备份须实际恢复，unknown 保持人工处理 |
| 六类输入 | 按 AC-008-009；一个类型或平台通过不外推到其他来源 |
