# 报告与知识库需求

本文定义该能力的产品要求，设计见 [Design005](../design/005-报告与知识库设计.md)，当前工作见 [BACKLOG](../../BACKLOG.md)。

## 1. 目标与范围

**目标**：登录研究者按个人关注分别阅读日报、周报及其原帖/评论引用，知道取得了什么、哪些尚未分析、哪些来源存在缺口；知识库启用后，在现有 Obsidian vault 浏览、检索、提问并核对出处。

**问题、对象与价值**：设置关键词的研究者需要把分散材料整理成对应日/周的可追溯记录；整理笔记的用户需要保留个人编辑，并从资料中找到出处。公共周刊、已有设置字段、单份日报导出或数据库检索扩展均不能回答全部问题。报告、对象导出、检索和问答分别以自己的 FR/AC 证明用户结果，减少反复查原帖、误读未知数字和覆盖缺口的成本。

登录后的关键词信息、可支持的评论、个人日报和周报构成最低个人交付闭环；所用来源已准入且具备真实持久材料与读取证据后，两种报告可独立交付，不等待 M1 四关键词/六榜全部验收、事件、知识库、问答或消息推送。其后来源就绪变化不得阻断报告按已知且仍有权读取的材料生成，主题停用、归档、权限撤回和周报开关按各自规则核验。报告、知识库与问答分别按独立 FR/AC 验收，不作为 M1—M3 的技术前置。评论观点生成和质量验收仍归 M4，M1/M2 的评论采集、父链与阅读不依赖此能力通过。

**不包含**：把报告生成等同于 Obsidian 写入或推送送达；未通过 M3 时添加事件结论；未准入、失去权限或无权读取的来源材料；新增商业平台采集、付费模型、向量库或第二报告/投递体系。最低模板闭环不替代既有连续稿和分析质量验收。

## 2. 用户场景与状态

- 在设定时间查看前一自然日日报或上周周报，打开原帖引用并核对数字、覆盖缺口与模板降级标记。
- 在现有 vault 的 `HotKey/` 浏览分阶段导出的日报、事件、精选帖子、周报及主题笔记；重导出后核对用户区块和双链。
- 通过 Web 或 CLI 提问，在答案中打开逐句出处；资料不足时看到明确说明，并核对问答笔记写入状态。

身份、个人数据归属及会话遵守 [总需求 §2.1](001-热点舆情监控平台需求.md#21-toc-用户登录需求) 与 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-公开欢迎页登录与个人数据访问)。

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-005-001 | 报告时间配置 | 以 `monitor_topics.report_time`、`report_timezone`、`weekly_report_enabled` 为唯一设置事实源；当前时区为 Asia/Shanghai，不提供未经定标的多时区选择。报告偏好不升采集版本，写入时检查采集版本冲突，同一采集版本的并发偏好以最后成功提交生效。日报按主题报告时间调度，周报仅在启用时按 FR-005-005 调度；保存设置、来源就绪与报告执行结果分别显示。报告到期扫描不以来源 `readiness_status` 为前置，仍核验有效主题、周报开关及当前权限，来源不足写入报告缺口。 |
| FR-005-002 | 摘要、情感与主要观点 | 对相关帖子提供可追到正文的一句话摘要、正/中/负情感；评论按所属作品批量判断情感并整理已采样评论的主要观点，保留实际体验、支持、质疑和补充证据等具体问题。评论数不代替评论正文，不把不同作品的回复拼成同一线程；样本观点不外推为所有平台用户意见，证据与统计按 FR-005-008 核对。质量仍按现行 NFR 与 AC-005-001 人工抽检，已有分析代码与开发运行记录不等于质量验收 |
| FR-005-003 | 日报生成 | 默认 09:00 Asia/Shanghai 按前一自然日 `[00:00,次日00:00)` 生成日报；先冻结输入，再由程序取数、模型可选润色；模型关闭、不可用或失败时生成标注“模板版”的存档报告，保留待分析材料及引用，不要求先有相关性标注才能展示已知材料。已确认相关、情感/观点与待分析各自计数，送达另验 |
| FR-005-004 | 报告存档 | 日报、周报按主题和时间窗保存版本、覆盖说明与引用；Web 可查看。Obsidian 导出另验 |
| FR-005-005 | 周报生成 | 每周一 09:00 Asia/Shanghai 按上一 ISO 周（上周一 00:00 至本周一 00:00，即上周日 24:00）独立受理、冻结、生成并存档个人周报，种类/主题/窗口的重复到期受理幂等；不等待某个日报 Job 成功，不以公共刊物或改标签的日报代替。保存所用日报版本/日期与引用，缺失日报标缺口、不造空稿或0；程序计算的周内数字与该周已存档日报按同一口径的合计一致。模型降级和未知范围遵守 FR-005-012，渠道送达另验，推送暂缓不阻断 M4 验收 |
| FR-005-006 | Obsidian 知识库 | 只写现有 vault `~/Desktop/Markdown/Obsidian` 的 `HotKey/`：先日报；事件及被报告或事件引用的精选帖子在事件能力上线后导出；周报和主题笔记后续加入。每类对象的准入、版本、写入/重导出与恢复须独立核对，不以日报导出证明其他对象可用。笔记带 frontmatter，先有目标笔记再补双链，保留用户“我的笔记”区块；写前复验当前权限，报告生成和导出失败分别显示 |
| FR-005-007 | 知识库问答 | Web 或 CLI 提问；只检索当前 owner 已存且仍获准的内容、报告及获准事件资料，返回可打开的出处与版本/时间范围；检索能力须独立核对，不以 `pg_trgm` 扩展存在或文件已导出证明可查询。Codex 在获准启用后回答并逐句标出处；资料不足则明说不足，回答存档与写入 `HotKey/问答/` 分别显示成功/失败。读取、检索和提问不替代来源采集准入，不为此开启真实模型或付费接口 |
| FR-005-008 | 评论观点证据与样本口径 | 评论进入报告冻结输入时须保留来源/入口版本、所属作品、评论原生 ID、直接父节点/线程根、回复关系缺口、内容/分析版本和采集时间；摘要/模板同样携带实际采样排序、时间窗、一级/回复范围、实际条数及分页/条数截断，不能只在来源详情显示。每个输出观点须关联可核验的评论原文与引用。观点计数与占比由程序按冻结输入、去重和有效标注计算，保存分子、分母及排除规则；同条评论可含多个观点时说明非互斥，不默认合计为 100%。无法引用、父链无法核对、无评论或证据不足时明确不足/不可用，缺失不写作 0，也不生成无依据的确定观点或全网态度 |

### 最低个人报告闭环

| ID | 功能 | 要求 |
|---|---|---|
| FR-005-012 | 关键词与评论的个人日报、周报 | 用户登录后保存关键词/来源及报告偏好，阅读对应真实信息和来源支持的评论，再按个人主题生成、存档和读取日报、周报；公共刊物不能代替个人主题报告。关键词命中与模型相关性分开，未分析材料显示绑定冻结内容版本的清单、来源/时间依据、原文引用及实际条数，不计入已确认相关、情感或观点统计。模型不可用时模板版仍显示已知材料、来源/评论缺口及范围；没有评论能力、未授权、未尝试、失败、部分与可信零评论分开。互动指标逐字段保留未知空值与真实0；只有部分可知时标“已知部分”及所含指标，不把未知填0或把部分合计称完整互动量。两种报告独立调度，来源就绪、事件、vault 或渠道故障不阻断按仍可读材料生成；停用、归档、撤权和周报开关仍单独核验。 |

个人交付须回答“我关注什么、实际取得什么、哪些仍未知、对应时段报告在哪”。完整路径为保存关注与偏好→读取真实材料/评论→分别按自然日及 ISO 周生成→读取个人存档与引用；已有报告入口只读取定稿报告，首页个人入口引导“设置关注/查看已有报告”。具体实现状态、排期和证据只在 BACKLOG / Acceptance 维护，不以页面文案或设置成功承诺周期结果。

|---|---|---|---|
| 配置个人关注与报告偏好 | FR-005-001、012；Design005 §3.2.3、§4、§5.1 | AC-005-013，关键词版本另按 PRD002 | 当前时区固定 Asia/Shanghai；保存开关不等于周报执行已接通，设置不决定来源就绪 |

### 报告内容与引用

| 报告 | 内容与时间依据 |
|---|---|
| 日报 | 概览与前日比较、重点内容 Top 10、风险与代表观点、各来源覆盖与缺口；M3 事件能力通过后可增加事件区块。按发布时间入窗；缺发布时间者按首次发现时间计并单列条数，注明“样本观察，不代表全网” |
| 周报 | 周内材料与覆盖说明、已有有效标注支持的趋势/上周比较和代表观点、下周关注；M3 事件能力通过后再加入 Top 事件、时间线及持续/平息。引用事件热度时附公式版本和计算口径，不能把不完整窗口当全量趋势；无有效分析时以待分析材料和缺口组成模板版，不编造变化结论 |

日报在精选帖子笔记不存在时只链接原帖；已存在笔记可附链接。精选帖子笔记成功导出后才补 Obsidian 双链，避免悬空引用。报告、知识库写入和渠道送达分别给出成功或失败状态。

缺少部分日报时，个人周报仍可按已冻结的真实周内材料生成并标明缺稿日期；合计核对须列出可比较的日期/版本及未核对范围。该结果可以满足最低可读闭环，不能宣称完整周内合计通过 AC-005-003；不得为了合计相等丢弃周内已知材料、补造缺稿数字或把未知日期计为0。

## 6. 验收标准与退出条件

**证据门槛**：按[总需求的证据等级](001-热点舆情监控平台需求.md#证据等级)逐项满足下表所列等级与用途。

**退出条件**：分析质量、日报、周报、vault 导出和问答各按自己的 AC 独立通过。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。

**独立发布门槛**：最低个人模板闭环按 AC-005-013 联验所用获准来源与真实材料，不等待 M1 十来源正式窗口或 M3/M4 质量全部通过。连续日报、完整周内合计和模型质量仍分别按 AC-005-001—003、007、009 验收；单次模板结果不能替代。对象导出按 AC-005-006、008 分对象核对；检索/问答按 FR-005-007、AC-005-004 另行交付，日报笔记写入或数据库扩展存在不能关闭检索、问答及其他对象导出。未启用的对象/模型能力保持明确不可用，具体状态归 BACKLOG。

## 7. 依赖、决策与未决项

- **依赖**：最低模板闭环使用所用获准来源的真实持久材料与权限证据；M4 正式质量等 AC 继续使用 M1/M2 已验收资料，不以局部模板交付代验来源全范围。事件区块、事件/精选帖子笔记须待 M3 通过；现有 vault 可写、检索就绪和获准模型结果分别影响各自能力，不阻断信息获取或个人模板报告。
- **假设与前置**：材料已有、存在标注、指标有值、评论父链完整、日报齐全、来源仍有权限、vault 可写及模型可用均须逐项核验；未知/不完整输入按 FR-005-008、012 展示，不由模型填补。当前 Asia/Shanghai、既有 Job/预算/存档及源平台准入继续有效，真实 Codex/付费请求保持暂停。日报导出、其他对象导出、检索与问答分别证明入口、真实结果、owner 隔离和恢复，不从处理器/扩展名称推断完成。
- **责任范围**：monitors 持有个人偏好，content/evidence 提供可读材料与父链事实，reports 持有冻结、程序数字与版本，analysis/ai 持有效结果及预算，knowledge 持对象导出/检索/问答，渠道由对应领域持回执；负责人和排期在 BACKLOG 明确。
- **决策/未决项**：沿用总需求 DEC-001-109/111/112/114/212/219/221/224；问答不引入向量库。本文不新建 DEC/OPEN。
- **对应 Design 章节**：[Design 005](../design/005-报告与知识库设计.md) §1—9；采集输入与事件引用边界分别见 [Design 002](../design/002-信息获取主链路设计.md) 与 [Design 004](../design/004-事件与热度设计.md)。
- **实施前提**：FR-005-008/AC-005-009 的输入冻结、观点/引用与父链、程序分母、异常状态、任务和页面合同按 Design005 定标，排期时补该能力执行步骤后实施。真实 Codex 请求仍按总需求暂停，不为后置观点能力提前扩展当前核心 POC。
