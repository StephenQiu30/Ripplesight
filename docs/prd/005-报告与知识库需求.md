# 报告与知识库需求

本文定义该能力的产品要求，设计见 [Design005](../design/005-报告与知识库设计.md)，当前工作见 [BACKLOG](../../BACKLOG.md)。

## 1. 目标与范围

**目标**：研究者分别阅读日报、周报及其原帖引用，在现有 Obsidian vault 浏览、检索、提问并核对出处。

登录后的关键词信息、可支持的评论、个人日报和周报构成最低个人交付闭环；日报和周报可在获准来源就绪后独立交付，不等待事件、知识库、问答或消息推送。报告、知识库与问答分别按独立 FR/AC 验收，不作为 M1—M3 的技术前置。评论观点生成和质量验收仍归 M4，M1/M2 的评论采集、父链与阅读不依赖此能力通过。

**不包含**：把报告生成等同于 Obsidian 写入或推送送达；未通过 M3 时添加事件结论；未验收来源的数据。

## 2. 用户场景与状态

- 在设定时间查看前一自然日日报或上周周报，打开原帖引用并核对数字、覆盖缺口与模板降级标记。
- 在现有 vault 的 `HotKey/` 浏览分阶段导出的日报、事件、精选帖子、周报及主题笔记；重导出后核对用户区块和双链。
- 通过 Web 或 CLI 提问，在答案中打开逐句出处；资料不足时看到明确说明，并核对问答笔记写入状态。

身份、个人数据归属及会话遵守 [总需求 §2.1](001-热点舆情监控平台需求.md#21-toc-用户登录需求) 与 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-公开欢迎页登录与个人数据访问)。

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-005-001 | 报告时间配置 | 以 `monitor_topics.report_time`、`report_timezone`、`weekly_report_enabled` 为唯一设置事实源；报告偏好不升采集版本，写入时检查采集版本冲突，同一采集版本的并发偏好以最后成功提交生效。日报按该主题本地时间调度，周报仅在启用时调度；设置不决定采集就绪。 |
| FR-005-002 | 摘要、情感与主要观点 | 对相关帖子提供可追到正文的一句话摘要、正/中/负情感；评论按所属作品批量判断情感并整理已采样评论的主要观点，保留实际体验、支持、质疑和补充证据等具体问题。评论数不代替评论正文，不把不同作品的回复拼成同一线程；样本观点不外推为所有平台用户意见，证据与统计按 FR-005-008 核对。质量仍按现行 NFR 与 AC-005-001 人工抽检，已有分析代码与开发运行记录不等于质量验收 |
| FR-005-003 | 日报生成 | 默认 09:00 Asia/Shanghai 按前一自然日生成日报；先冻结输入，再由程序取数、模型可选润色；模型失败生成标注“模板版”的存档报告，送达另验 |
| FR-005-004 | 报告存档 | 日报、周报按主题和时间窗保存版本、覆盖说明与引用；Web 可查看。Obsidian 导出另验 |
| FR-005-005 | 周报生成 | 每周一 09:00 Asia/Shanghai 按上一 ISO 周（上周一 00:00 至本周一 00:00，即上周日 24:00）冻结输入并生成周报；程序计算的周内数字与该周已存档日报按同一口径的合计一致，保存引用与覆盖说明。渠道送达另验，推送暂缓不阻断 M4 验收 |
| FR-005-006 | Obsidian 知识库 | 只写现有 vault `~/Desktop/Markdown/Obsidian` 的 `HotKey/`：先日报；事件及被报告或事件引用的精选帖子在事件能力上线后导出；周报和主题笔记后续加入。笔记带 frontmatter，先有目标笔记再补双链，保留用户“我的笔记”区块 |
| FR-005-007 | 知识库问答 | Web 或 CLI 提问；用已采资料检索，由 Codex 回答并逐句标出处及资料时间范围；不足则明说不足，结果写入 `HotKey/问答/` |
| FR-005-008 | 评论观点证据与样本口径 | 每个输出观点须关联可核验的评论原文与引用，保留来源、所属作品、评论原生 ID、直接父节点/线程根、内容/分析版本和采集时间；展示采样排序、时间窗、一级/回复范围、实际条数及分页/条数截断。观点计数与占比由程序按冻结输入、去重和有效标注计算，保存分子、分母及排除规则；同条评论可含多个观点时说明非互斥，不默认合计为 100%。无法引用、父链无法核对、无评论或证据不足时明确标注不足/不可用，缺失不写作 0，也不生成无依据的确定观点或全网态度 |

### 最低个人报告闭环

| ID | 功能 | 要求 |
|---|---|---|
| FR-005-012 | 关键词与评论的个人日报、周报 | 用户登录后保存关键词/来源及报告偏好，阅读对应真实信息和来源支持的评论，再按个人主题生成、存档和读取日报、周报；公共刊物不能代替个人主题报告。关键词命中与模型相关性分开，未分析材料显示待分析清单，不计入已确认相关、情感或观点统计。模型不可用时模板版仍显示已知材料、原文引用、来源/评论缺口和未分析数量；没有评论能力与实际零评论分开。两种报告独立调度，事件、vault 或渠道故障不阻断生成。 |

个人交付先回答“我关注什么、实际取得什么、哪些仍未知、对应时段报告在哪”。当前必须补齐的是个人周报执行与独立调度、无模型时的待分析材料清单及范围说明；不以公共周刊、已有枚举或设置字段替代结果。已有报告入口只承诺读取已经定稿的报告，首页个人入口引导“设置关注/查看已有报告”，不能承诺尚未接通的周期生成。

| 用户目标 | 需求与设计 | 必需验收 | 完成条件边界 |
|---|---|---|---|
| 配置个人关注与报告偏好 | FR-005-001、012；Design005 §3.2.3、§4、§5.1 | AC-005-013，关键词版本另按 PRD002 | 当前时区固定 Asia/Shanghai；保存开关不等于周报执行已接通，设置不决定来源就绪 |
| 分别查看日报与周报 | FR-005-003—005、012；Design005 §3.2、§6 | AC-005-002—003、007、013 | 日报使用前一自然日，周报使用上一 ISO 周；两种任务、存档、引用和合法调度分别核对，不把日报改标签当周报 |
| 模型或来源不可用时仍看懂材料范围 | FR-005-008、012；Design005 §3.2.3、§5.1、§7 | AC-005-005、009、013 | 模板显示已知材料、待分析清单、实际采样和缺口；不生成无依据的观点，质量、连续稿、vault 与送达仍独立验收 |

这些最低交付与后续编选、问答、事件和渠道增强按用户价值区分；没有用户满意度、付费意愿及实际成本数据，不给出虚构 RICE/ICE 分数。具体次序只维护在 BACKLOG。

| FR-005-009 | 精选价值判断与离线校准 | “与主题相关”与“值得精选”分开；已相关不自动入精选。保存判断标准/提示词版本、来源质量依据、模型标识、输入内容版本、结果/理由和失败。用人工标注样本区分开发集与留出集，展示查准率、查全率、错例、来源/内容分层、调用次数和耗时；不以训练调参样本冒充留出效果。是否双评分、分值/门槛与调用预算先通过真实样本校准，不把未经校准的固定分值或判断次数当作质量保证。无有效判断时保留待分析，不伪造分数。 |

| FR-005-011 | 报告编选与信息增量 | 在既有日报/周报冻结合同内，记录入选/排除理由、同事实去重与后续进展、分类区块和代表出处；自动分类不改变程序数字与样本分母。保存正文、摘要、分析、事件修订及报告版本所用清单；迟到资料和后续修订不得静默改写已定稿版本，显式生成新版本或按定标规则进入后续刊期。自然日日报、ISO 周周报及 09:00 规则保持；月报不纳入本条。 |

### 报告内容与引用

| 报告 | 内容与时间依据 |
|---|---|
| 日报 | 概览与前日比较、重点内容 Top 10、风险与代表观点、各来源覆盖与缺口；M3 事件能力通过后可增加事件区块。按发布时间入窗；缺发布时间者按首次发现时间计并单列条数，注明“样本观察，不代表全网” |
| 周报 | 周内材料与覆盖说明、已有有效标注支持的趋势/上周比较和代表观点、下周关注；M3 事件能力通过后再加入 Top 事件、时间线及持续/平息。引用事件热度时附公式版本和计算口径，不能把不完整窗口当全量趋势；无有效分析时以待分析材料和缺口组成模板版，不编造变化结论 |

日报在精选帖子笔记不存在时只链接原帖；已存在笔记可附链接。精选帖子笔记成功导出后才补 Obsidian 双链，避免悬空引用。报告、知识库写入和渠道送达分别给出成功或失败状态。
