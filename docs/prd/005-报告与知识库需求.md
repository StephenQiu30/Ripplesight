# PRD005 报告与知识库需求

设计见 [Design005](../design/005-报告与知识库设计.md)。

## 1. 目标与范围

**目标**：登录用户按个人关注分别阅读日报、周报及其原帖/评论引用，知道取得了什么、哪些未分析、哪些来源有缺口；知识库启用后，在现有 Obsidian vault 浏览、检索、提问并核对出处。

**价值**：把分散材料整理成对应日/周的可追溯记录，减少反复查原帖、误读未知数字和覆盖缺口的成本；整理笔记的用户能保留个人编辑并找到出处。公共刊物、设置字段、单份日报导出或数据库扩展都不能单独回答这些问题。

关键词信息、评论、个人日报和周报构成最低个人闭环：所用来源已准入且有真实持久材料与读取证据后即可独立交付，不等待 M1 全部验收、事件、知识库、问答或推送。之后来源就绪变化不阻断按仍有权读取的材料生成；主题停用、归档、撤权和周报开关分别核验。评论观点生成和质量归 M4。

**不包含**：把报告生成等同于 Obsidian 写入或推送送达；M3 未通过时加入事件结论；未准入或无权读取的材料；新增商业采集、付费模型、向量库或第二报告/投递体系。

## 2. 用户场景

- 在设定时间查看前一自然日日报或上周周报，打开原帖引用并核对数字、覆盖缺口与模板降级标记。
- 在 vault 的 `HotKey/` 浏览分阶段导出的日报、事件、精选帖子、周报及主题笔记；重导出后核对用户区块和双链。
- 通过 Web 或 CLI 提问，在答案中打开逐句出处；资料不足时看到明确说明。

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-005-001 | 报告时间配置 | `monitor_topics.report_time`、`report_timezone`、`weekly_report_enabled` 为唯一设置事实源；时区固定 Asia/Shanghai。报告偏好不升采集版本，写入时检查版本冲突，同版本并发以最后成功提交为准。日报按报告时间调度，周报仅启用时调度；保存设置、来源就绪与执行结果分别显示。到期扫描不以来源 `readiness_status` 为前置，来源不足写入报告缺口 |
| FR-005-002 | 摘要、情感与主要观点 | 对相关帖子提供可追到正文的一句话摘要和正/中/负情感；评论按所属作品批量判断情感并整理已采样评论的主要观点（体验、支持、质疑、补充证据）。不把不同作品的回复拼成同一线程，样本观点不外推；质量按 AC-005-001 人工抽检 |
| FR-005-003 | 日报生成 | 默认 08:00 按前一自然日 `[00:00,次日00:00)` 生成：先冻结输入，再由程序取数、模型可选润色；模型关闭、不可用或失败时生成标注“模板版”的存档，保留待分析材料及引用。已确认相关、情感/观点与待分析分别计数 |
| FR-005-004 | 报告存档 | 日报、周报按主题和时间窗保存版本、覆盖说明与引用，Web 可查看 |
| FR-005-005 | 周报生成 | 每周一 08:00 按上一 ISO 周（上周一 00:00 至本周一 00:00）独立受理、冻结、生成并存档；同一种类/主题/窗口重复到期幂等；不等待日报 Job，不以公共刊物或改标签日报代替。保存所用日报版本与引用，缺失日报标缺口、不造空稿或 0；周内数字与已存档日报同口径合计一致 |
| FR-005-006 | Obsidian 知识库 | 只写 vault `~/Desktop/Markdown/Obsidian` 的 `HotKey/`：先日报；事件及被引用的精选帖子在事件能力上线后导出；周报和主题笔记随后。每类对象的准入、版本、写入/重导出与恢复独立核对。笔记带 frontmatter，先有目标笔记再补双链，保留“我的笔记”区块；写前复验权限，报告生成与导出失败分别显示 |
| FR-005-007 | 知识库问答 | Web 或 CLI 提问；只检索当前 owner 已存且仍获准的内容、报告及事件资料，返回可打开的出处与版本/时间范围；检索能力独立核对，不以扩展存在或文件已导出代替。模型获准后回答并逐句标出处，资料不足明说；回答存档与写入 `HotKey/问答/` 分别显示结果 |
| FR-005-008 | 评论观点证据与样本口径 | 评论进入冻结输入时保留来源/入口版本、所属作品、原生 ID、直接父/线程根、关系缺口、内容/分析版本和采集时间；报告携带采样排序、时间窗、一级/回复范围、实际条数和截断。每个观点关联可核验的评论原文；计数与占比由程序按冻结输入、去重和有效标注计算，保存分子、分母和排除规则；多观点非互斥时不默认合计 100%。证据不足时明示，缺失不写 0 |
| FR-005-009 | 精选价值判断与离线校准（M4） | “相关”与“值得精选”分开。保存标准/提示词版本、来源质量依据、模型标识、输入版本、结果/理由和失败。用开发集与留出集展示查准率、查全率、错例、分层、调用次数和耗时；评分次数、分值门槛与调用预算先经真实样本校准；无有效判断保留待分析 |
| FR-005-010 | 可追溯中文阅读辅助（M4） | 中文标题、事实摘要、推荐理由与分类/实体标签，每项事实可追到原文；按正文质量说明完整/摘要/截断。外语全文翻译为按需增强，显示原文/译文、版本、失败和覆盖范围并满足展示许可；翻译失败不阻断原文阅读，读页面时不即时调模型 |
| FR-005-011 | 报告编选与信息增量（M4） | 在冻结合同内记录入选/排除理由、同事实去重与后续进展、分类区块和代表出处；自动分类不改变程序数字与分母。迟到资料和后续修订不静默改写已定稿版本，须显式生成新版本或进入后续刊期 |
| FR-005-012 | 个人日报、周报闭环 | 登录后保存关键词/来源和报告偏好，阅读真实信息与评论，再按个人主题生成、存档和读取日报、周报。关键词命中与模型相关性分开；未分析材料以绑定冻结版本的清单展示来源/时间依据、引用和条数，不计入相关、情感或观点统计。模型不可用时模板版仍显示已知材料、来源/评论缺口和范围；评论各状态分开；互动指标逐字段保留未知与真实 0，部分可知时标“已知部分”。两种报告独立调度，来源、事件、vault 或渠道故障不阻断生成 |

FR-005-009—011 承接 [Design008](../design/008-完整业务设计.md)，不增加当前 M1 必需模型步骤。

### 4.1 报告内容与引用

| 报告 | 内容与时间依据 |
|---|---|
| 日报 | 概览与前日比较、重点内容 Top 10、风险与代表观点、各来源覆盖与缺口；M3 通过后可加事件区块。按发布时间入窗，缺发布时间者按首次发现时间计并单列，注明“样本观察，不代表全网” |
| 周报 | 周内材料与覆盖说明、有效标注支持的趋势/上周比较和代表观点、下周关注；M3 通过后加入 Top 事件、时间线及持续/平息。引用热度时附公式版本；无有效分析时以待分析材料和缺口组成模板版，不编造变化结论 |

日报在精选帖子笔记不存在时只链接原帖，笔记导出成功后才补双链。缺少部分日报时，周报仍按冻结的周内材料生成并标明缺稿日期，列出可比较与未核对的范围；这满足最低可读闭环，但不能宣称通过 AC-005-003，也不得为合计相等丢弃已知材料或补造数字。

## 6. 验收标准

**退出条件**：分析质量、日报、周报、vault 导出和问答各按自己的 AC 独立通过。

**独立发布门槛**：最低模板闭环按 AC-005-013 联验，不等待 M1 正式窗口或 M3/M4 质量。连续日报、完整周内合计和模型质量分别按 AC-005-001—003、007、009；对象导出按 AC-005-006、008 分对象核对；检索/问答按 AC-005-004 另行交付。未启用的能力保持明确不可用。

## 7. 依赖与决策

- **依赖**：最低模板闭环使用所用获准来源的真实持久材料；M4 正式 AC 使用 M1/M2 已验收资料；事件区块与事件/精选笔记待 M3；vault 可写、检索就绪和获准模型分别影响各自能力，不阻断获取或模板报告。
- **假设**：材料存在、标注有效、指标有值、父链完整、日报齐全、权限仍在、vault 可写、模型可用均须逐项核验；未知输入按 FR-005-008、012 展示，不由模型填补。
- **责任**：monitors 持个人偏好；content/evidence 提供材料与父链；reports 持冻结、程序数字与版本；analysis/ai 持分析结果及预算；knowledge 持导出、检索与问答。
- **决策**：沿用 DEC-001-109/111/112/114/212/219/221/224；问答不引入向量库。本文不新建 DEC/OPEN。采集输入与事件引用边界见 [Design002](../design/002-信息获取主链路设计.md)、[Design004](../design/004-事件与热度设计.md)。
