# Ripplesight 产品需求

## 产品目标

面向个人非商业的公开资讯阅读与关键词事件监控，帮助用户减少重复搜索，从相关帖子读到可追溯的评论、事件和报告。关键词由用户自行配置，AI 行业或 DeepSeek 只是示例。

当前 POC 先验证国内平台的一条完整路径：配置关键词和来源 → 任务受理 → 帖子 → 评论 → 再次运行 → 新增与去重 → 停止。平台搜索、详情、根评论、回复、增量、相关性与持续稳定性分别验收；一个平台的小样本不代表全平台可用。长期海外目标需要重新确认具体范围。

需求以用户决定和现行设计为依据。视觉与交互见 [DESIGN](../design/DESIGN.md)，实际优先级、完成状态和待验收项只在仓库根目录的 `BACKLOG.md`，技术约定在 `PROJECT.md`，开发检查在 `AGENTS.md`。

## 产品边界

- 仅供个人非商业使用；不增加企业多租户、付费套餐或原生客户端。
- 第三方服务费用为零，不购买 API、代理、打码或云端模型；计费不明的路径也不启用。相关性、情感、观点和写作使用本机 Codex app-server，限流时延后处理，不丢任务。
- 只读取公开或本人账号可见内容，不发帖、点赞、评论、私信，不访问私密账号或群组。登录平台用本人单账号低频采集，默认每小时一轮，评论有上限；验证码、登录失效或限流时停止，等待人工恢复，不换账号、代理或打码。
- X 不用官方 API；公开趋势和本人账号试点分别确认，源内容删除后同步清理本地数据。Reddit 只走官方 API 与 OAuth，申请获批前不发请求。
- 凭据只留本机配置或独立浏览器配置目录，不进入代码、日志、URL、导出、快照或数据库明文。个人资料按会话 owner 隔离，公开读取必须符合当前许可。
- 对外分发（RSS、只读 API、MCP/Agent Markdown、SEO/IndexNow、分享海报）、Instagram/Facebook/Threads、Flutter App、通用浏览器采集和飞书推送不属于当前实施范围。
- 产品不提供 Codex 重置公告统计与管理页面。
- 项目文档直接使用本仓库 Markdown/Git 和 Obsidian；不建设在线文档站、网页编辑、快照或发布平台。业务报告的 Obsidian 导出仍有效。
- 优先复用开源项目：MIT 代码可按许可改编并署名，GPL/AGPL 仅参考设计或独立运行，无许可证不用；商用前须重新核对非商业组件。

## 用户路径与功能

| 用户路径 | 必须得到的结果 |
|---|---|
| 首页、探索 → 事件或文章 → 原文 | 标题、摘要、来源、时间和许可一致；正文与证据版本可追溯 |
| 收藏 → 搜索、备注 → 所选导出 | 本机状态刷新后可恢复，只导出选中且仍可公开的信息 |
| 登录 → 来源 → 主题 → 运行 → 帖子与评论 | 配置保存、受理、采集、分析分别可辨，失败有原因和恢复方式 |
| 日报或榜单 → 固定刊期、模型与来源 | 同一修订或计算轮次可复核，不拼接历史版本冒充当前结果 |
| 必要的来源、任务和运营维护 | 仅授权角色可操作，版本冲突不覆盖输入，不在浏览时触发采集或外发 |

相关性、相似度、热度和新鲜度分别表达。当前相关性读取真实 bool、理由、错误或未知，不虚构连续分数或四档质量。按平台对象身份去重，不将不同作者、平台或评论因文字相似而合并。

评论保留原帖、根、父和回复目标；缺失父链明确显示上下文未知。来源发布时间、观察时间和接收时间分开，存储用 UTC，接口带时区，窗口左闭右开。新增、重复、0 条、失败和部分覆盖不同，抓取时间不冒充发布时间。

公共阅读免登录，登录弹窗关闭后可以继续阅读并恢复焦点。个人持久设置和结果需账号隔离，站点来源与个人来源分开；个人来源不因用户也是发布账号就自动公开。

## 实现取舍

- 设计中的全站统计、24 小时曲线、情感、关注、多类型收藏和告警已读仍是需求。服务尚未提供时显示真实空态或未知，分切片接入，不能用本页长度、最近五条或 48 小时值代替全量统计和 24 小时窗口。
- 本机备注是已确认交互；收藏每页 20 个 ID 回读，本机收藏最多 500 条、已读 ID 最多 5000 条，备注最多 2000 字。损坏或禁用存储不得误报成功；导出只含所选可读元信息和备注，不复制受限正文。
- URL 保存筛选、分页或页签；临时选择、草稿在组件内，本机收藏和阅读位置在 localStorage；业务配置和结果才入库。阅读位置绑定内容 ID 和修订，版本变化不跳到旧段落。
- 主题三个入口共用同一数据和编辑流程。主题列表每页 20 条；最近结果五条与 30 秒只读刷新不能当作采集次数、总量或后台运行证明。配置保存、任务受理、运行、部分完成和送达分别说明。
- 读取有界，列表和评论按页加载，回复独立分页，筛选变化清理旧 cursor；取消或忽略过期响应。性能、容量、恢复时限和准确率没有实测就不写达标，先测当前路径，再按实际瓶颈优化。
- 写操作由用户明确触发，沿用已有版本、幂等键和任务回执；超时结果未知先核对，不能盲目重发或静默覆盖草稿。公开许可撤回后按当前许可重读，撤权清理个人视图，刷新失败可保留并标明过期数据。
- 复用现有 jobs、版本、租约、outbox、许可与内容身份；不新增通用操作账本、第二套采集批次、搜索会话、每页面数据副本或默认云同步。新增结构必须有实际读写方。数据库以唯一的 `backend/sql/schema.sql` 为准，物理删表先核对消费者、外键、迁移与恢复。

## 验收标准

| 场景 | 最小成功结果与失败条件 |
|---|---|
| 公开阅读 | 搜索、专题、事件、文章和固定刊期能沿来源阅读；许可、修订和时间一致；缺期不换日期，503 不显示为 0 条 |
| 收藏与导出 | 刷新、备注、搜索、选择、取消和导出正常；撤回、损坏存储、超上限和空选择可解释，不导出不可读正文 |
| 登录与隔离 | 只显示服务器已配置的登录方式，安全站内回跳；另一账户替换 ID、cursor、导出或附件 URL 均不泄露私有信息 |
| 主题配置 | 来源准入、样本预览和显式保存有效；旧版本保存冲突保留草稿；预览和页面轮询不发起外部采集 |
| 运行与评论 | 受理和完成不同，job、跳过原因与原回执可追溯；两轮新增与去重分别核对，正文、根评论、回复和缺父链可读 |
| 调度与停止 | 到期、暂停、取消、预算耗尽、验证码和限流各有明确结果；停止后不发新请求，重启不密集补发积压；自然持续运行另验 |
| 分析、告警与报告 | 相关性、情感、错误和未知不混淆，观点有原文引用；热度窗口、规则与固定修订可追溯；触发、发送、送达分别验证，真实通知不由模拟样本证明 |
| 维护与恢复 | 来源、模型、站点和刊期维护有权限与版本检查；任务仅合法状态允许恢复或取消；数据库备份在独立库实际恢复后才算可恢复 |
| 页面体验 | 1440px 和 390px 检查正常、空、加载、错误、无权限及键盘路径；未知数值不造曲线，窄屏无整页横向溢出，减少动态效果可用 |

先交付一条真实阅读或监控闭环，再按已证实的缺口补服务。源码存在、固定样本、独立环境、真实平台、自然持续运行、用户体验和独立审查分别记录；单元测试或健康检查通过不能宣称整项能力可用。实际进度与证据摘要只更新 BACKLOG。
