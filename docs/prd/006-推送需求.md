# PRD006 推送需求

设计见 [Design006](../design/006-推送设计.md)。

## 1. 目标与范围

**目标**：渠道单独启用后，订阅者接收已存档报告；所有者核对实际送达与未知投递。

**用户问题**：报告生成后用户仍需回站查找，而发送任务成功不等于收件人收到。渠道启用后，订阅者应按时收到正确版本，所有者能定位未发送、明确失败和结果未知并人工处置。提高报告使用率是待验证假设，发送量不代表阅读或满意度。

**不包含**：信息获取或报告生成的验收；M6 突发告警；未重新排期的飞书实际发送。

## 2. 用户场景

- 报告存档且渠道启用后，订阅者分别接收 SMTP 或飞书报告；所有者按报告版本与接收方核对送达。
- 发送结果未知时，所有者查看待人工确认状态，确认前不自动重发。
- 接收方或授权改变时停用旧目标；更换收件身份建立新目标，历史投递仍指向原对象。模板版明确说明材料或分析缺口。

报告接收方是独立投递对象，无需产品账户。

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|
| BR-006-001 | 送达可追溯的日报和周报 | 已存档报告在渠道启用后分别验证送达；生成与送达分别验收 |
| BR-006-002 | 在预算内长期、安全地运行 | 不重复投递，不静默丢失结果 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-006-001 | 推送对象配置 | 渠道满足启用条件时，有权限的所有者配置目标名称、渠道、获准接收方和启用状态；新目标默认停用，凭据只引用私有配置，不在页面、日志或报告中展示。收件身份不可变，更换地址建立新目标；停用或撤权后不再接受新投递，执行与恢复前复验目标版本、权限和稿件可读范围。提供目标与投递状态、失败原因及 unknown 人工确认入口；保存配置或健康探针不等于投递成功 |
| FR-006-002 | 报告推送 | 飞书与 SMTP 分别启用、分别验收，飞书暂缓。已定稿的正常版或模板版日报在配置时间后 15 分钟内送达（默认 08:00 生成、08:15 前收到）；周报每周一 08:15 前送达。按报告版本与接收方去重，结果不确定时标待人工确认、不自动重发；报告生成、Obsidian 写入与来源故障不互相回滚 |

### 4.1 渠道边界

- 报告 SMTP 默认关闭，飞书暂缓；目标授权、SMTP 凭据与实际收件条件具备后才启用。
- 登录/绑定邮箱的验证码邮件属于身份流程，使用独立配置，不受报告推送开关影响，也不能作为报告渠道已核收的证据。
- 内容提醒与运行告警区分对象、开关、接收方和去重依据，不并入当前渠道范围。
- [Design008](../design/008-完整业务设计.md) 的付费调用未知结果恢复不适用于通知：同版本同接收方结果未知仍待人工确认；不因源码有重试逻辑宣称“恰好一次送达”。

### 4.2 个人邮件订阅与定时交付

- 收件地址由用户在账户中绑定并验证，保存在个人分区；环境变量只配置平台 SMTP 发信服务。普通用户无需运营令牌，在账户入口启用/关闭订阅，在主题入口选择发送哪些日周报。
- 发送前复核当前绑定邮箱、主题订阅和目标修订；更换邮箱使旧目标失效，不再向旧地址发送；其他用户不能读取、修改或使用该目标。未绑定、未验证或发信服务未就绪时显示实际原因。
- 新主题默认每 3600 秒采集、08:00 生成前一自然日日报，并启用周一 08:00 的上一 ISO 周周报；存量自定义值保持。08:00 是生成和投递触发时刻，目标 08:15 前收到，不承诺供应商精确入箱时间。
- 模型关闭时不等待分析水位，缺口进入模板；重启后依数据库事实补扫当前到期窗口，重复扫描或消费不重复发送，unknown 保持人工核实。

价值假设：个人关注持续产生可追溯的阅读成果。北极星候选为每周实际阅读报告的订阅用户数；当前先度量订阅后按时生成及 SMTP 接受率（SMTP 接受不等于收件或阅读）。低成本验证为主动订阅用户连续三天核收、周一核收和一周阅读反馈。

## 5. 非功能需求

适用共享 NFR：NFR-001-101、104—107；无专属 NFR。

## 6. 验收标准

**退出条件**：重新排期与启用后，SMTP 和飞书分别证明真实送达、幂等与未知投递人工确认。

逐目标保存固定报告版本、受理/尝试/供应商响应/最终状态与收件确认时间，检查撤销目标、撤权、同版本重放和执行中断。SMTP 接受、机器人 HTTP 200 和 Worker 成功均不替代真实收件；人工认定未收到后仍需显式新发送动作。

| ID | 前提 | 操作 | 期望 | 证据等级 |
|---|---|---|---|---|
| AC-006-001 | M4 日报或周报已定稿，相应渠道满足启用条件 | 各渠道分别发送正常版或模板版日报、周报，并模拟来源/模型故障与 vault 只读 | 分渠道核对接收方真实收到：连续 3 天日报均在设定时间后 15 分钟内、周报每周一 08:15 前；周报数字与上一 ISO 周已存档日报合计一致；故障时报告标缺口或模板版仍可发送，vault 只读不阻断；同版本同接收方幂等，结果未知待人工确认、不自动重发；飞书暂缓期间不真实发送 | 受控（故障隔离、时限、幂等与 unknown）；真实运行；产品（接收方核实） |

## 7. 依赖与决策

- **依赖**：已存档报告或所属领域的固定可读 subject 及渠道启用决定；目标管理与 unknown 人工闭环复用 `notification.send` 唯一账本。
- **决策**：沿用 DEC-001-110/212；OPEN-001-109 飞书恢复条件待定，不以 SMTP 通过或身份邮件收到解除其前提。
