# 推送需求

本文从 [总需求 001](001-热点舆情监控平台需求.md) 保留的 PRD 001 v3.0 基线按 M5 拆出，现与 [Design/Epic 006](../design/006-推送设计.md) 对齐；后置能力按本文、Design006 与 [BACKLOG](../../BACKLOG.md) 排期时补具体执行步骤。需求状态 `approved` 不表示产品验收通过。

## 1. 目标与范围

**目标**：订阅者在渠道单独启用后接收已存档报告；所有者核对实际送达与未知投递。

**不包含**：信息获取或报告生成的验收；M6 的突发告警；未经重新排期和启用条件的飞书实际发送。

## 2. 用户场景与状态

- 报告存档且渠道获准启用后，订阅者分别接收 SMTP 或飞书报告；所有者按报告版本与接收方核对送达。
- 发送结果未知时，所有者查看待人工确认状态，确认前不自动重发；飞书保持暂缓直到重新排期。

当前匿名 Demo 直接进入业务页面，不要求账户、登录或用户会话；业务 `owner_id`/`created_by` 仅维持历史业务 UUID 分区，按 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-当前-demo-的访问与数据分区) 解析唯一分区，不能作为用户身份。报告订阅接收方仍属于投递对象，无需产品账号；渠道授权与真实送达独立验收。未来 ToC 账户及多用户隔离见 [PRD001 §2.1 后置账户需求](001-热点舆情监控平台需求.md#21-未来-toc-用户登录需求后置)，当前 Demo 与受控证据不能证明多用户 AC 已通过。页面保留加载、空、业务错误与重试状态；以上场景按本里程碑 FR/AC 与总需求 NFR 核对。

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|

| BR-006-002 | 在预算内长期、安全地运行 | 投递在预算和安全约束内长期运行，不重复投递或静默丢失结果。 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-006-001 | 推送对象配置 | 推送对象在推送结果启用时配置。 |
| FR-006-002 | 报告推送 | 飞书群机器人与 SMTP 邮件分别启用、分别验收；飞书暂缓。已定稿的正常版或模板版日报按配置时间后 15 分钟内送达（默认 09:00 生成、09:15 前收到）；周报每周一 09:15 前送达获准接收方。按报告版本与接收方去重，发送结果不确定时标待人工确认，不自动重发；报告生成、Obsidian 写入与来源故障不互相回滚 |

### AIHOT 对照后的渠道边界

AIHOT 已有飞书精选内容通知及运维通知代码，但不构成 HotKey 的 SMTP 实现或任一真实送达证据。沿用本项目“报告生成、vault 写入、渠道投递分别验收”的合同；内容提醒与运行告警须区分对象、开关、接收方及去重依据，不提前并入当前渠道范围。实际发送前满足对应目标启用和授权条件。

[Design048](../design/048-AIHOT全量迁移架构与兼容设计.md) 中的付费调用未知结果恢复不能套用于通知：同报告版本同接收方的发送结果未知仍待人工确认，不自动重发；SMTP 和飞书分别测试失败、未知、限流、撤销目标及真实接收，不因源码有重试逻辑便宣称“恰好一次送达”。原 FR/AC 编号与时限不变。

## 6. 验收标准与退出条件

**证据门槛**：表中列出的等级须分别具备。受控测试验证状态机、边界与故障；真实运行验证实际来源、外部依赖和持久结果；产品验收按本条样本、连续窗口或用户核对口径作结论。低一级证据不能替代高一级；“代码已合入”本身不属于通过证据。

**退出条件**：重新排期与启用后，SMTP 和飞书分别证明真实送达、幂等与未知投递人工确认。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。

| ID | Given（前提） | When（操作） | Then（期望与退出条件） | 证据等级与用途（所列均必需） |
|---|---|---|---|---|
| AC-006-001 | M4 日报或周报已定稿，且相应渠道重新排期并满足启用条件。 | 各获准渠道分别发送正常版或模板版日报、周报，并模拟来源/Codex 故障与 vault 只读 | 飞书、SMTP 分渠道核对接收方真实收到：连续 3 个自然日的日报均在各自设定时间后 15 分钟内（默认 09:15 前）、周报每周一 09:15 前；周报数字与上一 ISO 周已存档日报按同一口径的合计一致。来源/Codex 故障时报告标缺口或模板版仍可发送，vault 只读不阻断已定稿报告投递；同版本同接收方幂等，结果未知时待人工确认、不自动重发。飞书暂缓期间不触发真实发送，送达不作为 M1/M4 条件 | 受控测试（故障隔离、时限、幂等与 unknown）；真实运行（获准渠道分别送达）；产品验收（接收方核实时间、数字及人工确认） |


## 7. 依赖、决策与未决项

- **依赖**：依赖已存档报告或所属领域的固定可读 subject 及渠道启用决定；SMTP 处理器、目标管理和 unknown 人工闭环已接 `notification.send` 原账本，真实 SMTP 核收与飞书启用/送达仍待验。
- **决策/未决项**：沿用总需求 DEC-001-110/210/212；OPEN-001-109：飞书恢复实施与启用条件仍待定。本文不新建 DEC/OPEN。
