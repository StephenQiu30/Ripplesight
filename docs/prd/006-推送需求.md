# 推送需求

本文定义该能力的产品要求，设计见 [Design006](../design/006-推送设计.md)，当前工作见 [BACKLOG](../../BACKLOG.md)。

## 1. 目标与范围

**目标**：订阅者在渠道单独启用后接收已存档报告；所有者核对实际送达与未知投递。

**用户问题与预期结果**：报告已经生成仍需要用户主动回站查找，发送任务成功也不等于收件人收到。渠道获准启用后，订阅者应在约定时间收到正确版本，所有者能定位未发送、明确失败和结果未知并人工处置。提高报告使用率是待验证的价值假设，不把发送量当作用户阅读或满意度证据。

**不包含**：信息获取或报告生成的验收；M6 的突发告警；未经重新排期和启用条件的飞书实际发送。

## 2. 用户场景与状态

- 报告存档且渠道获准启用后，订阅者分别接收 SMTP 或飞书报告；所有者按报告版本与接收方核对送达。
- 发送结果未知时，所有者查看待人工确认状态，确认前不自动重发；飞书保持暂缓直到重新排期。
- 接收方或授权改变时，所有者停用旧目标并核对未发送任务；更换收件身份建立新目标，历史投递仍指向原对象。收到的模板版明确说明材料或分析缺口，不能冒充正常分析稿。

身份、个人数据归属及会话遵守 [总需求 §2.1](001-热点舆情监控平台需求.md#21-toc-用户登录需求) 与 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-公开欢迎页登录与个人数据访问)。 报告接收方是独立投递对象，无需产品账户；渠道授权及真实送达另验。

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|
| BR-006-001 | 提供可追溯的日报和周报 | 已存档报告在渠道启用后分别验证送达；报告生成与渠道送达分别验收。 |
| BR-006-002 | 在预算内长期、安全地运行 | 投递在预算和安全约束内长期运行，不重复投递或静默丢失结果。 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-006-001 | 推送对象配置 | 在相应渠道满足启用条件时，由有权限的所有者配置目标名称、渠道、获准接收方和启用状态；新目标默认停用，凭据仅引用私有配置，不在页面、日志或报告中展示。收件身份不可变，更换地址建立新目标；停用或撤销授权后不再接受该目标的新投递，执行及恢复前复验当前目标版本、权限和稿件可读范围。提供目标与投递状态、失败原因及 unknown 人工确认入口，不能以保存配置或健康探针当作投递成功。 |
| FR-006-002 | 报告推送 | 飞书群机器人与 SMTP 邮件分别启用、分别验收；飞书暂缓。已定稿的正常版或模板版日报按配置时间后 15 分钟内送达（默认 09:00 生成、09:15 前收到）；周报每周一 09:15 前送达获准接收方。按报告版本与接收方去重，发送结果不确定时标待人工确认，不自动重发；报告生成、Obsidian 写入与来源故障不互相回滚 |

### 渠道边界

报告生成、vault写入与渠道投递分别验收；内容提醒与运行告警须区分对象、开关、接收方及去重依据，不提前并入当前渠道范围。实际发送前满足对应目标启用和授权条件。

报告 SMTP 默认关闭，飞书暂缓；目标授权、当前 SMTP 凭据与实际收件条件具备后才启用报告投递。登录/绑定邮箱的验证码邮件属于身份流程，使用独立身份 SMTP 配置及目的绑定，不受报告推送暂停开关阻断，也不作为报告渠道已核收的证据。

[Design048](../design/048-完整业务设计.md) 中的付费调用未知结果恢复不能套用于通知：同报告版本同接收方的发送结果未知仍待人工确认，不自动重发；SMTP 和飞书分别测试失败、未知、限流、撤销目标及真实接收，不因源码有重试逻辑便宣称“恰好一次送达”。原 FR/AC 编号与时限不变。

## 6. 验收标准与退出条件

**证据门槛**：按[总需求的证据等级](001-热点舆情监控平台需求.md#证据等级)逐项满足下表所列等级与用途。

**退出条件**：重新排期与启用后，SMTP 和飞书分别证明真实送达、幂等与未知投递人工确认。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。

AC-006-001 逐目标保存固定报告版本、受理/尝试/供应商响应/最终状态与收件方确认时间，检查撤销目标、撤权、同版本重放和执行中断；报告、vault 或其他目标失败不回滚已经独立定稿或送达的结果。SMTP 接受、机器人 HTTP 200 和 Worker 成功均不替代真实收件。发送可能已经发生后结果未知须保持待人工确认，人工认定未收到后仍需显式新发送动作，不由确认或重启触发自动重发。

| ID | Given（前提） | When（操作） | Then（期望与退出条件） | 证据等级与用途（所列均必需） |
|---|---|---|---|---|
| AC-006-001 | M4 日报或周报已定稿，且相应渠道重新排期并满足启用条件。 | 各获准渠道分别发送正常版或模板版日报、周报，并模拟来源/Codex 故障与 vault 只读 | 飞书、SMTP 分渠道核对接收方真实收到：连续 3 个自然日的日报均在各自设定时间后 15 分钟内（默认 09:15 前）、周报每周一 09:15 前；周报数字与上一 ISO 周已存档日报按同一口径的合计一致。来源/Codex 故障时报告标缺口或模板版仍可发送，vault 只读不阻断已定稿报告投递；同版本同接收方幂等，结果未知时待人工确认、不自动重发。飞书暂缓期间不触发真实发送，送达不作为 M1/M4 条件 | 受控测试（故障隔离、时限、幂等与 unknown）；真实运行（获准渠道分别送达）；产品验收（接收方核实时间、数字及人工确认） |

## 7. 依赖、决策与未决项

- **依赖**：依赖已存档报告或所属领域的固定可读 subject 及渠道启用决定；SMTP、目标管理和 unknown 人工闭环复用 `notification.send` 唯一账本；SMTP 核收与飞书启用/送达分别验收。
- **决策/未决项**：沿用总需求 DEC-001-110/212；OPEN-001-109：飞书恢复实施与启用条件仍待定。本文不新建 DEC/OPEN。
- **对应 Design 章节**：[Design 006](../design/006-推送设计.md) §1—9；共享任务和错误契约见 [总设计 001](../design/001-热点舆情监控平台总体设计.md) §5—6。
- **就绪与未知条件**：各渠道的接收方授权、凭据、时限核收和未知结果确认机制分别就绪；个人周报须先有真实定稿版本。飞书恢复决定与接收方尚未确定时保留暂缓，不以 SMTP 通过或身份邮件收到解除其前提。
