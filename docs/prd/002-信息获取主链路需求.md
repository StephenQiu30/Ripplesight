# PRD002 信息获取主链路需求

设计见 [Design002](../design/002-信息获取主链路设计.md)；共享原则、来源清单与时间口径见 [PRD001](001-热点舆情监控平台需求.md) §1、§5，本文不重复。

## 1. 目标与范围

**目标**：用户围绕关注方向和实体别名设置主题，核对四个关键词来源、六个公开热榜和模型相关性；从来源 × 能力 × 时间窗进入帖子、评论或快照，区分空榜、部分、失败与待分析。

**使用对象**：匿名读者直接阅读有出处的公开信息；登录用户用关键词减少无关材料并核对作品与评论；运营人员定位哪个来源、能力和窗口出现缺口。来源可访问、适配器存在、模型有结果与用户真正读到材料是不同条件，交付须连成可追溯流程。

**不包含**：本人 B 站及其他登录平台、跨平台事件与热度、观点摘要、Obsidian、推送、告警与导出增强。日报/周报由 [PRD005](005-报告与知识库需求.md) 负责。

### 1.1 最低交付：公开阅读与个人关注

- **公开阅读**：运营明确配置公共来源与发布分区，与个人分区隔离；优先无需凭据的官方 RSS/Atom、公开 JSON 和已准入热榜，不把 AIHOT 线上内容或其信源名单当默认数据源。访客可读获准的标题、来源摘要、原文链接和发布时间（或标明的发现时间）；获准正文或摘要在本站直接阅读。无独立摘要但有获准正文时显示正文预览，不要求模型补写；只有标题和链接的记录保留详情并说明缺口，不进入资讯流。模型停用或失败时原始信息仍可读，未分析不伪造为精选。
- **稳定获取**：须证明定时采集、持久化、去重、失败恢复与匿名页面组成真实链路；单次可达或解析成功只算预检。源站故障时保留仍有权展示的已存内容及观察时间。
- **个人关注**：取得关键词命中与评论父链；无评论能力、未授权、失败、采样截断和真实零评论分别显示，评论数不当评论正文，一类来源评论不可用不阻断其他阅读。

| 用户目标 | 需求与设计 | 必需验收 | 完成边界 |
|---|---|---|---|
| 不登录也能阅读最新获准信息 | FR-002-013—015；Design002 §3.7、§5.1 | AC-002-014—015 | 不依赖模型编选；许可与撤回在各公开出口一致；历史或时间未知材料明确标注；持续性按 72 小时口径另验 |
| 保存关键词后找到对应信息 | FR-002-001—003、008—010、012—014；Design002 §3、§5、§6 | AC-002-001—002、004、009—011、013—014 | 逐入口证明真实入库、规则版本和时间依据；通用 RSS/JSON 类型不证明某平台搜索已接入 |
| 核对来源、评论和缺口 | FR-002-004、007、011；Design002 §3.4、§5.1、§6.2 | AC-002-003、006、012；个人闭环 AC-005-013 | 根/直接父、采样与增量证据可查；无评论能力、未知总数、部分与真实 0 分别保留 |

来源卡片和结果详情分别说明入口/版本、支持的能力、是否需要源平台授权、规则执行方式、最近成功观察时间和本窗口结果。未知字段显示“未知/未记录”，真实 0 只来自本窗口证据；不用统一“实时”标签承诺全平台覆盖。

### 1.2 M1 短窗验证

目标：设置一个主题后能实际取得公开信息，阅读帖子、HN 评论和榜单命中，追溯原帖与时间，分辨相关结论、未分析和未采完；任务失败后能在预算内恢复，重复操作不产生重复结果或重复实耗。

- **阶段 A**：固定一个主题、`hackernews` 搜索和预检后冻结的一榜，在同一运行库和短窗完成下表适用操作。Web 至少打开一条真实 HN 帖及有父链的评论、一条真实热榜快照与主题命中；分析状态使用明确标记的受控输入，真实模型保持关闭。实际停止重启单 Worker 后重放不产生重复身份或预算实耗。不得换榜、借旧库样本或模拟帖子补齐。通过只说明该来源与一榜，不代表四来源六榜或真实模型效果。
- **阶段 B**：同一流程扩到四个关键词来源、HN 评论和六榜，至少一榜按合法间隔取得前后快照；每个入口各自留真实结果、失败或空的事实。

| 用户流程 | 要看到的结果 | 设计合同 |
|---|---|---|
| 配置主题和来源 | 在 `/monitors/new` 配置任一/全部/排除词并选择就绪来源；保存后读回规则、来源、版本和运行状态 | Design002 §3 |
| 手动与定时采集 | 主题页“立即运行”进入实际 Job 查看进度与停止原因；再核对一次合法到期；受理成功与采集成功分开 | Design002 §6 |
| 阅读帖子与评论 | 打开原帖，核对发布/发现时间与内容版本；至少一条 HN 帖含一级评论和回复，根与直接父可追溯，缺父正文保留占位；旧帖复采、采样截断和部分覆盖可见 | Design002 §3.4、§5 |
| 六榜与主题命中 | 逐榜取得真实快照，至少一榜有前后两次快照并核对排名变化；`/hotlists` 可看观察时间和榜位，命中项进入主题作品列表；空榜与失败分开 | Design002 §3.5、§5 |
| 相关性与分析状态 | 同一内容/主题/规则/提示词版本下显示相关/不相关及理由；无记录、待处理、失败、无效分别可见（当前为受控验证） | Design002 §3、§6 |
| 覆盖、预算与失败 | `/sources` 选来源、能力和时间窗，下钻 Job、内容或快照；请求、页数、入库/去重、预算和停止原因与数据库一致 | Design002 §6.2 |
| 暂停、重试与进程恢复 | Web 暂停主题、取消任务、重试失败任务；核对重复点击、预算不足与消息重投；实际停止/重启单 Worker 后核对身份、父链、预算和连续 offset（只重建 Consumer 不算重启） | Design001 §6.2、§6.3 |

**完成条件**：固定代码版本、运行库、来源/策略和主题版本，记录实际 `[T0,T1)`。核心操作经 Web 完成并与 API、数据库核对；CLI 只用于准备、执行控制和取证。采集阅读、受控分析、故障/预算/进程恢复分别给结论；真实模型暂停期间只能报告“采集阅读与受控分析通过，真实分析待验”。逐根远程评论分页、HN 十帖抽检、连续 72 小时、5 分钟中位延迟、95% 及时率和正式质量抽检后置，不为后置条件提前增加表或任务框架。

## 2. 用户场景

- 打开主题，查看四来源与六榜最新的帖子、评论、命中条目及相关理由；待处理或异常单列。
- 选定来源、能力和时间窗，核对到期、请求/页数、预算、入库/去重与未确认缺口，再进入原帖或快照。
- 比较同一来源前后热榜快照的排名变化；命中条目入库并判相关，未命中只留快照。
- 遇到失败、部分页、空榜或分析积压时追查停止原因，在预算和权限内手动重试。
- 用方向与实体别名表达关注范围，保存前预览已有样本的命中解释，并分辨原生查询、本地过滤及作品/评论能力。

身份与个人数据归属见 [PRD001 §3](001-热点舆情监控平台需求.md#3-账户与登录) 与 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-公开欢迎页登录与个人数据访问)。

| FR-002-009 | 规则预览与命中解释 | 保存前预览规范化规则及逐来源执行方式；样本预览只读当前 owner 已有、仍可读的入库内容，展示命中/排除理由、时间、规则版本和样本范围；不访问源站、不建任务、不调模型；无样本时显示证据不足 |

| FR-002-011 | 来源作品与评论能力矩阵 | 按入口及版本列明关键词发现、作品列表、正文、互动计数、一级评论、回复/父链、旧帖新增回复能力，并分开声明支持、配置就绪、真实窗口结果和产品验收；显示采样排序、上限、截止/失败与缺口。不支持、未授权、未尝试、失败、部分与可信真实 0 分别表达，未知总数留空；“本次已采 0 条”不等于“源站评论总数为 0”。当前 M1 仅 HN 承担评论验收，B 站归 M2 |
| FR-002-012 | 内容阅读与文本检索 | 在内容列表/详情上提供标题、摘要和获准正文的文本搜索，组合主题、来源、时间与分析状态筛选；显示命中位置、版本、时间、原文与缺口；只读已有资料，不抓源站或触发模型 |

| FR-002-014 | 历史材料与新内容区分 | 分开显示发布、首次发现和采集时间；“新内容”说明排序依据，历史导入和新来源首轮存量不因今天入库就称今天发布；无发布时间保留未知和发现时间标记 |

## 6. 验收标准

**退出条件**：四关键词来源与六榜共用连续 72 小时窗口，逐来源核对延迟，六榜逐榜 ≥90% 有效桶，相关性及时率 ≥95%，覆盖与缺口可查。证据等级按 [PRD001 §2.3](001-热点舆情监控平台需求.md#23-证据等级)，表中所列等级均必需。

| ID | 前提 | 操作 | 期望 | 证据等级 |
|---|---|---|---|---|
| AC-002-001 | HN 搜索/评论预设、主题规则与预算可用；PostgreSQL、Kafka、Worker 和调度运行 | 手动触发 HN 真实搜索，重启 Worker 并重放消息 | 帖子和带父链的评论入库；重启与重放后无重复；来源状态与真实证据一致 | 受控（重启与重放幂等）；真实运行（入库）；产品（状态一致） |
