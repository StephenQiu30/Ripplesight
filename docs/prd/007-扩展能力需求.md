# 扩展能力需求

本文定义该能力的产品要求，设计见 [Design007](../design/007-扩展能力设计.md)，当前工作见 [BACKLOG](../../BACKLOG.md)。

## 1. 目标与范围

**目标**：研究者按来源逐项准入指定账号和后续平台，并分别使用告警、报告或原始数据导出。

**不包含**：把 M1 热榜或其他来源的结果视作后续登录平台、账号追踪或告警的验收；未经凭据与月度上限确认的 X 真实请求。

## 2. 用户场景与状态

- 逐来源核对授权、能力与真实采集证据后，查看指定账号新帖或后续平台内容；公开热榜结果不算登录来源接入。
- 已启用 M5 渠道后核对负面内容或事件热度一小时阈值触发的告警与冷却时间。
- 从有权限的真实报告或原始数据导出 Markdown/PDF、CSV/JSON，核对引用、版本、字段脱敏与失败状态。

身份、个人数据归属及会话遵守 [总需求 §2.1](001-热点舆情监控平台需求.md#21-toc-用户登录需求) 与 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-公开欢迎页登录与个人数据访问)。

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|
| BR-007-001 | 持续获取关键词相关的帖子和评论 | 后续关键词来源或指定账号逐来源、逐能力准入，真实内容可追溯。 |
| BR-007-002 | 判断内容是否相关并逐步整理观点、事件 | 负面内容或事件热度达到阈值时提供后续告警能力。 |
| BR-007-003 | 提供可追溯的日报和周报 | 报告与原始数据按权限导出，版本、引用和字段可核对。 |
| BR-007-004 | 在预算内长期、安全地运行 | 新增来源、告警和导出在预算及授权范围内运行，失败与缺口可见。 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-007-001 | 导出增强 | 报告导出 Markdown/PDF；原始数据导出 CSV/JSON |
| FR-007-002 | 突发告警 | 负面内容或事件热度一小时内超阈值时推送，设置冷却时间，依赖 M5 渠道 |
| FR-007-003 | 指定账号追踪 | 本人获授权的指定作者新帖全部按已准入来源能力追踪与收录，不受主题关键词限制；来源逐个准入与验收，分页或权限造成的缺口明确标注 |
| FR-007-004 | 后续来源 | Reddit 仅考虑当前显式获批的官方 API 路径及 OAuth，商业用途另须平台书面批准；核对公共 Data API 迁移/退役与现行合同，不能把 OAuth、旧端点或 Devvit 当作外部全站监测已获准。X 仅走官方 API 且凭据与月度上限确认前不发真实请求；小红书、抖音、微信公众号及其他登录平台分别评估许可、授权、分页、限流、身份与失败状态后逐能力准入；微博、知乎登录仍须分别独立核对准入，不得随热榜验收视作已接入；获准后独立验证真实采集与持久结果 |
| FR-007-005 | 来源准入证据 | 每个候选来源分别保存固定软件/服务版本的软件许可与平台/数据授权证据，记录原文出处、取证时间、允许用途、账号/身份范围、费用额度、留存/传播限制和待确认项。能力矩阵分别列原生关键词搜索、作品正文、顶层评论正文、回复正文及父链、增量/旧帖新评论、公开热榜；评论数等指标与评论正文分开。逐能力记录已验证、受限、未验证/未知、不支持或停用及证据边界；没有证据时保持未知，不从营销覆盖数、公开网页、Cookie、登录成功或 HTTP 200 推定身份、费用权益、数据授权或完整评论覆盖。未决许可、身份与费用条件不记作准入通过，资料核查不替代逐能力真实采集验收 |

Reddit 官方依据（访问日：2026-10-04）：[Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy)要求显式 API 批准及商业用途书面批准；[应用登记](https://developers.reddit.com/app-registration)与[公共 API 迁移公告](https://www.reddit.com/r/redditdev/comments/1wubcvf/moving_data_api_apps_to_the_developer_platform/)说明 2026-10-31 停止新的公共 API 申请、2027-01-12 处理未登记/未参与迁移应用、2027-03 结束剩余公共访问。该公告不等于商业许可合同或所有 Devvit 能力一并关闭；具体适用路径须再次核对。[官方基础设施公告](https://www.reddit.com/r/modnews/comments/1wubgvt/continuing_our_infrastructure_updates_whats/)说明 RSS 于 2026-11-13 停止支持，不能作为长期免费基础来源。上述资料不证明 HotKey 已获准或已接通。

### 4.1 统一内容出口

| ID | 功能 | 要求 |
|---|---|---|
| FR-007-006 | 一致的可发布内容分发 | 后续提供获准内容的 RSS、只读 API 及 MCP/Agent Markdown；各出口读取同一内容/事件/报告版本与可发布范围，保留时间窗、出处、分析/精选状态、覆盖和分页边界。明确正文的站内展示与再分发许可；隐藏、撤回、授权变化同步作用于所有出口及缓存。私人主题、评论、账号材料、预算和凭据不进入公开投影。先定可发布投影、访问权限和许可，再决定具体出口、工具、分页/增量及限流；不手写第二份 OpenAPI，不在读取时采集或调用模型。 |

本条承接 [Design048](../design/048-完整业务设计.md)，公开站点/SEO、模型榜、外部摄入、月报、分享海报与 Codex 重置公告的新增要求见 [PRD046](046-完整业务需求.md)。工作区可访问性不等于内容允许公开传播，真实启用继续核对许可、预算与发布合同。

## 6. 验收标准与退出条件

**证据门槛**：按[总需求的证据等级](001-热点舆情监控平台需求.md#证据等级)逐项满足下表所列等级与用途。

**退出条件**：导出、告警、账号追踪和后续来源逐项独立验收。受控测试、真实运行与产品验收分层记录；一项结果不替代另一项。

| ID | Given（前提） | When（操作） | Then（期望与退出条件） | 证据等级与用途（所列均必需） |
|---|---|---|---|---|
| AC-007-001 | 对应能力具备真实输入、权限及逐来源准入条件。 | 评估负面内容或事件热度一小时阈值 | M6 告警按 FR-007-002 所述一小时阈值、冷却时间和 M5 渠道单独验收；不得用其他能力的证据代替 | 受控测试（阈值与冷却时间）；真实运行（已启用渠道的真实告警）；产品验收（告警单独核对） |
| AC-007-002 | 对应能力具备真实输入、权限及逐来源准入条件。 | 跟踪本人授权的指定账号 | 按获准来源能力核对该作者新帖不受关键词过滤且逐条收录，分页、限流或权限造成的未确认缺口须显示；不得用其他来源的证据代替 | 受控测试（授权、关键词绕过与来源边界）；真实运行（指定账号新帖与分页）；产品验收（各来源能力分别核对） |
| AC-007-003 | 对应能力具备真实输入、权限及逐来源准入条件。 | 逐来源、逐能力验收后续来源 | 各后续来源逐能力单独验收；不得用其他来源或公开热榜证据代替 | 受控测试（分页、限流和失败状态）；真实运行（每个获准来源的采集）；产品验收（逐来源逐能力独立结论） |
| AC-007-004 | 对应能力具备真实输入、权限及逐来源准入条件。 | 分别导出真实报告与有权限的原始数据 | 分别导出真实报告 Markdown/PDF 和有权限的原始数据 CSV/JSON，核对版本、引用、字段脱敏与导出失败状态；导出功能不作为报告生成或信息获取的完成条件 | 受控测试（导出失败与字段脱敏）；真实运行（真实报告及数据导出）；产品验收（版本、引用与权限核对） |
| AC-007-005 | 候选来源的固定版本、许可/条款、身份/授权与费用材料或未决清单可审阅；尚未准入的来源不发真实请求。 | 逐来源核对准入证据，并检查未知、不支持、权限失效和费用未定的受控状态 | 软件许可与平台/数据授权各有原文、版本、时间、用途和范围记录；原生搜索、作品、顶层评论、回复/父链、增量和热榜逐项给出证据与状态，指标不冒充正文。未验证能力保持未知，受限范围和失效身份可见；许可、授权、身份或费用未决时不记对应准入通过，不泛推为全平台、全历史或全部评论。资料核查完成不关闭 FR-007-004/AC-007-003，获准后的真实采集须另按逐来源实施合同验收 | 受控测试（未知、不支持、权限失效和费用未定不误记准入）；产品验收（逐来源原文、固定版本、身份/费用与逐能力证据审阅）；真实采集另按 AC-007-003 留证，不以本项替代 |

## 7. 依赖、决策与未决项

- **依赖**：导出依赖有权限的真实报告/数据；突发告警依赖 M3 事件与 M5 渠道；新增平台和指定账号逐来源准入。X 凭据与月度上限未定前禁止真实请求。
- **决策/未决项**：沿用总需求 DEC-001-106/108/115/221/225；OPEN-001-104：X 凭据和月度上限；OPEN-001-107：知乎登录实现路径；各来源真实分页仍见 OPEN-001-108。本文不新建 DEC/OPEN。
- **对应 Design 章节**：[Design 007](../design/007-扩展能力设计.md) §1—9；X 官方 API 的准入仍按总需求 OPEN-001-104。
- **实施前提**：FR-007-005/AC-007-005 的许可/授权记录、逐能力状态及证据关联按 Design007 定标，排期时补该能力执行步骤；准入研究材料不自动证明实施合同通过，不新增来源、付费请求或真实登录操作。

### 后续改进要求

资料比较、交互与检索性能、可用性/无障碍、容量与部署能力保留为后续改进需求；目标、样本与指标在实施前定标。
