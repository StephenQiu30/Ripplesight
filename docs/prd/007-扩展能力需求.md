# PRD007 扩展能力需求

设计见 [Design007](../design/007-扩展能力设计.md)，执行计划见 [PLAN007-01](../plan/007-01-公开信息免费采集执行计划.md)，平台与竞品调研见 [Research007](../research/007-七平台与竞品调研.md)。

## 1. 目标与范围

**目标**：按来源逐项准入公开作者和后续平台，围绕关键词或作者持续获取可追溯材料、去重与摘要，并分别使用告警、报告或原始数据导出。新增目标平台为 **X、Instagram、Facebook、Threads、抖音、Bilibili、微博**，全部保留在范围内，按实际能力逐项交付。

**用户问题**：用户在中外平台分别搜索关键词、检查作者更新，容易重复阅读，也分不清某平台是没有更新还是采集失败；关键词可能漏掉指定作者的新内容，负面或事件变化难以持续盯住，站内报告还需要可核对的文件。HotKey 应让用户在一个主题中选择确实可用的来源，读到有出处的新材料和摘要，并看到缺口与成本。平台图标、配置完成或接口返回成功都不等于平台支持完成。

**定位假设**：面向中文研究者的中外公开信息工作台——中文阅读便利、事实可追溯、覆盖与费用透明。平台整合、过滤和摘要已有竞品，未经访谈不称市场空白。

**路线**：供应商费用硬上限为零。以免费原生 RSS/Atom、已准入的本机 RSSHub 路由、允许读取的网页/JSON 列表为发现入口，必要正文由本机 Firecrawl 提取，SearXNG 只补充已准入的网页发现。免费订阅流上的主题过滤不等于平台原生搜索，搜索引擎索引不等于作者订阅；没有允许且可持续的免费入口时保留缺口，不自动切换收费接口。合同见 [Design007 §11](../design/007-扩展能力设计.md#11-免费本机采集顶层设计)。

**不包含**：把 M1 热榜或其他来源结果当作登录平台、账号追踪或告警的验收；未确认凭据与月上限的 X 真实请求；绕过验证、商业爬虫、全站/全历史/全量评论保证；代发帖、点赞、评论、私信、广告或读取私密账号/群组；默认下载图片/视频、识别画面或转写音频（视频首期只处理获准的标题、简介、文本、链接和互动观察）。高级导出不含报告生成，账号追踪不扩展本人 B 站试点的许可或评论层级。

### 1.1 使用对象与职责

核心用户：追踪行业/产品变化的研究者、订阅中外公开作者的内容研究者、需要轻量主题监控的个人用户。小团队为后续验证对象，不引入团队账户或协作权限。

| 职责 | 负责结果 |
|---|---|
| 产品范围与发布决策（需求提出者） | 确认七平台目标、试点用户、预算与阶段发布范围 |
| 平台准入与数据用途（待指定） | 核对官方/服务商条件、允许字段、留存、模型处理、展示和删除条件 |
| 实现与技术验收（待指定） | 复用现有领域合同，完成逐能力任务、读取、恢复与权限检查 |
| 体验与质量验收（待指定） | 核对真实命中、重复、摘要引用和更新缺口 |

### 1.2 目标与衡量

| 目标 | 指标与观察窗口 | 判断口径 |
|---|---|---|
| 用户知道实际能读什么 | 首次发布时七个平台均有逐能力、入口、授权、时间范围与阻断原因说明 | 只有通过相应 AC 的能力显示“已可用” |
| 形成真实跨平台阅读结果 | 首个试点至少两个不同平台的已准入能力完成主题配置→合法到期→持久读取→原帖核对 | 两个平台分别有非空真实材料和独立验收；不能用同平台两个入口或热榜替代 |
| 重复执行可靠且成本有界 | 每个发布能力完成固定版本的 72 小时观察及 §5 指标 | 不重复内容身份、不超预算、不隐藏失败 |
| 降低日常信息负担（假设） | 5—8 位候选用户两周试点，记录有效阅读天数、重复阅读量、每日整理时间与来源费用 | 每日整理时间中位下降 30% 为假设，首周基线与次周配对；无数据不宣称达成 |

试点另记录“已有来源之外的有效新材料比例”和每位活跃用户的平台/模型成本。不用互动总数或接入平台数代表用户价值。

## 2. 用户场景

- 逐来源核对授权、能力与真实采集证据后，查看指定账号新帖或后续平台内容。
- M5 渠道启用后，核对负面内容或事件热度一小时阈值触发的告警与冷却。
- 从有权限的报告或原始数据导出 Markdown/PDF、CSV/JSON，核对引用、版本、字段脱敏与失败状态。

**七平台用户流程**：

1. 在 `/sources` 查看七平台及逐能力状态，选择已准入入口；需要连接时说明目标对象、数据范围、费用和恢复方式。
2. 在主题配置中输入关键词/别名、排除词和来源，作者订阅走 FR-007-003 入口；保存后显示原生/本地执行方式、频率和限制。
3. 显式“立即运行”或启用定时策略，进入原 Job 查看进度；读取配置、刷新页面和 GET 查询不产生采集或费用。
4. 阅读已持久化材料，查看来源、时间、文本范围和重复提示；详情可打开原帖、展开重复来源、核对评论样本。
5. 阅读已有摘要或个人日周报，查看依据、未分析材料和缺口；来源受限时仍可阅读获准的已有材料。
6. 在来源健康页处理授权失效、预算不足、部分结果和暂停；人工恢复须形成有效连接状态。

状态文案示例：“Threads｜公共关键词｜待审核”“Instagram｜专业账号/标签｜范围受限”“B站｜本人试点｜未通过”。普通读者只看能力、更新和范围，端点、审核材料和错误映射留在管理详情。

| 用户任务 | 应有结果 | 必须避免的误判 |
|---|---|---|
| 追踪“模型发布”及别名，订阅 X/Threads/微博 | 各来源按实际支持条件返回材料，可分别核对命中、时间和缺口 | Threads 未获公共搜索权限时，自身帖子结果不算公共搜索成功 |
| 订阅公开研究者或 UP 主 | 先判断目标账号类型与读取范围，再执行获准作者列表能力 | 自有账号 OAuth、昵称解析或关键词命中不能替代第三方作者订阅 |
| 同一新闻被多平台转载 | 折叠重复候选但保留各原帖，新进展独立可读 | 文本相同不删除出处，事件不明时不强行归并 |
| 看抖音/B 站材料摘要 | 明确摘要输入为标题/简介、正文或获准字幕 | 未处理视听内容时不得称已总结视频 |
| 平台无更新、额度不足或查询受限 | 分开显示可信空、部分/未知、失败或暂停 | 所有空数组都写成“没有新内容” |

## 3. 业务需求

| ID | 业务需求 | 成功判断 |
|---|---|---|
| BR-007-001 | 持续获取关键词或指定作者的内容 | 后续来源或指定账号逐来源、逐能力准入，真实内容可追溯 |
| BR-007-002 | 突发变化告警 | 负面内容或事件热度达到阈值时提供告警 |
| BR-007-003 | 导出报告与原始数据 | 按权限导出，版本、引用和字段可核对 |
| BR-007-004 | 在预算内长期、安全地运行 | 新增来源、告警和导出在预算及授权范围内运行，失败与缺口可见 |

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-007-001 | 导出增强 | 有权限的用户选择固定报告版本导出 Markdown/PDF，或选择获准原始数据范围导出 CSV/JSON；受理时冻结对象/内容版本清单、时间窗、格式和渲染/字段版本，提供任务、失败原因和下载结果。文件保留出处、引用、程序数字、缺口与正文许可边界，未知不写 0；CSV 防公式注入，PDF 中文与分页可读。生成与下载分别复验权限和撤回；超限明确失败，不把截断产物当完整文件；失败不改源对象 |
| FR-007-002 | 突发告警 | 获准用户配置对象、最近一小时负面内容计数或事件热度变化的阈值、冷却时间及已通过 M5 的目标，规则默认关闭。事件热度类使用 M3 已验收的可比事件/热度输入，负面内容类使用 M4 已验收的情感输入。触发记录固定规则与输入版本、窗口、实际值、阈值和原因，去重与冷却持久化；缺失或不可比输入显示无法判定。发送前复验规则、目标与许可；中断/重放不重复触发；unknown 占用冷却并按 M5 人工确认 |
| FR-007-003 | 指定账号追踪 | 配置平台明确允许读取的公开作者或本人授权账号、稳定账号 ID、授权连接与来源节奏，显式启用后以作者列表能力采集获准窗口的新帖，全部收录且不受主题关键词限制；不能用昵称、别名或关键词搜索代替。须有该入口允许读取第三方作者的证据；只支持本人账号的接口不扩大范围。保存稳定作品 ID、版本、发现窗口、分页/水位和停止证据；只有可信尾段才推进水位；停用、撤权或换版后旧任务不得写入 |
| FR-007-004 | 后续来源 | 七平台按 Research007 的入口和逐能力条件评估，没有获准路径时保留目标与阻断项。Reddit 仅考虑当前显式获批的官方 API 及 OAuth，商业用途另须书面批准，核对公共 Data API 迁移/退役；OAuth、旧端点或 Devvit 不等于已获准。X 仅走官方 API，凭据与月上限确认前不发真实请求。小红书、公众号、知乎等分别评估后逐能力准入；热榜验收不等于平台接入 |
| FR-007-005 | 来源准入证据 | 每个候选来源分别保存固定软件/服务版本的软件许可与平台/数据授权证据：原文出处、取证时间、允许用途、身份范围、费用额度、留存/传播限制和待确认项。能力矩阵分列原生搜索、作品正文、顶层评论、回复及父链、增量/旧帖新评论、公开热榜；逐能力记录已验证、受限、未知、不支持或停用。无证据保持未知，不从营销覆盖、公开网页、Cookie、登录成功或 HTTP 200 推定权限；资料核查不替代真实采集验收 |
| FR-007-006 | 一致的可发布内容分发 | 获准内容的 RSS、只读 API 及 MCP/Agent Markdown 读取同一内容/事件/报告版本与可发布范围，保留时间窗、出处、分析/精选状态、覆盖和分页边界；撤回和授权变化同步作用于所有出口及缓存；私人主题、评论、账号材料、预算和凭据不进公开投影；不手写第二份 OpenAPI，读取时不采集或调模型。承接 Design008，相关新增要求见 [PRD008](008-完整业务需求.md) |
| FR-007-007 | 七平台能力目录 | 来源页列出七平台及各入口的关键词搜索、指定作者、新内容、正文、互动计数、评论/回复、热点和历史能力，分开呈现文档声明、连接准入、真实试点、产品可用与停止状态；显示目标账号类型、时间范围、排序/分页、审核/凭据、采样限制和最近成功时间。无证据为未知，明确拒绝为不支持；选源只允许已准入能力 |
| FR-007-008 | 主题与公开作者订阅 | 复用个人主题及账号追踪入口；作者订阅用稳定账号 ID。原生关键词、标签检索、本地过滤和热点匹配分开说明；不支持的条件明确拒绝或由用户选择可解释的本地过滤，不静默降级。OAuth 只解决调用身份，不证明任意作者可读 |
| FR-007-009 | 有界增量获取 | 手动与定时使用相同连接版本、权限、预算和任务路径，按准入节奏执行重叠回看、分页与水位。只有可信返回范围和尾段才能确认已处理；TOP 排序、受限历史、固定条数或敏感词空结果不证明完整。旧帖修订与新增评论用已准入的轮询能力单独验证；停用/撤权/换版后禁止旧执行写入 |
| FR-007-010 | 统一材料与阅读 | 保存并展示平台、稳定帖子/作者 ID、原文链接、作者、发布/发现/采集时间、文本范围、语言和可用指标；缺字段为未知。区分原帖、转发/引用、评论与回复，保留原生关系与缺口。视频摘要只基于实际获准文本，媒体默认以原文链接呈现 |
| FR-007-011 | 去重及重复报道组织 | 同平台同原生对象在多主题、分页重叠和消息重放中共用内容身份，保留各发现关系和真实修订。URL/文本相似只作重复候选提示；跨平台转载保留独立原帖；进入正式事件前显示“可能重复”，可展开来源、取消错误关联；跨平台事件复用 PRD004 |
| FR-007-012 | 有引用的中文摘要 | 区分来源摘要与模型摘要，固定输入版本、模型与提示词，每项关键事实可回原文；单帖与主题摘要分别标明材料范围、截止时间与缺口；评论观点不当已证实事实。仅在来源允许模型处理、模型已准入且预算成立时执行，禁止默认用于训练。无模型时展示原始材料并标未分析；撤回材料使依赖摘要失效 |
| FR-007-013 | 更新健康与成本控制 | 按平台/能力/窗口查看计划到期、最近尝试/成功、请求与页数、获准材料、入库/重复/修订、实际/未知费用和停止原因；以准入间隔判断过期，不宣传实时。供应商费用硬上限为零，仍限制本机调用、条目、正文长度、运行时间与并发；额度达 80% 提示，到硬上限拒绝新请求；未知计费不进入免费执行 |
| FR-007-014 | 数据用途与撤回联动 | 逐入口确认读取、保存、站内展示、模型处理、公开再分发和文件/API 输出范围；仅聚合或仅 ID 的供应商不能当正文来源。原文删除、转私密、撤权或许可收紧后，在约定期限内停止新采集并阻止受影响内容、摘要、报告、公开投影和缓存继续读取；须删除的执行删除并保留不含正文的必要审计。已下载文件无法远程召回，须事先限制输出并说明 |
| FR-007-015 | 平台支持与发布结论 | 每个平台的发布说明列出已通过能力、对象范围、时间窗/排序/采样、延迟和不支持项，并关联真实证据。至少一种公开关键词或公开作者订阅能力通过后才能称该平台“采集阅读支持”；七平台全部达标才关闭总目标，单平台阻断不影响其他平台交付 |
| FR-007-016 | 免费本机采集路线 | 仅使用零供应商费用的服务与允许读取的数据；RSSHub、Firecrawl、SearXNG 复用本机服务，不购买 API、转换服务、付费代理、验证码服务或云端模型，不以 fallback 引入费用。逐路由核对内嵌第三方调用、身份、缓存、自动重试和浏览器回退；无法约束费用或风控时不可执行。模型关闭时交付来源摘要/未分析材料和模板报告 |

作者扫描、告警评估与高级导出各自须有受理、持久结果、恢复和实际读取/送达；资料登记、配置/枚举、公开出口和既有账本只是基础。来源准入将公开阅读、官方 API 授权、平台登录和软件许可分开核对。

## 5. 非功能需求

适用共享 NFR：NFR-001-101、102、104—108、111。以下为七平台切片专属口径，不改变 M1/M2 指标。

| ID | 要求 | 衡量方法 |
|---|---|---|
| NFR-007-001 | 内容身份与费用正确 | 重叠分页、重复主题和消息重放不新增重复身份，未变正文不产生伪修订；请求/条目/积分/金额按实际计费口径对账；预占、确认、unknown 与余额可核对，超过硬上限的新外部请求为 0 |
| NFR-007-002 | 结果与摘要可核查 | 每条材料有原文引用、来源身份与时间依据；每份模型摘要保存固定输入与版本；抽检至少 30 份摘要、100 个事实，直接支持比例 ≥95%，严重编造为 0；样本不足或模型暂停时摘要质量未通过 |
| NFR-007-003 | 逐能力持续更新 | 拟标稳定的能力在同代码/连接/规则/库中观察至少连续 72 小时且至少 20 次合法到期；有效完成比例 ≥95%，预算耗尽、故障、未尝试与 partial 留在分母，可信空算完成；到期至持久可读中位 ≤10 分钟 |
| NFR-007-004 | 失效与删除有界 | 撤权/停用后零新请求、零旧任务写入；许可或删除事实进入后下一次读取即拒绝；须同步源站删除的入口在准入时冻结检查路径、间隔与期限，无法满足则不上线该存储/展示能力 |
| NFR-007-005 | 故障隔离与安全 | 单平台失败不阻塞其他平台；429 按退避与原 Job 恢复；风控按既有停用规则；跨账户读取、秘密暴露与未准入的外部/模型请求为 0；模型不执行材料中的指令 |

## 7. 发布阶段、依赖与决策

| 阶段 | 用户可获得的结果 | 发布门槛 |
|---|---|---|
| 免费路线定标 | 七平台的入口/能力/用途矩阵可审阅，明确本机路由、免费下游依赖和缺口 | AC-007-005/007/016 的设计条件明确；每个平台有允许范围或阻断清单；路由存在与服务健康不算平台通过 |
| 采集阅读试点 | 至少两个获准平台完成关键词/作者→材料→阅读→去重与覆盖 | AC-007-002/003、008—011/013/014 适用条件通过；稳定标签另需 NFR-007-003；不要求模型恢复 |
| 有依据的摘要 | 获准材料生成中文摘要，进入个人日/周报 | AC-007-012 与 PRD005 适用 AC；真实模型另获准 |
| 七平台逐项完成 | 七平台都有实际目标能力 | 每平台 AC-007-015；仅本人授权数据或聚合服务不能关闭公开检索/作者目标 |

- **依赖**：导出依赖有权限的报告/数据；告警按规则依赖 M3 事件/热度或 M4 情感，以及 M5 已验渠道；新增平台与指定账号逐来源准入。
- **决策**：沿用 DEC-001-106/115/221/225；OPEN-001-104（X 凭据与月上限）、OPEN-001-107（知乎入口与软件许可）、OPEN-001-108（分页）。付费官方 API、SocialData、Jina、Dajiala 与付费模型不进入本轮关键路径；免费组件不解除平台条款、数据用途或浏览器冻结边界。
- **待验证假设**：免费获准入口能带来有效增量；来源摘要与重复提示节省整理时间；抖音/B 站只有标题和简介仍有阅读价值；本机维护负担与缓存延迟可接受。
- **后续改进**：资料比较、交互与检索性能、可用性/无障碍、容量与部署能力，目标与指标在实施前定标。
