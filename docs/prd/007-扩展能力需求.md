# 扩展能力需求

本文定义该能力的产品要求，设计见 [Design007](../design/007-扩展能力设计.md)，详细执行及checklist见 [PLAN007](../plan/007-公开信息免费采集执行计划.md)，总体进度见 [BACKLOG](../../BACKLOG.md)。

本次补充日期：2026-10-04。需求提出者已确认新增范围为**公开信息采集、订阅、监控、去重和摘要**，并进一步确定**复用本机 Firecrawl、RSSHub 等组件，不使用付费实现，先完成顶层设计**。本文件承接 pm-market-research 的平台/竞品调研与 pm-execution 的 PRD 方法，沿用现有章节及需求编号；调研结论与来源见 §8，WP状态和checklist只在PLAN007维护，总体进度在BACKLOG维护，实际证据进入既有Acceptance。

## 1. 目标与范围

**目标**：研究者按来源逐项准入指定公开作者和后续平台，围绕关键词或作者持续获取可追溯材料、去重与摘要，并分别使用告警、报告或原始数据导出。新增目标平台为 **X、Instagram、Facebook、Threads、抖音、Bilibili、微博**，七个平台全部保留在产品范围中，按实际能力逐项交付。

**用户问题与预期结果**：关键词可能漏掉指定作者的新内容，用户也难以持续盯住负面或事件变化；站内报告还需要可核对的文件供个人整理。对应结果是获准作者的新帖按既定范围收录、有依据的阈值告警及固定版本文件，各自显示权限、缺口和失败。需求价值和使用频率仍是待验证假设，不以竞品覆盖宣传推定所有平台都可持续接入。

**不包含**：把 M1 热榜或其他来源的结果视作后续登录平台、账号追踪或告警的验收；未经凭据与月度上限确认的 X 真实请求；绕过验证、商业爬虫、全站/全历史/全量评论保证。高级导出不包含报告生成，指定账号追踪不扩展本人 B 站试点的许可、账号主体或评论层级。

新增切片不包含代发帖、点赞、评论/回复、私信、广告投放、读取私密账号或私有群组；不默认下载图片/视频、识别画面、转写音频。视频平台首期仅处理获准接口提供的标题、简介、文本、原文链接及可用互动观察；字幕和视听摘要须另行确认数据来源、处理权与费用。既有告警、导出等要求继续保留，独立于本次接入切片验收。

### 1.1 摘要、背景与价值

用户在中外平台分别搜索关键词、检查作者更新，容易重复阅读同一消息，也无法判断某个平台没有更新还是采集失败。HotKey 应让用户在一个主题中选择确实可用的来源，读到有出处的新材料和摘要，并看到更新缺口及成本。成功按真实内容和用户阅读结果判断，平台图标、配置完成与接口返回成功均不等于平台支持完成。

现有项目已有来源连接版本、任务、预算、内容身份、个人报告与公开发布许可基础。新增能力复用这些基础；微博/B站热榜不代表作品检索，本人 B站试点不代表面向所有用户的接入，X 受控适配器与官方编辑来源实现也不代表凭据、预算或真实业务已验收。代码与当前缺口以 BACKLOG 为准，不在本节保留另一份运行状态。

定位建议是**面向中文研究者的中外公开信息工作台**：围绕专业主题持续阅读，保留来源事实、差异和成本范围。平台整合、过滤和摘要已有竞品，差异化假设是中文阅读便利、事实可追溯和覆盖透明；没有访谈前不将其称为已验证市场空白。

本次路线以免费原生 RSS/Atom、已准入的本机 RSSHub 路由、允许读取的网页/JSON 列表作为发现入口，必要正文由本机 Firecrawl 提取；SearXNG 仅提供已准入的网页发现补充。免费订阅流上的主题过滤不等于平台原生关键词搜索，搜索引擎索引也不等于平台作者订阅。保留七平台需求，但不承诺免费组件一定能覆盖全部能力；不存在允许且可持续的免费入口时，明确保留缺口，不自动切换收费接口。

### 1.2 职责与使用对象

| 职责 | 责任人/安排 | 负责结果 |
|---|---|---|
| 产品范围与发布决策 | 需求提出者；具体执行分工待定 | 确认七平台目标、试点用户、预算与阶段发布范围 |
| 平台准入与数据用途 | 产品、来源负责人；待指定 | 核对官方/服务商条件、允许字段、留存、模型处理、展示和删除条件 |
| 实现与技术验收 | 后端/Web负责人；待指定 | 复用当前领域合同，完成逐能力任务、读取、恢复与权限检查 |
| 体验与质量验收 | 产品/试点用户；待指定 | 核对真实命中、重复、摘要引用和更新缺口 |

核心用户按任务划分：需要追踪行业/产品变化的研究者；需要订阅中外公开作者的内容研究者；需要轻量主题监控的个人用户。小团队属于后续验证对象，本次不引入团队账户、协作权限或企业销售承诺。

### 1.3 目标与衡量

以下是新增切片的目标和验收口径，不是当前实测结果。稳定性与安全要求见 §5—6；试点价值指标为待验证目标，不替代来源工程验收。

| 目标 | 指标与观察窗口 | 判断口径 |
|---|---|---|
| 用户知道实际能读什么 | 首次发布时，七个平台均有逐能力、入口、授权、时间范围与阻断原因说明 | 只有通过相应 AC 的能力可显示“已可用”；候选和受限平台不得冒充上线 |
| 形成真实跨平台阅读结果 | 首次采集阅读试点至少有两个不同平台的已准入能力，完成主题配置→合法到期→持久读取→原帖核对 | 两个平台分别有非空真实材料和独立验收；不能用两个同平台入口或热榜替代关键词能力 |
| 重复执行可靠且成本有界 | 每个发布能力完成固定版本的 72 小时观察及 §5 指标 | 不重复内容身份，不超预算，不隐藏失败；不将 API 返回范围外的内容计为全站召回 |
| 降低日常信息负担 | 5—8 位候选用户开展两周试点，记录有效阅读天数、重复阅读量、每日整理时间与来源费用 | 暂以每日整理时间中位下降 30% 为价值假设；用户各自首周基线与次周结果配对，未取得数据不宣称达成 |

试点还应记录“已有来源之外的有效新材料比例”和每位活跃用户的平台/模型成本，计算口径固定后再制定收费方案。不用互动总数或接入平台数代替用户价值。

## 2. 用户场景与状态

- 逐来源核对授权、能力与真实采集证据后，查看指定账号新帖或后续平台内容；公开热榜结果不算登录来源接入。
- 已启用 M5 渠道后核对负面内容或事件热度一小时阈值触发的告警与冷却时间。
- 从有权限的真实报告或原始数据导出 Markdown/PDF、CSV/JSON，核对引用、版本、字段脱敏与失败状态。

身份、个人数据归属及会话遵守 [总需求 §2.1](001-热点舆情监控平台需求.md#21-toc-用户登录需求) 与 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-公开欢迎页登录与个人数据访问)。

## 4. 功能需求

| ID | 功能 | 要求 |
|---|---|---|
| FR-007-001 | 导出增强 | 有权限的用户选择固定报告版本导出 Markdown/PDF，或选择获准原始数据范围导出 CSV/JSON；受理时冻结对象/内容版本清单、时间窗、格式及渲染/字段版本，提供任务、失败原因和下载结果。文件保留出处、引用、程序数字、缺口与正文许可边界，未知值不写成零；CSV 防公式注入，PDF 中文与分页可读。生成与下载分别复验当前权限和撤回状态，秘密或其他用户资料不得导出；超限明确失败，不把截断产物当完整文件。沿用 Design007 的有界规模，失败不改源报告或内容。已有公开 Markdown 出口、浏览器打印和格式枚举不代表本项四种文件均完成。 |
| FR-007-002 | 突发告警 | 获准用户配置对象、最近一小时负面内容计数或事件热度变化的阈值、冷却时间及已通过 M5 的接收目标，规则默认关闭；事件热度类规则使用 M3 已验收的有效、可比事件/热度输入，负面内容类规则使用 M4 已验收的有效情感输入，按 Design007 的周期评估所选规则。触发记录固定规则与输入版本、适用的事件版本、窗口、实际值、阈值与原因，去重与冷却持久化；缺失有效情感或不可比热度显示无法判定，不补零或以 M3 事件归并代替情感依据。发送前复验规则、目标与许可，执行中断/重放不重复触发；发送结果 unknown 占用冷却并按 M5 人工确认，不自动重发。配置表或通知通道存在不等于阈值评估及真实告警已经完成。 |
| FR-007-003 | 指定账号追踪 | 用户配置平台明确允许读取的公开作者或本人获授权账号、稳定平台账号 ID、授权连接及来源节奏，显式启用后以作者列表能力采集获准窗口的新帖，全部收录且不受主题关键词限制；不能以昵称、别名表或关键词搜索代替作者扫描。允许公开读取不要求目标作者一定为本人，但须有该入口允许读取第三方作者的证据；仅支持本人账号的接口不得扩大范围，MediaCrawler 仍仅本人 B站试点。保存稳定作品 ID、内容版本、发现窗口、分页/水位和停止证据，手动与合法到期执行共用去重及预算；仅可信尾段允许推进水位，部分、限流或权限缺口明确可见。停用、授权撤销或连接换版后禁止旧任务继续写入；阅读可回到真实原帖。新帖收录、已有作品修订及缺口分别核对，不承诺未准入的历史回补或平台全量覆盖。 |
| FR-007-004 | 后续来源 | 首批目标为 X、Instagram、Facebook、Threads、抖音、Bilibili、微博，均按 §8 的入口和逐能力条件评估；没有获准路径时保留目标与阻断项，不静默删去，也不宣布已支持。Reddit 仅考虑当前显式获批的官方 API 路径及 OAuth，商业用途另须平台书面批准；核对公共 Data API 迁移/退役与现行合同，不能把 OAuth、旧端点或 Devvit 当作外部全站监测已获准。X 仅走官方 API 且凭据与月度上限确认前不发真实请求；其他候选小红书、微信公众号、知乎等分别评估许可、授权、分页、限流、身份与失败状态后逐能力准入；热榜验收不等于平台接入，获准后独立验证真实采集与持久结果 |
| FR-007-005 | 来源准入证据 | 每个候选来源分别保存固定软件/服务版本的软件许可与平台/数据授权证据，记录原文出处、取证时间、允许用途、账号/身份范围、费用额度、留存/传播限制和待确认项。能力矩阵分别列原生关键词搜索、作品正文、顶层评论正文、回复正文及父链、增量/旧帖新评论、公开热榜；评论数等指标与评论正文分开。逐能力记录已验证、受限、未验证/未知、不支持或停用及证据边界；没有证据时保持未知，不从营销覆盖数、公开网页、Cookie、登录成功或 HTTP 200 推定身份、费用权益、数据授权或完整评论覆盖。未决许可、身份与费用条件不记作准入通过，资料核查不替代逐能力真实采集验收 |

Reddit 官方依据（访问日：2026-10-04）：[Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy)要求显式 API 批准及商业用途书面批准；[应用登记](https://developers.reddit.com/app-registration)与[公共 API 迁移公告](https://www.reddit.com/r/redditdev/comments/1wubcvf/moving_data_api_apps_to_the_developer_platform/)说明 2026-10-31 停止新的公共 API 申请、2027-01-12 处理未登记/未参与迁移应用、2027-03 结束剩余公共访问。该公告不等于商业许可合同或所有 Devvit 能力一并关闭；具体适用路径须再次核对。[官方基础设施公告](https://www.reddit.com/r/modnews/comments/1wubgvt/continuing_our_infrastructure_updates_whats/)说明 RSS 于 2026-11-13 停止支持，不能作为长期免费基础来源。上述资料不证明 HotKey 已获准或已接通。

作者扫描、告警评估与高级文件导出各自须有受理、持久结果、恢复和实际读取/送达；资料登记、配置/枚举、公共分发出口和既有账本只提供基础，不能替代完整功能。来源准入将公开阅读、官方 API 授权、平台账号登录及软件许可分开核对；官方接口只覆盖本人或授权账号时，不能描述为任意作者或全站检索。新内容增量和旧帖新增评论分别验证，评论完整性只在指定来源、权限、时间窗、取样范围与可信尾段内成立。

以下需求将新增七平台目标落到已有主链路，不替代 FR-007-003—005、PRD002 的内容/覆盖与 PRD005 的个人报告合同。

| ID | 功能 | 要求 |
|---|---|---|
| FR-007-007 | 七平台能力目录 | 来源页列出七平台及各入口的关键词搜索、指定作者、新内容、正文、互动计数、评论/回复、热点和历史能力；每项分开呈现平台文档声明、连接准入、真实试点、产品可用与停止状态。显示目标账号类型、查询时间范围、排序/分页、需要的审核/凭据、采样限制和最近成功时间；无证据为未知，已明确拒绝为不支持。选源时只允许当前已准入能力，候选能力保留原因与需求入口。 |

| FR-007-012 | 有引用的中文摘要 | 区分来源摘要与模型摘要，固定输入材料/版本、模型及提示词，每项关键事实可回原文；单帖和多材料主题摘要分别标明材料范围、截止时间与采样缺口。摘要不得把评论观点当已证实事实，也不推导源站未知互动或完整舆情。仅在该来源允许模型处理、当前模型已准入且预算成立时执行；禁止默认用于训练。没有模型时展示原始材料/来源摘要并标未分析，禁止用模板伪装模型结论；撤回材料使依赖摘要/报告失效或重新形成合法版本。 |
| FR-007-013 | 更新健康与成本控制 | 用户可按平台/能力/窗口查看计划到期、最近尝试/成功、请求与页数、获准材料、入库/重复/修订、实际费用/未知费用及停止原因。以准入间隔判断过期，不统一宣传实时。本次供应商费用硬上限为零；仍限制本机服务调用、条目、正文长度、运行时间与并发。来源额度达 80% 提示风险，到硬上限拒绝新请求；未知计费不得进入免费执行，不自动重购。显示自身主题结果与安全额度说明，其他账户规则、凭据和内容不可见。 |
| FR-007-014 | 数据用途与撤回联动 | 逐入口分别确认读取、保存、站内展示、模型推理处理、公开再分发和文件/API输出范围；仅可聚合或仅 ID 的供应商不得当正文来源。原文删除、转私密、来源撤权或许可收紧后，在约定期限内停止新采集并阻止受影响内容、摘要、报告、公开投影和缓存继续读取；必须删除的内容执行删除并保留不含正文/秘密的必要审计事实。已被用户下载的文件无法保证远程召回，需事先限制输出及说明范围。 |
| FR-007-015 | 平台支持与发布结论 | 每个平台的发布说明列出已通过能力、对象范围、时间窗/排序/采样、延迟和不支持项，并关联真实证据。能看热榜、授权本人数据、取得聚合计数或导入样本时只能使用对应名称；至少一种本次目标中的公开关键词或公开作者订阅能力通过后，才能称为该平台的采集阅读支持。全部七平台达成相应标准才能关闭七平台目标，单个平台阻断不阻止已就绪平台独立交付。 |
| FR-007-016 | 免费本机采集路线 | 本次新增入口仅使用明确零供应商费用的服务与允许读取的数据。RSSHub、Firecrawl、SearXNG 复用本机服务，不购买 API、第三方转换服务、付费代理、验证码服务或云端模型，不以默认 fallback 引入费用。逐路由核对内嵌第三方调用、身份、缓存、自动重试和浏览器回退；无法约束费用或风控行为时保持不可执行。本机 CPU/内存/存储和维护仍有资源成本。模型关闭时交付来源摘要/未分析材料及模板报告；本地模型只有在另行定标、获准且通过质量验收后才可标为中文模型摘要。 |

#### 用户流程与页面要求

1. 用户进入 `/sources` 查看七平台及逐能力状态，选择已准入入口；需连接时说明目标对象、数据范围、费用及恢复方式。
2. 在现有主题配置中输入关键词/别名、排除词和来源；作者订阅进入 FR-007-003 对应入口。保存后显示规则的原生/本地执行方式、频率和限制。
3. 用户明确执行“立即运行”或启用已约定的定时策略，进入原 Job 读取进度；配置读取、刷新页面和 GET 查询均不产生采集或付费。
4. 在主题列表阅读已持久化材料，查看来源、时间、文本范围和重复提示；详情可打开原帖、展开重复来源、核对评论样本。
5. 用户阅读已有摘要或个人日报/周报，查看依据、未分析材料及缺口；来源受限时仍可阅读当前获准的已有材料，失效材料按撤回规则处理。
6. 在来源健康页处理授权失效、预算不足、部分结果及暂停；人工恢复必须形成有效连接状态，不能靠反复刷新触发重试。

最小界面信息示例：“Threads｜公共关键词｜待审核”“Instagram｜专业账号/标签｜范围受限”“B站｜本人试点｜未通过”；这些是状态文案示例，不是当前运行事实。普通读者只看到能力、更新和范围，API端点、审核材料及技术错误映射留在管理与运行详情。

## 7. 依赖、决策与未决项

- **决策/未决项**：沿用总需求 DEC-001-106/115/221/225；OPEN-001-104：X 凭据和月度上限；OPEN-001-107：知乎目标能力的数据入口与软件许可选择；各来源真实分页仍见 OPEN-001-108。本文不新建 DEC/OPEN。

- **当前路线决定**：供应商调用费用硬上限为零，优先本机 RSSHub 及 Firecrawl；付费官方 API、SocialData、Jina、Dajiala 与付费模型不进入本轮关键路径。既有 X/模型暂停继续有效，免费组件不自动解除平台条款、数据用途或浏览器冻结边界。顶层合同与能力矩阵见 Design007 §11，先完成设计，再按 [PLAN007](../plan/007-公开信息免费采集执行计划.md) 进入逐入口实现。
- **实施前提**：FR-007-005/AC-007-005 的许可/授权记录、逐能力状态及证据关联按 Design007 定标，排期时补该能力执行步骤；准入研究材料不自动证明实施合同通过，不新增来源、付费请求或真实登录操作。
- **就绪与未知条件**：作者追踪先有明确目标及获准作者列表能力；告警按所选规则先有 M3 有效可比事件/热度或 M4 有效情感、阈值/冷却和 M5 已验渠道，缺少对应输入时保留无法判定；高级导出先有有权限的固定版本材料、字段及规模约定。数据用途、软件许可、商业授权、费用或身份未定则保留阻断/未知；不为补样本扩大本人 B 站或付费调用范围。用户对作者追踪、告警和文件整理的实际价值需后续观察验证，不预设市场份额、收益或工期。
