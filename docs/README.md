## 变更归属与证据

PRD 只写需求/AC，Design 只写现行合同，总体状态只写 BACKLOG，实际证据只写 Acceptance。本次按用户明确要求创建PLAN007并迁入详细执行计划，WP状态、步骤和checklist只在该PLAN维护。文档采用 `NNN-中文主题.md`，现有编号和FR/NFR/AC含义不变；编号不复用。已完成步骤、临时运行快照、视觉参考、调研和版本迁移过程从 `git log --all -- docs` 查阅；文件清理不取消需求或改变未通过结论。

整理按“用户问题→既有FR/NFR/AC→工作包/设计职责→checklist→真实证据”映射，先修冲突和缺失条件，不复制第二份路线或通过清空旧文档关闭需求。没有访谈重要性/满意度、触达人数与工时数据时，优先级采用需求对齐、源码缺口和依赖风险的定性判断；本轮执行顺序唯一维护在PLAN007，其他范围沿用BACKLOG。

PM整理沿用现行章节表达摘要、职责、问题背景、目标、使用对象、价值、方案/假设和发布门槛；不用新模板重排FR/AC。需求目标与软件基础、真实运行、产品通过分别判断，既有能力的增量实现和真实验收各有退出条件，未执行的外部、质量或持续窗口保持未通过。
