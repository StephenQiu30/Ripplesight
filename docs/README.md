# HotKey 产品总览

更新：2026-10-06。本目录只回答三件事：HotKey 做什么、每项能力现在到哪一步、怎样算做完。技术实现见 [PROJECT](../PROJECT.md)，工程规则见 [AGENTS](../AGENTS.md)，下一步做什么见 [BACKLOG](../BACKLOG.md)。

## 1. HotKey 是什么

**知微见澜 HotKey 是一个“公开资讯阅读站 + 个人舆情监控”工具，个人非商业使用。**

- **不登录**：在首页阅读有出处的公开资讯、事件和日报周报，查看 AI 模型榜。
- **登录后**：为关心的主题设置关键词，每小时获取各平台的热点内容与评论，每天看到 X 等社交媒体上最热的事件，看到情感走向，收到日报周报和负面告警。

**冻结**（代码保留，不再推进，需要时再立项）：对外分发（RSS/只读 API/MCP/Agent Markdown、SEO/IndexNow、分享海报）、Instagram/Facebook/Threads 接入、Flutter App、通用浏览器采集。

## 3. 状态的含义

| 状态 | 含义 |
|---|---|
| 可用 | 在本机真实数据上跑通，用户在页面上能看到结果 |
| 部分可用 | 代码已完成，但真实运行只跑通一部分，或还缺持续运行验证 |
| 未开始 | 没有可用代码 |
| 冻结 | 有代码但不推进，也不承诺可用 |

单元测试、受控测试或模拟数据通过，**不算**可用。

## 4. 文档规则

1. 每项能力一份文档，固定六节：要解决的问题、功能、做法、现状、验收标准、不做什么；最后附验收记录。
2. 同一条规则只写一处：跨能力规则在 [07](07-边界与决策.md)，技术约定在 PROJECT/AGENTS，进度与优先级只在 BACKLOG。
3. 用白话写，不引入新的编号体系；单份文档不超过约 6000 字符，写不下说明范围太大，需要拆分或删减。
4. 需求变化先改对应能力文档，再派开发任务；验收结果写进该文档末尾的「验收记录」：日期、做了什么、结果、怎么复核。
