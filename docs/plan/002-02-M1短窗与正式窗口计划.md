# PLAN002-02 M1 短窗与正式窗口计划

需求：[PRD002](../prd/002-信息获取主链路需求.md) §1.2、§6（AC-002-001—008）；设计：Design002、Design001 §6。BACKLOG 代号 BL-03（短窗）、BL-04（人工重试）、BL-05（HN 评论）、BL-06（正式窗口）。计划规则见 [docs/README §5](../README.md#5-plan-规则)。

## 1. 目标

**证明四个关键词来源和六个热榜能在同一个库里持续、及时、可追溯地运行。**

现状：短窗 A 未通过、B 未开始；人工重试与 HN 评论只有受控证据；正式窗口 `phase_verified=false`、`analysis_status=not_computable`。

## 3. 执行步骤

1. 核对实际代码 SHA、Schema 哈希、hotkey 库身份、账户/主题/规则、连接/策略、预算、任务/offset 及 UTC/Asia/Shanghai 窗口；保持单宿主 Worker，不恢复旧 POC 编排、换库重置预算或沿用旧连接就绪结论。
2. **短窗 A**：Web 配置→手动运行与一次合法到期→真实帖子/父链评论/榜单命中→原帖阅读→相关/不相关及 pending/failed/invalid→覆盖/预算下钻→同 operation 人工重试→单 Worker 停止重启/消息重放。模型关闭时只判断受控分析状态。
3. **短窗 B**：逐一验证 HN、Google News 搜索 RSS、SearXNG duckduckgo news、RSSHub 36Kr 快讯，以及微博/百度/知乎/B 站热门/36Kr/澎湃六榜；至少一榜有合法间隔前后快照。
4. **重试与评论**：重试保留原 Job/started_at/operation/失败记录，新周期仅下一次领取开始；十条高热帖逐帖记录根/回复/尾段/停止原因；重建 Consumer 不算 Worker 重启。
5. **正式窗口**：先核对统计与同版本备份恢复，再冻结 `[T0,T0+72h)`；六榜按实际间隔和首相位枚举桶；需分析身份固定 `(content_version,topic,rule,prompt)`，pending/failed/invalid/未入队留分母，尾部再观察 ≥60 分钟。
