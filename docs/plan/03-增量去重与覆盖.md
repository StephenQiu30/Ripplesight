# 03 增量去重与覆盖

依据：[03 增量去重与覆盖](../requirement/03-增量去重与覆盖.md)；设计：[03 增量去重与覆盖](../design/03-增量去重与覆盖.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-03-01 身份与版本

**Card**：作为个人监测用户，当想知道第二轮究竟增加或改变了什么时，我希望能够区分身份、正文变化和互动观察，以便相信新增与覆盖说明而不被重复数据误导。

**Conversation**：使用FR-03-01及BR-03-01确定范围。需要讨论的边界为“正文相似不能作为物理去重键”；需对齐的业务输入合同为02实际请求回执、08命名空间，不以当前实现是否方便决定取舍。

**Confirmation**：AC-03-01使用固定输入“轮1 A/a、A/b；轮2 A/a未变、A/b编辑、A/c两次、B/a一次”，执行“把相同评论从缺父状态补成回复并提交跨源同ID”，核对“仍是同一原生评论，跨命名空间对象不合并”，并验证对应反例。界面样本通过与真实业务验收分别记录。

### US-03-02 计量分母

**Card**：作为个人监测用户，当想知道第二轮究竟增加或改变了什么时，我希望能够核对每轮新增与重复分母，以便相信新增与覆盖说明而不被重复数据误导。

**Conversation**：使用FR-03-02及BR-03-01确定范围。需要讨论的边界为“任务累计、执行轮次和预算周期不得互相替代”；需对齐的业务输入合同为02实际请求回执、08命名空间，不以当前实现是否方便决定取舍。

**Confirmation**：AC-03-02使用固定输入“轮1 A/a、A/b；轮2 A/a未变、A/b编辑、A/c两次、B/a一次”，执行“复算轮2的上游返回与四类身份”，核对“返回5、唯一4、新增2/更新1/未变1/无法比较0，各有分母”，并验证对应反例。界面样本通过与真实业务验收分别记录。

### US-03-03 覆盖与缺口

**Card**：作为个人监测用户，当想知道第二轮究竟增加或改变了什么时，我希望能够看清覆盖与未采到的范围，以便相信新增与覆盖说明而不被重复数据误导。

**Conversation**：使用FR-03-03及BR-03-01确定范围。需要讨论的边界为“只有能证明查询终点时才标该有界查询完成，不能推导全平台完整”；需对齐的业务输入合同为02实际请求回执、08命名空间，不以当前实现是否方便决定取舍。

**Confirmation**：AC-03-03使用固定输入“轮1 A/a、A/b；轮2 A/a未变、A/b编辑、A/c两次、B/a一次”，执行“查询部分完成、源空结果与失败结果”，核对“空是已知零，失败未知；旧对象不据此删除，覆盖不称全平台完整”，并验证对应反例。界面样本通过与真实业务验收分别记录。

## 工程任务与完成判据

数据合同先行，数据提供方与消费入口可按同一合同独立开发；关联编号不是相互完成前置。任务按下表顺序推进；共享实现步骤只维护一次，各故事通过同序号FR/AC关联。任何发现的设计缺口先补同编号规格，再实施。

## 验收与发布门槛

本编号交付先满足FR-03和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
