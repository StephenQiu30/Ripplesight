# 58 个人来源

依据：[58 个人来源](../requirement/58-个人来源.md)；设计：[58 个人来源](../design/58-个人来源.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-58-01 管理本人来源

**Card**：作为个人监测用户，当补充本人RSS网页或JSON来源时，我希望能够维护本人来源草稿及版本，以便安全补充本人来源并理解其限制。

**Conversation**：使用FR-58-01及BR-58-01确定范围。需要讨论的边界为“本人是发布账号也不能使来源自动公开”；需对齐的业务输入合同为08能力、10权限、02受理，不以当前实现是否方便决定取舍。

**Confirmation**：AC-58-01：Given 本人合法RSS/网页/JSON草稿及旧配置版本；When 保存、修改并查看来源能力；Then 默认关闭且零采集；版本不改写旧任务；类型/ID/关键词限制明确，个人源不自动公开。同时验证该AC的反例及适用NFR，真实验收与固定样本分开。

### US-58-02 显式启用与执行

**Card**：作为个人监测用户，当补充本人RSS网页或JSON来源时，我希望能够显式启用并执行有界取数，以便安全补充本人来源并理解其限制。

**Conversation**：使用FR-58-02及BR-58-01确定范围。需要讨论的边界为“URL可保存不能证明能够关键词检索或完整抓取”；需对齐的业务输入合同为08能力、10权限、02受理，不以当前实现是否方便决定取舍。

**Confirmation**：AC-58-02：Given 合法源已启用且有预算；另设跳转私网/未准入来源反例；When 分别显式运行合法源及尝试越界来源；Then 合法运行有窗口/配置/覆盖回执；每跳准入拒绝越界，失败不装成功空集合。同时验证该AC的反例及适用NFR，真实验收与固定样本分开。
