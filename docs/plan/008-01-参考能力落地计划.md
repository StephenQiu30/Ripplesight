# PLAN008-01 参考能力落地计划

需求：[PRD008](../prd/008-完整业务需求.md)（另涉及 PRD002/004/005 的对应 FR）；设计：Design008 及所属领域 Design。计划规则见 [docs/README §5](../README.md#5-plan-规则)。

参考实现为开源项目 [AIHOT](https://github.com/KKKKhazix/AIHOT)（提交 `9acad0c`）。本计划只把其中已被验证有价值的能力，按 HotKey 自己的架构和合同实现为 HotKey 的能力：Python 领域划分、Job/Outbox/Kafka、按 owner 的发布分区、ALL 许可复验、零付费与真实模型暂停等边界都保持不变。不复制其代码结构、部署方式、品牌或数据；改编代码的署名按 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md) 随实现更新。

## 1. 目标

**让读者在 HotKey 上看到的精选、事件和日报更少重复、更有依据，并且在模型关闭时也能按规则出刊。**

现状：HotKey 已具备采集、预筛/评分/写作、事件、热度、刊物与公开出口的底座；以下能力在 HotKey 中尚未实现或仅有早期版本。

## 4. 风险与阻断

- 真实模型暂停期间，依赖模型判断的 WP-008-001/003/004 只能用受控输入和离线评测回执验证；WP-008-005、006、007 不依赖模型，可完整交付。
- WP-008-002 复用阶段/运行结果及事件 frame JSONB，不改变 DDL、不执行保留库升级；若后续工作包需要改结构，仍须按 Design001 §6.3 处理保留库。
- Codex 执行沙箱无法连接 PostgreSQL，集成测试由审查者按 CI 方式在独立 `hotkey_test_<suffix>` 库补跑并与基线对比，跳过用例不计完成。
- `editorial_rss.py` 等文件可能有并行改动，开工前先同步主干。
