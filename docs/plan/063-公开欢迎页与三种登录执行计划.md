# 公开欢迎页与三种登录执行计划

更新日期：2026-10-02。状态：in_progress。合同为 [Design001 §9.2](../design/001-热点舆情监控平台总体设计.md#92-公开欢迎页登录与个人数据访问) 与 [PRD001 §2.1](../prd/001-热点舆情监控平台需求.md#21-toc-用户登录需求当前恢复)。用户最新决定覆盖此前匿名 Demo；本轮先确认既有 main 推送，再实现公开欢迎页和登录工作区。

## 本轮步骤

1. 保留现有首页品牌与留白风格，拆分公开站点导航、登录组合和工作区导航；公开说明不读取个人业务统计。统一 BasicLayout、头尾、容器、字体、组件和窄屏行为。
2. 实现账号密码、GitHub App、邮箱验证码及同一数据库会话，登记 identity 包、模型、错误与 OpenAPI；私有 API 与页面深链接同时验证身份，SSR 携带请求级 Cookie，运营权限独立。
3. 更新完整 Schema、独立测试与 CI。先验证旧 Schema 不支持新身份，再用本机 PostgreSQL 独立临时库验证新 Schema、两账户及会话/CSRF/回调/验证码。测试库由执行者清理。
4. 保留现有 hotkey 数据；备份恢复、新空库导入与计数/关联校验后切换，旧库可回退。历史分区到账户由维护者显式指定，不能自动授给第一个注册者。GitHub/SMTP 未配置时保留可配置实现和明确不可用，不填开发密钥或伪造成功。
5. 完成 lint、类型、格式、测试、生产构建、OpenAPI 漂移和浏览器桌面/窄屏 welcome/login/匿名深链接检查。真实 OAuth 和实际邮件核收单独记录；未满足时不关闭对应产品 AC。

## 完成条件

匿名访问首页有可索引 SSR 内容及 canonical/OG，robots/sitemap 仅列公开说明；任意工作区页面含预取不能输出业务内容，安全回跳有效。真实密码会话、退出、失效和受控 GitHub/邮箱完整流程通过，业务 API 拒绝匿名且用户不跨分区。三种登录呈现明确可用/错误/重试状态，与系统共用设计规范；无手写请求，测试不进入业务源码。本机继续使用已有服务，数据恢复与真实集成缺口如实保留。
