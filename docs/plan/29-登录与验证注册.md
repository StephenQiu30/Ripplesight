# 29 登录与验证注册

依据：[29 登录与验证注册](../requirement/29-登录与验证注册.md)；设计：[29 登录与验证注册](../design/29-登录与验证注册.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-29-01 验证身份并安全进入

**Card**：作为访问个人功能的用户，当阅读中需要进入本人工作区时，我希望能够验证身份并安全返回原任务，以便安全进入本人工作且不打断公开阅读。

**Conversation**：使用FR-29-01及BR-29-01确定范围。需要讨论的边界为“未验证身份不能完成注册；外部returnTo和失效验证被拒绝”；需对齐的业务输入合同为10安全、00本机凭据，不以当前实现是否方便决定取舍。

**Confirmation**：AC-29-01使用固定输入“有效、过期、已使用challenge与站外returnTo；公开文章仍打开”，执行“验证注册、重复提交、退出或关闭弹窗”，核对“有效验证后建立可撤销会话；关闭登录仍能继续公开阅读。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

数据合同先行，数据提供方与消费入口可按同一合同独立开发；关联编号不是相互完成前置。任务按下表顺序推进；共享实现步骤只维护一次，各故事通过同序号FR/AC关联。任何发现的设计缺口先补同编号规格，再实施。

## 验收与发布门槛

本编号交付先满足FR-29和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
