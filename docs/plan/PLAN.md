# Ripplesight 当前执行计划

## 目标

优先跑通一个国内平台的“关键词 → 帖子 → 评论 → 再次运行 → 新增与去重 → 停止”路径。只处理当前路径已证实的缺口，不以补齐所有页面、平台、接口和表为前置。

范围与验收见 [PRD](../prd/PRD.md)，页面需求见 [Requirement](../requirement/REQUIREMENT.md)，界面约束见 [Design](../design/DESIGN.md)。实际完成状态、优先级和阻塞只在仓库根目录的 `BACKLOG.md`，本文件不维护第二份进度。

## 执行顺序

| 顺序 | 工作 | 交付门槛 |
|---|---|---|
| 1 | 确认一个平台、主题、来源能力、账号和样本窗口 | 真实请求已获授权，来源免费可用，凭据仅本机；候选平台不视为已接通 |
| 2 | 核对现有来源、主题与任务链，修补最小阻塞 | 保存、受理、运行、结果分别可辨；复用已有版本、任务与预算 |
| 3 | 验证帖子、根评论、回复与第二轮增量 | 来源和时间可追溯，新增与重复分别记录，不用旧数据代替本轮采集 |
| 4 | 验证暂停、风控停止、超时与恢复 | 结果未知先核对，重试沿用冻结配置，停止后不发新请求 |
| 5 | 复核相关性和实际页面体验 | 真实样本人工核对，1440px/390px 五状态和键盘可用；空态不当作采集成功 |
| 6 | 按实际需要验证自然持续运行、告警与报告 | 自然时间、覆盖、质量和送达分别验收，缺凭据或授权就记录阻塞 |

## 每次交付

一次只实施一个可独立验证和回滚的变化。先更新受影响的需求或设计，完成对应工程检查和独立审查，再在 BACKLOG 记清结果与未验证范围；提交、推送、真实外部请求按用户授权执行。

只有实际路径证明需要时才增加平台、聚合、索引或持久结构。本计划只包含当前实施范围，不维护已完成事项和历史方案。
