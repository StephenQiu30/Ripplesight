# Plan 003：空榜与失败时间桶

## 实施文件、事务与判定用例

修改 `backend/app/worker/scheduler.py`、`connections/services.py`、`jobs/coverage.py`、`content/{hotlist_execution,hotlist,models,schemas}.py`、`sources/adapters/rsshub_hotlist.py` 和 `backend/database/schema.sql`；API DTO 变化后从运行 OpenAPI 生成前端客户端。现有热榜调度尚未写 033 到期窗，因此 scheduler 须以 owner/source/计划到期点记录原桶，并在相同事务关联 Job/Outbox；`jobs/coverage.py` 用原桶、Job、快照和预算账本投影真实成功/缺口。停机恢复从当前连接最近状态/版本更新时间起补可证明处于当前启用时期的周期：旧到期点按历史策略记 missed/skipped，最新点正常受理；状态历史无法证明的更早时期不伪造。间隔变化不拼接旧周期，交给 009 重开验收窗。合法 Feed 解析成功且 entries=[]，在与 Job 页提交相同事务写 `hotlist_snapshots`、observed_at、operation_id，条目数为 0；解析/网络/准入失败只记原到期窗原因，不创建成功空快照。`hotlist_snapshots` 的 owner/source/operation 唯一约束覆盖重放，快照关联 033 的原到期窗。

本卡的 `SPEC-003-DATA-001/002` 和 `JOB-001` 在 `backend/tests/unit/test_hotlist.py` 与新增 `backend/tests/integration/test_hotlist_persistence.py` 验证：合法空→非空、HTTP错误→下桶成功、原桶安全重试、跨桶迟到结果、重复消息、写条目中途异常、停机后多桶补记和连接状态更新时间边界。断言原失败桶仍存在、空快照计成功观察但不等于完整历史、跨桶结果observed_at不回填伪造、事务失败不留半快照。`OBS-001` 查询由004/039消费，不在本卡新建页面。

运行B门禁；真实空榜无法遇到时保留受控证明与“无真实空样本”限制，不向来源制造故障。证据归M1 Acceptance Plan003。完成需每个上述用例有预期/实际和库断言，不能仅以pytest总数代替。

## 范围与需求

旧 `TASK-002-S02-T01` 已有六榜快照代码和受控证据，开发库曾记录 `hotlist_36kr` 真实失败桶；尚未证明空榜和失败在连续窗口中可独立复查。本卡只负责时间桶持久事实与状态口径，覆盖查询和六榜产品核对分别由 Plan 004/008 完成。源需求为 [PRD 002](../prd/002-信息获取主链路需求.md) 的 `FR-002-006/007`、`NFR-001-102/104/111`；贡献 `AC-002-005/006`。

先行033的到期窗口事实；来源策略沿用002。文件、事务和用例按本文实施合同执行；本卡不重复实现031调度、004查询或039页面。

## SPEC

| ID | 规格 |
|---|---|
| `SPEC-003-DATA-001` | 到期时间桶以来源、能力、固定窗口和 operation ID 唯一定位；成功但空 Feed 写带 `observed_at` 的空快照，缺失排名不伪造为零。 |
| `SPEC-003-DATA-002` | 上游、解析、准入、限流和中途失败不写成功空快照；失败、部分、未尝试及预算截断保留各自原因和缺口。 |
| `SPEC-003-JOB-001` | 同桶重试归原 operation ID；跨桶恢复不覆盖旧失败桶，重复扫描/重放不重复快照或洗掉缺口。 |
| `SPEC-003-OBS-001` | 六榜每个应到期桶可按来源核对到期、尝试、快照、失败和最终状态，分母不因后续成功而缩小。 |

## 验收与 Checklist

Given：准备成功非空、成功空 Feed、上游失败、解析失败、限流、部分页和跨桶恢复样本。When：运行同桶重试及下一桶采集。Then：每桶保留独立终态及原因，成功空榜有真实观察时间，失败不会冒充空榜，旧失败可回查。六榜各自 72 小时达标率仍由 Plan 009 判定。
