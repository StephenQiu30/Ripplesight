# 09 模型分析

依据：[09 模型分析](../requirement/09-模型分析.md)；设计：[09 模型分析](../design/09-模型分析.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-09-01 独立分析维度

**Card**：作为个人监测用户，当需要理解短评论和最相关的新内容时，我希望能够分别核对各分析维度，以便优先读最相关且有时效价值的证据。

**Conversation**：使用FR-09-01及BR-09-01确定范围。需要讨论的边界为“情感结果不得阻断或篡改已经有效的相关性”；需对齐的业务输入合同为03上下文、01规则、50本机模型，不以当前实现是否方便决定取舍。

**Confirmation**：AC-09-01使用固定输入“原帖Alpha发布，评论终于来了；缺父链样本；相关性有效但情感失败；字符串true与虚构引文”，执行“按冻结正文、父链、规则、提示和模型配置分析并排序”，核对“无效输出保留失败；信息不足保留不足；未分析不归中性。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

### US-09-02 上下文与证据

**Card**：作为个人监测用户，当需要理解短评论和最相关的新内容时，我希望能够结合父链读懂短评论及引用，以便优先读最相关且有时效价值的证据。

**Conversation**：使用FR-09-02及BR-09-01确定范围。需要讨论的边界为“不存在的父评论、引文和数值不得由模型补造”；需对齐的业务输入合同为03上下文、01规则、50本机模型，不以当前实现是否方便决定取舍。

**Confirmation**：AC-09-02使用固定输入“原帖Alpha发布，评论终于来了；缺父链样本；相关性有效但情感失败；字符串true与虚构引文”，执行“按冻结正文、父链、规则、提示和模型配置分析并排序”，核对“短回复不必复述关键词；引用必须存在于实际可读输入。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

### US-09-03 延后与重算

**Card**：作为个人监测用户，当需要理解短评论和最相关的新内容时，我希望能够在限流后继续分析或对新版本重算，以便优先读最相关且有时效价值的证据。

**Conversation**：使用FR-09-03及BR-09-01确定范围。需要讨论的边界为“未经请求不得自动扩词、扩大采集或调用新付费模型”；需对齐的业务输入合同为03上下文、01规则、50本机模型，不以当前实现是否方便决定取舍。

**Confirmation**：AC-09-03：Given 正文v1已有有效结果，本机模型随后限流；再编辑为v2并补齐父链，规则/模型配置亦可换版；When 限流时提交分析，再以新输入显式重算；Then 材料不丢，限流deferred；v1结果保留但不作v2当前结论，新输入摘要绑定正文/父链/规则/模型版本；相同新指纹重放幂等。同时验证该AC的反例及适用NFR，真实验收与固定样本分开。

### US-09-04 相关性与时效排序

**Card**：作为个人监测用户，当需要理解短评论和最相关的新内容时，我希望能够按相关性与时效读取材料，以便优先读最相关且有时效价值的证据。

**Conversation**：使用FR-09-04及BR-09-01确定范围。需要讨论的边界为“布尔相关性或高互动不能冒充最相关排序”；需对齐的业务输入合同为03上下文、01规则、50本机模型，不以当前实现是否方便决定取舍。

**Confirmation**：AC-09-04使用固定输入“原帖Alpha发布，评论终于来了；缺父链样本；相关性有效但情感失败；字符串true与虚构引文”，执行“用标注的相关/不相关、新/旧及未知时间材料评估排序”，核对“输出可复核顺序及解释，未知时刻不补成当前时间，按冻结排序指标验收”，并验证对应反例。界面样本通过与真实业务验收分别记录。

## 验收与发布门槛

本编号交付先满足FR-09和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
