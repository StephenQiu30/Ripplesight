# AIHOT 全量业务迁移执行计划

用户确认全部功能、不中途停在局部交付，并明确保留 Python/Next.js/Kafka。全量范围与退出条件由 PRD046 和 Design048 定义；Research049 的固定源码用作移植依据，全量路由/处理器/定时任务及遗漏核对见 [Research050](../research/050-AIHOT全量源码与迁移覆盖矩阵.md)。该计划统筹实现与接入，原 058/032/038/009/014 的实际失败和真实验收条件继续保留，不把来源、模型、72 小时或渠道证据降低。

## 1. 实现步骤

1. 固定上游 SHA 与 HotKey 基线，核对全部 sources/editorial/events/publication/reports/notify/leaderboard/monitor/admin/operations 以及 API、Worker、Web 入口；记录上游未实现/宣传差异和本地保留能力，补许可文本与复用记录。未出现用户可操作的功能不得写成完成。
2. 先完成共享材料读取与版本边界、事件读取 API、提示词/关系算法移植；同事实/进展/纠错/热度扩展既有事件域，先定 Schema 与事务再接 Writer/Worker。内容搜索、质量和历史时间用既有内容域承接；相关性和精选分开。
3. 并行移植分析全链路及评测、六类来源与外部摄入、模型榜与公告监控。调用、凭据、预算、任务和审计都接现有底座；真实请求受既有启用条件约束。
4. 接日周月刊编选、知识库和派生输入复核，再接统一公开投影、阅读归组、RSS/API/MCP/Markdown/SEO/海报/媒体和通知/运维。各领域 Handler、到期调度、状态查询和人工恢复同时接入，不能留下未注册 kind。
5. 随接口从运行时 OpenAPI 生成客户端，实现搜索/阅读/事件修订/热度、报告归档、榜单详情、公告日历、收藏、Agent与运营后台；实际浏览器核对完整流程及失败状态。共享导航和入口最后串行切换，保留已选首页。
6. 完成同一 Schema/代码版本的隔离数据库、Kafka、MinIO、Worker 故障恢复和全部适用静态/测试/构建检查；再逐来源、模型、渠道、持续窗口完成真实验收。重复旧路径在全部调用方切换和回归后撤下；未满足外部条件如实保留待验，不宣布完整交付。

## 2. 并行与共享文件

按领域分工，组件、模型、服务与测试可并行；`schema.sql`、`db/metadata.py`、`api/router.py`、API dependencies、Worker注册/调度、生成客户端、架构注册、PROJECT/AGENTS 与导航由统筹者串行汇合。新模块先登记 Design/PROJECT 职责，用失败测试证明未登记实现被拒绝，出现实际实现时再更新注册。

数据库仅在隔离新空库应用完整 Schema，业务库不改、不清空。保持外部调用开关和预算上限，不启动另一套服务环境、第二个任务队列或上游安装器；执行上游源码仅限已审计并移植到本项目后的测试。手工生成客户端、宽泛类型忽略、任意固定假数据或吞掉失败不能用作完成手段。

## 3. 收尾

动态进度只维护 BACKLOG；实际证据进入对应 Acceptance，新增特有能力证据按 PRD046 保存。任务不在某模块测试通过时结束，退出要求为全部范围实现、调用方接通、原功能回归和所需真实验收完整；存在凭据/费用/真实窗口限制时明确指出未通过项。此计划不承诺未经执行的工期或复用比例，不自动提交、推送或发布。
