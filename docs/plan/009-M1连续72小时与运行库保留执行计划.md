## 开窗前统计事实与必要实现

既有覆盖服务仍输出 `phase_verified=false`、`analysis_status=not_computable`，候选账本也不等于正式分析比例。本卡不能仅引用旧API或候选计数宣布可计算；须在开窗前核对各榜实际间隔/首个到期相位及配置版本，以及真实 Codex 可用/限流的受影响区间和样本。运行会话只证明配置，不证明模型可用，缺历史或冲突事实仍为unknown。

先复用既有只读 API、`jobs coverage-metrics` 与 `jobs analysis-need-ledger` 导出原始ID复算。必要改动限定既有 `backend/app/jobs/{coverage,metrics,schemas}.py`、`backend/app/analysis/{services,schemas}.py`、`backend/app/cli/jobs.py`；验证复用 `backend/tests/unit/test_freshness_metrics.py`、`test_job_freshness.py` 及 `backend/tests/integration/test_coverage_metrics.py`、`test_analysis_need_ledger.py`。补齐冻结事实的消费、排除依据及可计算结果，不提前建设持久汇总或通用统计系统。行为变化先保存失败用例，修改计算口径同步Design与 `metric_version`，旧 `collection-v1/v2`、`analysis-candidate-v1/v2/v3` 证据保留原口径。HTTP响应变化同批核对运行OpenAPI和生成客户端；事实不齐不输出达标率。

| ID | 规格 |
|---|---|
| `SPEC-009-OPS-001` | 核对上述前置与适用恢复证据。冻结代码SHA、库身份、Schema哈希、内部分区、主题/规则、十来源连接/策略/预算、模型/提示词版本和UTC/Asia/Shanghai的共同 `[T0,T1)`，`T1=T0+72小时`。 |
| `SPEC-009-OBS-001` | 四关键词来源与六榜在同库共同连续72小时逐来源记录到期、尝试、真实入口、原帖、入库、预算、延迟和未确认缺口；首周期真实帖子、HN十帖/旧帖新回复、重放和人工重试证据先核对。十帖不承诺每帖在窗内都有新回复。 |
| `SPEC-009-OBS-002` | 六榜按T0冻结的实际 `hotlist_interval_seconds` 与各榜首个到期相位枚举窗内due_at；成功快照或明确空榜至少 `ceil(0.9 × 应到期桶数)`，逐榜≥90%，其余桶保留失败/缺口。只有1800秒且T0对齐到期点时才是144桶/至少130桶。逐来源正常到期窗 `finished_at-due_at` 的中位延迟≤300秒（5分钟）；未受理/未结束留超时，精确中位数未知时保留null及下界，不删除超时样本。 |
| `SPEC-009-OBS-003` | 十来源真实命中均可查询Codex相关/不相关与理由。需分析集合按 `(content_version_id,topic_id,topic_rule_version,prompt_version)` 固定，含未入队的合格身份；旧内容加入新主题不沿用旧全局入库时间。正常时段成熟样本为分母，首次有效结论≤3600秒（60分钟）为分子，有效比例≥95%；待处理、失败、invalid和空值保留分母。未成熟单列，T1后至少再等60分钟，保留窗内样本；零分母ratio=null，无合格样本不判通过。 |

静默、来源限流延后和 Codex 限流分别记录reason、start/end、evidence_id及受影响样本，只排除相应指标；不按整个自然日删除样本，预算耗尽、普通失败和未调度不作无条件排除。热榜失败、暂停或缺失的应到期桶不因后续成功缩小分母。中位数下界已超过300秒时可判失败，否则缺事实保持不可判定；unknown和不足样本不能算通过。
