# 48 公开许可与发布管理

依据：[48 公开许可与发布管理](../requirement/48-公开许可与发布管理.md)；设计：[48 公开许可与发布管理](../design/48-公开许可与发布管理.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-48-01 控制公开许可与撤回

**Card**：作为发布管理员，当只公开获准内容并及时撤回时，我希望能够预览许可范围并显式发布或撤回，以便控制哪些内容何时允许公开。

**Conversation**：使用FR-48-01及BR-48-01确定范围。需要讨论的边界为“个人材料不能默认公开，历史链接和派生物不能绕过撤回”；需对齐的业务输入合同为10唯一许可、42定稿，不以当前实现是否方便决定取舍。

**Confirmation**：AC-48-01使用固定输入“来源允许摘要但某内容拒绝；未来才公开一条；已发内容撤回”，执行“预览白名单、发布、撤回并读取历史”，核对“来源策略与逐内容例外可解释；公开投影即时执行当前许可。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

## 验收与发布门槛

本编号交付先满足FR-48和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
