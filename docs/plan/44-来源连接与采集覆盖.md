# 44 来源连接与采集覆盖

依据：[44 来源连接与采集覆盖](../requirement/44-来源连接与采集覆盖.md)；设计：[44 来源连接与采集覆盖](../design/44-来源连接与采集覆盖.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-44-01 理解连接与覆盖

**Card**：作为个人监测用户，当想知道未取得资料是连接还是覆盖问题时，我希望能够看懂连接状态与查询覆盖，以便区分无结果与连接或覆盖问题。

**Conversation**：使用FR-44-01及BR-44-01确定范围。需要讨论的边界为“来源已配置或单一成功样本不得宣称全部能力可用”；需对齐的业务输入合同为08连接、03覆盖、02运行，不以当前实现是否方便决定取舍。

**Confirmation**：AC-44-01使用固定输入“已连接但评论不支持，另有登录过期及部分分页”，执行“看覆盖并显式恢复连接”，核对“配置、连接就绪与真实执行分别说明；搜索/评论/回复逐项可读。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

### US-44-02 恢复合法连接

**Card**：作为个人监测用户，当想知道未取得资料是连接还是覆盖问题时，我希望能够显式恢复合法连接，以便区分无结果与连接或覆盖问题。

**Conversation**：使用FR-44-02及BR-44-01确定范围。需要讨论的边界为“页面不存Cookie，不通过换账号或绕过风控恢复”；需对齐的业务输入合同为08连接、03覆盖、02运行，不以当前实现是否方便决定取舍。

**Confirmation**：AC-44-02使用固定输入“已连接但评论不支持，另有登录过期及部分分页”，执行“看覆盖并显式恢复连接”，核对“启用显式操作；账号/费用/风控边界未满足时拒绝新请求。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

## 工程任务与完成判据

数据合同先行，数据提供方与消费入口可按同一合同独立开发；关联编号不是相互完成前置。任务按下表顺序推进；共享实现步骤只维护一次，各故事通过同序号FR/AC关联。任何发现的设计缺口先补同编号规格，再实施。

|---|---|---|---|

## 验收与发布门槛

本编号交付先满足FR-44和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
