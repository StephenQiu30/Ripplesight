# 28 模型榜计算规则

依据：[28 模型榜计算规则](../requirement/28-模型榜计算规则.md)；设计：[28 模型榜计算规则](../design/28-模型榜计算规则.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-28-01 解释模型排名形成方式

**Card**：作为模型比较读者，当理解并复算名次时，我希望能够按发布方法复算排名，以便理解并复算名次。

**Conversation**：使用FR-28-01及BR-28-01确定范围。需要讨论的边界为“规则变更不能无版本地改写历史榜单”；需对齐的业务输入合同为26证据协议、23轮次，不以当前实现是否方便决定取舍。

**Confirmation**：AC-28-01固定v1的竞赛排名、缺证据排除与稳定同分次序，复算A/B同为第1、C排除；切v2不改写v1，并核对原始分数、方法和发布窗口。

数据合同先行，数据提供方与消费入口可按同一合同独立开发；关联编号不是相互完成前置。任务按下表顺序推进；共享实现步骤只维护一次，各故事通过同序号FR/AC关联。任何发现的设计缺口先补同编号规格，再实施。

## 验收与发布门槛

本编号交付先满足FR-28和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
