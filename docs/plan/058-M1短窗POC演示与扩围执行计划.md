# Plan 058：M1 短窗 POC 演示与扩围

## 范围与执行顺序

本卡承接 [Design 002](../design/002-信息获取主链路设计.md) → [PRD 002 §1](../prd/002-信息获取主链路需求.md#1-目标与范围) 的同库短窗演示，先交付 **A：最小可演示闭环**，再扩为 **B：完整 M1 短窗 Demo**。`depends_on` 消费各卡已证实的技术产物，不要求其连续窗口或真实 Codex 产品验收先通过。当前不启动 [Plan 009](009-M1连续72小时与运行库保留执行计划.md) 的 72 小时观察，也不把 A 当作四来源六榜已通过。

| 阶段 | 固定输入和用户可见结果 | 结论边界 |
|---|---|---|
| A 最小闭环 | 固定一个主题、已准入的 `hackernews` 搜索和六榜中预检后选定的一榜；冻结来源键、主题/连接版本、预算、代码 SHA、Schema 哈希、隔离库身份及短窗 `[T0,T1)`。Web 配置并手动运行 HN，观察一次合法到期调度；真实帖子与一条有父链的 HN 评论可读、可跳原帖；该榜取得真实快照和主题命中，能下钻内容。Web 显示受控相关/不相关及待处理/失败/无效状态，覆盖与预算和同库事实一致；失败重试及实际单 Worker 进程重启后不重复内容身份或预算实耗。 | 只核对这一个来源和一榜。真实 Codex 请求暂停时，分析只作受控状态与账本验证，不能写真实模型效果通过。 |
| B M1 扩围 | 保持同一演示方法，逐个核对 HN、Google News、SearXNG、36Kr 快讯及微博、百度、知乎、B站热门、36Kr、澎湃六榜；每个来源记录真实入口、原帖/快照、状态、预算与缺口，至少一榜在合法间隔下有前后快照及排名变化口径。 | A 的样本不能补齐其余九个入口；某来源真实为空、失败或未就绪如实记录，本阶段不能因此称完整 M1 Demo 通过。 |

日报、周报、Obsidian、知识库、投递、本人账号 B 站和 M3 事件均不在本卡。正式十来源 72 小时、时效比例、HN 十帖及真实模型质量仍由对应产品 Plan/AC 验收；不改原阈值。本卡默认不新增表、API、页面或通用测试框架。演示暴露的具体代码缺陷回所属 Plan 先做失败用例和修复，单独提交推送后以新 SHA 重新冻结本次演示。

## SPEC 与证据

| SPEC | 执行合同 |
|---|---|
| `SPEC-058-OPS-001` | 只用可丢弃的独立 PostgreSQL 库和既有 Redis/Kafka/MinIO、单宿主机 Worker、调度与 Web；检查现有配置和依赖，生成隔离演示所需的本地秘密且不记录其值。不得对保留库就地应用完整 `schema.sql`、删除数据卷或把旧库结果并入本次窗口。 |
| `SPEC-058-DATA-001` | 每阶段冻结 owner、主题/规则/来源连接/预算版本、代码 SHA、Schema 哈希、库身份、UTC 与 Asia/Shanghai 窗口、所选热榜和原始 Job/内容/评论/快照/标注/覆盖/预算 ID。Web 操作、运行 API 与同库 SQL 逐项对账；无真实数据时保留失败或空的原始事实。 |
| `SPEC-058-FLOW-001` | 演示从 Web 登录、配置、运行、阅读、覆盖下钻到暂停/重试；真实采集与持久化、受控分析状态、故障/预算与 Worker 重启分开给结论。重试同 operation ID 和已完成消息重投不制造第二个内容身份或预算实耗；只重建 Consumer 的测试不算实际 Worker 进程恢复。 |
| `SPEC-058-OBS-001` | 在 [Acceptance 002](../acceptance/002-信息获取主链路验收.md) 分别记 A/B 的通过、失败、未验证，附代码/库/时间与原始 ID、浏览器路径、故障和恢复；只在相应阶段全部必需结果有证据时记阶段通过。关闭真实模型时结论最多为“采集阅读 Demo 与受控分析通过，真实分析待验”。 |

- [x] `CHK-058-101` → OPS/DATA：记录隔离库、Schema/代码哈希、主题/来源/预算版本和热榜选择；Web 创建后从 API/库读回，不打印秘密。隔离窗口与未通过边界见 Acceptance 002 EV-002-052。
- [ ] `CHK-058-102` → FLOW：同库真实 HN 帖子、父链评论、一榜快照/命中及 Web 原帖跳转逐 ID 对账；合法空榜、失败和部分页不冒充成功。
- [ ] `CHK-058-103` → FLOW/OBS：受控分析四种状态、请求/页/入库/去重/预算/缺口、人工重试与真实 Worker 停止重启核对；记录 Kafka offset 与重放前后身份。
- [ ] `CHK-058-104` → OBS：A 的全部必需结果有据后才进入 B；逐来源扩围并保存每个真实入口的结论，不借其他库或时段补样本。

## 阶段门禁

- [ ] `CHK-058-G0-001`：核对历史 046 S03、上述 Plan 技术产物、适用的 Plan051 库/Schema恢复边界与当前运行依赖。
- [x] `CHK-058-G1-001`：冻结 A 阶段主题、来源/一榜、预算、短窗和受控模型边界；B 扩围前另冻结完整十来源清单。A 已冻结并留证，B 尚未开始，见 EV-002-052。
- [ ] `CHK-058-G2-001`：先保存空/失败/部分、预算拒绝、重复消息与 Worker 退出的失败/基线证据，发现代码问题回原 Plan 修复。
- [ ] `CHK-058-G3-001`：按 A → B 执行 Web 用户流程与真实来源短窗，默认只复用已交付代码。
- [ ] `CHK-058-G4-001`：每次代码修复运行适用后端、契约、前端、真实 PostgreSQL/Kafka/MinIO 与浏览器门禁；演示以最终固定 SHA 重跑。
- [ ] `CHK-058-G5-001`：Acceptance 002 保存 A/B 同库原始 ID、时间、截图或浏览器路径及失败/恢复，不拼接旧库。
- [ ] `CHK-058-G6-001`：分别判 A/B；本卡阶段结论不关闭 Plan009、真实 Codex 或父级 `AC-002-001—008` 的未满足条件。

来源不可用、风控或预算耗尽时停止相应请求并保留状态；不提高频次、不绕开来源准入或费用限制。每个实际缺陷修复为独立任务提交到 `main`，演示证据在固定提交核对后另行提交；工作树保持干净。
