# Plan 058：M1 短窗 POC 演示与扩围

## 范围与执行顺序

本卡承接 [Design 002](../design/002-信息获取主链路设计.md) → [PRD 002 §1](../prd/002-信息获取主链路需求.md#1-目标与范围) 的同库短窗演示，先交付 **A：最小可演示闭环**，再扩为 **B：完整 M1 短窗 Demo**。原 003/004/005/006/040/041 的短窗执行和实际缺陷修复汇入本卡，正式统计与产品验收归 [Plan009](009-M1连续72小时与运行库保留执行计划.md)；责任合并不关闭原未完成条件。032/038 消费已证实的技术产物，不要求其完整产品验收先通过。当前不启动 009 的 72 小时观察，也不把 A 当作四来源六榜已通过。

技术前置是 Design001/002 的主题与来源版本、预算、Job/Outbox/offset、热榜/评论/阅读和备份恢复合同，以及 Acceptance001/002 对应技术证据。执行前在实际运行库核对适用能力与结构；历史通过不代替当前就绪。

| 阶段 | 固定输入和用户可见结果 | 结论边界 |
|---|---|---|
| A 最小闭环 | 固定一个主题、已准入的 `hackernews` 搜索和六榜中预检后选定的一榜；冻结来源键、主题/连接版本、预算、代码 SHA、Schema 哈希、实际运行库身份及短窗 `[T0,T1)`。Web 配置并手动运行 HN，观察一次合法到期调度；真实帖子与一条有父链的 HN 评论可读、可跳原帖；该榜取得真实快照和主题命中，能下钻内容。Web 显示受控相关/不相关及待处理/失败/无效状态，覆盖与预算和同库事实一致；失败重试及实际单 Worker 进程重启后不重复内容身份或预算实耗。 | 只核对这一个来源和一榜。真实 Codex 请求暂停时，分析只作受控状态与账本验证，不能写真实模型效果通过。 |
| B M1 扩围 | 保持同一演示方法，逐个核对 HN、Google News、SearXNG、36Kr 快讯及微博、百度、知乎、B站热门、36Kr、澎湃六榜；每个来源记录真实入口、原帖/快照、状态、预算与缺口，至少一榜在合法间隔下有前后快照及排名变化口径。 | A 的样本不能补齐其余九个入口；某来源真实为空、失败或未就绪如实记录，本阶段不能因此称完整 M1 Demo 通过。 |

日报、周报、Obsidian、知识库、投递、本人账号 B 站和 M3 事件均不在本卡。正式十来源 72 小时、时效比例、HN 十帖及真实模型质量由 009 和原 PRD/AC 验收，不改阈值。本卡复用已有能力，不预建表、API、页面或通用测试框架。演示暴露的实际缺陷由本卡按 Design 明确最小变更、先复现再修复；重试周期和评论专项分别归 032/038。行为合同变化先同步 Design，按影响范围回归，以最终代码 SHA 重新冻结演示；提交推送依会话授权。

## SPEC 与证据

| SPEC | 执行合同 |
|---|---|
| `SPEC-058-OPS-001` | 按用户2026-10-01最新要求，全部操作复用已经启动的 PostgreSQL/Redis/Kafka/MinIO 与来源服务，不另外启动环境，也不恢复旧 `hotkeypoc058` 编排。先只读核对现有应用入口、库身份/结构、Kafka分组、来源版本、预算和模型开关；现有库不兼容时先确定运行库选择，完整 `schema.sql` 仍只应用于全新空库，不覆盖已有结构。单宿主机 Worker、调度与 Web 接入确认后的同一运行库，秘密仅保存在本地私有配置。不得删除用户库/卷、重置预算或以换库绕过耗尽窗口；旧库记录只作历史证据，不并入新短窗。 |
| `SPEC-058-DATA-001` | 每阶段冻结 owner、主题/规则/来源连接/预算版本、代码 SHA、Schema 哈希、库身份、UTC 与 Asia/Shanghai 窗口、所选热榜和原始 Job/内容/评论/快照/标注/覆盖/预算 ID。Web 操作、运行 API 与同库 SQL 逐项对账；无真实数据时保留失败或空的原始事实。 |
| `SPEC-058-FLOW-001` | 演示从匿名进入 Web、配置、运行、阅读、覆盖下钻到暂停/重试；真实采集与持久化、受控分析状态、故障/预算与 Worker 重启分开给结论。重试同 operation ID 和已完成消息重投不制造第二个内容身份或预算实耗；只重建 Consumer 的测试不算实际 Worker 进程恢复。 |
| `SPEC-058-OBS-001` | 在 [Acceptance 002](../acceptance/002-信息获取主链路验收.md) 分别记 A/B 的通过、失败、未验证，附代码/库/时间与原始 ID、浏览器路径、故障和恢复；只在相应阶段全部必需结果有证据时记阶段通过。关闭真实模型时结论最多为“采集阅读 Demo 与受控分析通过，真实分析待验”。 |

- [ ] `CHK-058-101` → OPS/DATA：在现有服务上重新记录实际运行库、Schema/代码哈希、主题/来源/预算版本和热榜选择；Web 创建后从 API/库读回，不打印秘密。EV-002-052的旧隔离库冻结曾完成，用户改变运行方式后不能作为当前环境已就绪的证据。
- [ ] `CHK-058-102` → FLOW：同库真实 HN 帖子、父链评论、一榜快照/命中及原帖跳转逐 ID 对账；核对合法空榜、失败桶和适用恢复，失败不造空榜，部分页不冒充完整覆盖。桌面与窄屏核对安全正文、父链、当前/历史标注和显式复采，读取不自动发起采集。
- [ ] `CHK-058-103` → FLOW/OBS：核对相关/不相关与待处理/失败/无效状态、有效结论理由、恢复诊断及旧失败不覆盖有效结论；旧库 3 条异常缺少原事实时保持待核对。请求/页/入库/去重/预算/缺口和同库账本一致，未知为 null、证实零才为 0；人工重试与实际单 Worker 停止重启后记录 Kafka offset、重放身份和预算，回滚/幂等按适用真实依赖验证。
- [ ] `CHK-058-104` → OBS：适用代码修复通过当前契约、后端、前端和真实依赖回归后，以固定 SHA 重跑；A 的全部必需结果有据后才进入 B，逐来源扩围并保存真实入口结论，不借其他库或时段补样本。Acceptance002 分别给出 A/B 通过、失败、未验证及原始 ID、时间和浏览器路径，不关闭父级 AC 的剩余条件。

历史准备与切换记录见 [Acceptance002](../acceptance/002-信息获取主链路验收.md) EV-002-052/056—058。旧库、连接、预算窗口、Kafka 分组和空闲 Worker 重启均只证明各自记录时的事实；Demo 去身份后的匿名配置验证归 Acceptance001，不补齐本卡采集、评论、人工重试和任务恢复。执行前重新冻结实际运行库、当前 Schema、来源版本及预算，不复用旧部署就绪结论，不借换库绕过既有耗尽窗口。101 及同主题联验仍需完成，A 未通过、B 未开始；旧 G0—G6 的适用条件已并入上面的同一组 Checklist，未通过状态未改变。

来源不可用、风控或预算耗尽时停止相应请求并保留状态；不提高频次、不绕开来源准入或费用限制。实际缺陷按可独立验证的范围交付，演示证据只引用最终固定版本。
