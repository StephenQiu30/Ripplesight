# 42 刊期生产档案

依据：[42 刊期生产档案](../requirement/42-刊期生产档案.md)；设计：[42 刊期生产档案](../design/42-刊期生产档案.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-42-01 管理刊期生产

**Card**：作为刊物编辑，当管理可发布的固定刊期时，我希望能够管理刊期草稿、定稿及发布，以便有序编选与发布真实刊期。

**Conversation**：使用FR-42-01及BR-42-01确定范围。需要讨论的边界为“尚未结束窗口不得冒充完整刊期，页面打开不启动生产”；需对齐的业务输入合同为43修订、48许可，不以当前实现是否方便决定取舍。

**Confirmation**：AC-42-01使用固定输入“同一周期窗口重复生成，另有失败刊期”，执行“创建草稿、定稿并显式发布”，核对“同刊期操作幂等，受理与成稿分别可核对。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

## 工程任务与完成判据

数据合同先行，数据提供方与消费入口可按同一合同独立开发；关联编号不是相互完成前置。任务按下表顺序推进；共享实现步骤只维护一次，各故事通过同序号FR/AC关联。任何发现的设计缺口先补同编号规格，再实施。

| 任务 | 具体交付物 | 输入合同与任务依赖 | 完成判据 |
|---|---|---|---|
| T-42-01 | 刊期身份及周期 | 43修订、48许可 | 形成刊期身份及周期的输入字段、身份/版本、输出与拒绝条件；覆盖FR-42各相关条款，独立审查无冲突 |
| T-42-02 | 草稿到定稿状态 | 前一任务产物与同编号设计 | 草稿到定稿状态能处理固定场景“同一周期窗口重复生成，另有失败刊期”，正常及BR-42-01反例均有可核对结果 |
| T-42-03 | 显式发布回执 | 前一任务产物与同编号设计 | 显式发布回执接入目标业务流程，能从操作返回稳定资源/回执；没有隐式扩权或外部动作 |
| T-42-04 | AC-42场景、质量检查及独立复核 | 本编号全部故事及适用NFR | 执行“创建草稿、定稿并显式发布”；核对“重复操作不生两期；失败不出公开归档；发布指向固定修订”；反例不产生错误业务效果，证据写BACKLOG |

## 验收与发布门槛

本编号交付先满足FR-42和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
