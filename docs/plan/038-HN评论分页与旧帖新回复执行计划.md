# Plan 038：HN 评论分页与旧帖新回复

## 当前 POC 切片与后置条件

本轮复用 HN 整树读取和缓存切页，验证原生父链、旧帖显式复采与新回复、采样上限、计量和消息重放。逐根来源分页、独立源游标/尾段与十帖真实产品验收后置，不能将本地分页或受控树描述为这些条件已通过。保留下述完整产品 SPEC/CHK，不修改父级 AC。

当前修复文件为 `backend/app/content/comments.py` 与 `backend/tests/{unit/test_comments_execution.py,integration/test_comment_runs_http.py,integration/test_comment_collection.py}`；复用现有 CoverageWindow/Job 状态，无新表、HTTP DTO、客户端或页面。页提交消费来源原有 `terminal_evidence`，不从 `COMPLETE/EMPTY` 合成证明；缺证、无界、时间窗/排序不符均为 `partial/unverified_terminal`。根/回复上限实际截断时为 `partial/budget_exhausted`，截断跨页保留；重复身份去重不制造截断。已有内容、父链、预算与 offset 保留。

- [x] `CHK-038-POC-001`：先复现错误完整覆盖，再在隔离 PostgreSQL 验证空树/整树无证、无界/错窗证据、根/回复截断、较早页截断、重复身份和来源契约的有效证据；核对持久覆盖与 Job 状态，并回归旧根新增回复和 Kafka 重投。专项 46 passed，证据见 Acceptance002 EV-002-051；仅记录受控技术结果，真实 HN 与操作系统 Worker 重启继续待验。

技术前置是 Design002 的 HN 搜索、版本化评论预设、到期/计量及父链持久化合同，032 的重试周期；保留库按 Design001/PROJECT 恢复合同执行，不依赖旧搜索或计量执行卡。FR-002-004、NFR-001-102/104/106，AC-002-001/003/004 仍适用。真实样本需 10 条可打开高热帖，不以同库外旧线程抵数。

版本化评论预设、显式复采 API、手动 scope、旧根新回复受控树、Kafka 重投及原生父链的历史技术证据见 Acceptance002 EV-002-024—028，现行合同见 Design002 §3.4。同进程重建 Consumer 不算操作系统 Worker 重启；受控树和缓存切页不算真实逐根分页/尾段或十帖产品验收，CHK-038-001—005 的剩余条件不关闭。
