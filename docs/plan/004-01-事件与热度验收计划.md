# PLAN004-01 事件与热度验收计划

需求：[PRD004](../prd/004-事件与热度需求.md)；设计：Design004、Design008 事实关系。BACKLOG 代号 BL-07。计划规则见 [docs/README §5](../README.md#5-plan-规则)。

## 1. 目标

**让用户少看重复报道，同时不漏掉同一件事的新进展，并看懂热度从哪来。**

现状：稳定身份与 R1—R5 受控证据已有，事件扫描默认关闭；真实三平台、模型确认与产品 AC 未执行。事件关系判定规则的改进见 PLAN008-01 WP-008-003。

## 2. 可度量结果

| # | 结果 | 基线 | 目标值 | 验收依据 | 反作弊/反向指标 |
|---|---|---|---|---|---|
| R1 | 人工判定的固定样本集（同事实、同实体不同发布、近似无关、后续进展、背景、综合稿） | 0 | ≥60 条，6 类各 ≥10 | AC-004-002、006 | 样本冻结后不再按结果调整 |
| R2 | 样本上“同实体不同发布被误并”和“综合稿与单事件被合并”的次数 | 未测 | 0 | AC-004-002、006 | 只统计确认事件，候选不计 |
| R3 | 真实三平台同一事件归并、人工合并/拆分与升温标注 | 0 | ≥1 个事件全链可核对 | AC-004-001 | 热榜快照不替代 |
| R4 | 热度分来源贡献可复算、未知为 null、不可比窗口不标降温 | 受控通过 | 真实窗口复算一致 100% | AC-004-003、004 | 误标降温次数为 0 |
| R5 | 代表帖子/评论引用正确定位版本与样本边界 | 受控通过 | 抽查 20 条引用 100% 可回原文 | AC-004-005 | 只有计数时虚构正文的次数为 0 |
