# 39 个人事件分析

依据：[39 个人事件分析](../requirement/39-个人事件分析.md)；设计：[39 个人事件分析](../design/39-个人事件分析.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-39-01 解释本人事件变化

**Card**：作为个人监测用户，当理解并纠正事件组织时，我希望能够核对本人事件证据与变化，以便理解事件依据并修正误判。

**Conversation**：使用FR-39-01及BR-39-01确定范围。需要讨论的边界为“重复转载不算新事实，48小时值不标成24小时”；需对齐的业务输入合同为05纠错、07去重、10许可，不以当前实现是否方便决定取舍。

**Confirmation**：AC-39-01使用固定输入“同一r1被两个操作同时更正，另有跨主题事件”，执行“预览影响并提交纠错”，核对“事件修订和材料版本可回溯；覆盖改变说明不可比。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

### US-39-02 纠正事件组织

**Card**：作为个人监测用户，当理解并纠正事件组织时，我希望能够预览并提交事件纠错，以便理解事件依据并修正误判。

**Conversation**：使用FR-39-02及BR-39-01确定范围。需要讨论的边界为“纠错不能改原帖身份、覆盖他人修订或复活撤回证据”；需对齐的业务输入合同为05纠错、07去重、10许可，不以当前实现是否方便决定取舍。

**Confirmation**：AC-39-02使用固定输入“同一r1被两个操作同时更正，另有跨主题事件”，执行“预览影响并提交纠错”，核对“成功产生新修订并保留历史；冲突要求核对当前版本。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

## 验收与发布门槛

本编号交付先满足FR-39和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
