# 43 刊期内部详情与修订

依据：[43 刊期内部详情与修订](../requirement/43-刊期内部详情与修订.md)；设计：[43 刊期内部详情与修订](../design/43-刊期内部详情与修订.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-43-01 修正刊期内容

**Card**：作为刊物编辑，当修正一期内容而不覆盖历史时，我希望能够修订固定刊期内容，以便修正内容而保留版本依据。

**Conversation**：使用FR-43-01及BR-43-01确定范围。需要讨论的边界为“并发修订不覆盖，撤回材料不能从旧修订重新发布”；需对齐的业务输入合同为42刊期、48许可，不以当前实现是否方便决定取舍。

**Confirmation**：AC-43-01使用固定输入“两个编辑同时基于r1修改，某引用撤回”，执行“保存修订并预览发布内容”，核对“历史修订不被原地覆盖，选材仍有当前许可与证据。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

数据合同先行，数据提供方与消费入口可按同一合同独立开发；关联编号不是相互完成前置。任务按下表顺序推进；共享实现步骤只维护一次，各故事通过同序号FR/AC关联。任何发现的设计缺口先补同编号规格，再实施。

## 验收与发布门槛

本编号交付先满足FR-43和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
