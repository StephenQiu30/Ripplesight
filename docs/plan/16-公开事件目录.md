# 16 公开事件目录

依据：[16 公开事件目录](../requirement/16-公开事件目录.md)；设计：[16 公开事件目录](../design/16-公开事件目录.md)。采用pm-execution的Card / Conversation / Confirmation拆解。本文定义交付工作，不登记进度，不授权提交推送、真实请求或数据库改造。

## 用户故事与工作拆解

### US-16-01 发现公开具体事件

**Card**：作为公开读者，当寻找具体事件时，我希望能够筛选公开具体事件，以便发现值得深入阅读的具体事情。

**Conversation**：使用FR-16-01及BR-16-01确定范围。需要讨论的边界为“集合不足不制造事件，私有事件不因排序进入公开集合”；需对齐的业务输入合同为04事件、48发布，不以当前实现是否方便决定取舍。

**Confirmation**：AC-16-01使用固定输入“同主体两件事件及一个不足证据线索”，执行“筛选并按明确时间维度排序”，核对“每条区分事件、线索和证据不足；只包含当前可公开信息。”，并验证对应反例。界面样本通过与真实业务验收分别记录。

数据合同先行，数据提供方与消费入口可按同一合同独立开发；关联编号不是相互完成前置。任务按下表顺序推进；共享实现步骤只维护一次，各故事通过同序号FR/AC关联。任何发现的设计缺口先补同编号规格，再实施。

## 验收与发布门槛

本编号交付先满足FR-16和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。核心需取得相应真实来源/模型/自然窗口/送达证据；辅助功能还须先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。
