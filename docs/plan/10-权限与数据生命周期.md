# 10 权限与数据生命周期

PLAN-10，面向agent的执行交接。业务依据：[10 权限与数据生命周期](../requirement/10-权限与数据生命周期.md)；开发交接：[10 权限与数据生命周期](../prd/10-权限与数据生命周期.md)；目标方案：[10 权限与数据生命周期](../design/10-权限与数据生命周期.md)。故事与用户价值只在PRD维护，当前差距、执行次序及证据只在[BACKLOG](../../BACKLOG.md)。本文件不新增提交推送、真实请求或业务库变更授权。

## 启动输入与就绪检查

实施前必须按[PLAN内嵌SPEC规范](../index.md#plan内嵌specsdd)完善本文件的SPEC开发合同并独立评审，记录PLAN的Git版本和FR/AC/US/T映射。没有就绪SPEC不得开始依赖其合同的代码改动。

1. 读取同编号需求、PRD、设计及[工程规范](../../AGENTS.md)，从BACKLOG选择当前优先级内的一个可独立验证切片；记录起始提交与已有工作区差异。
2. 本切片覆盖US-10-01、US-10-02、US-10-03中的明确子集，并关联同序号FR/AC（00为GOV、11为VR）；下面是能力工作包，不要求一次提交实现本编号全部内容。
3. 上游业务输入为“29身份、08来源政策”；核对已评审合同的字段、版本、权限、缺失与未知含义。提供方和消费入口可按同一合同准备，不将关联页面全部完成设为前置。
4. 未冻结决策见PRD“假设与开放问题”；仅当它影响本切片的预期行为、数据完整性或验收时停止相关实施。需要真实来源/模型/通知、收费或业务库操作时，先核对现行授权与准入；受控样本准备可继续。

## SPEC 开发合同

本节承载本PLAN各实施切片的可执行规格，不另建SPEC文件。启动时从上述US/FR/AC选定一个切片，依据同编号设计冻结以下合同后再执行工程任务：

- 范围与追踪：明确本次FR/AC/US/T子集、非目标、可消费依赖及未解决决策。
- 行为与不变量：输入输出、状态转换、权限、时间/未知含义、重复及并发结果。
- 技术边界：接口/数据约束与设计引用、事务/锁序/幂等、外部副作用和失败恢复。
- 验证与切换：逐合同场景的起始状态→操作→预期→证据；数据/消费者切换、回退和停止条件。

本节为开发门槛，尚未冻结具体切片合同时不能宣称就绪；不从旧代码补造需求。跨PLAN共享合同引用所属PLAN的SPEC，禁止复制成第二真源。评审版本以Git提交固定，实际结果只写BACKLOG。

### CORE-01 独立账本与恢复屏障切片

覆盖FR/AC-10-01/02、BR-10-01及US-10-01/02中的旧备份恢复反例，执行T-10-03/04；共享身份失效合同引用[PLAN-29 SPEC](29-登录与验证注册.md#spec-开发合同)。目标是恢复后仍执行当前删除/撤权事实，不能以dump/restore成功或临时库校验成功替代开放读取许可。

**实施前决定性合同**：按[设计10](../design/10-权限与数据生命周期.md#权限矩阵与生命周期执行)冻结独立账本介质及故障域、持久确认与业务提交失败的协调、资源/原生身份摘要的规范化版本、可验证连续游标/高水位、保留及账本自身恢复策略；同时冻结恢复时密码/第三方绑定/账户删除或停用/credential_version回退的权威处理，不能把引用PLAN-29的在线失效合同当成恢复授权方案。这些未冻结时不得开始依赖其安全性的业务恢复实现；可以独立准备反例样本和只读消费者清单。RPO/RTO数值由恢复方案评审及演练确定，不由agent编造。

| 合同 | 实施时必须证明的结果 |
|---|---|
| 独立性与最小化 | 账本不随旧业务备份回退，不被资源FK级联删除；只保留设计允许的最小标识/原因/时间/operation及期限，不存正文/验证码/凭据 |
| 账本保留与备份年龄 | 账本/tombstone覆盖全部仍允许恢复的一致性点；合法清理或截断后，缺完整删除证明的更旧备份拒绝开放，不以“保留期已到”允许复活正文 |
| 写入与失败 | 明确何时删除/撤权生效、持久确认及幂等；覆盖账本写失败、业务提交失败、进程中断和重试，不以双存储顺序调用假装原子 |
| 恢复输入 | 备份身份/一致性点、schema版本、独立账本有效范围及重放高水位都可核对；时间戳本身不充当连续完整性证明 |
| 恢复状态 | 隔离→基础恢复→账本校验→幂等重放→派生物/附件及身份失效复核→允许开放；缺失、损坏、断档、重放或复核失败一律保持隔离 |
| 全入口隔离 | API、Worker、Scheduler、队列/outbox、模型/通知、对象文件直出和缓存均受围栏约束；重放完成前旧任务不得执行或外发，预签名附件不能旁路 |
| 当前事实与追赶 | 恢复期间新发生的删除/撤权纳入最终追赶及切换屏障；旧政策不得覆盖当前更严格政策；明确切换期间写入围栏 |
| 身份与消费者 | 旧会话/未完成挑战不得因恢复重新生效；旧密码/第三方绑定/已删除或停用账户/凭据版本不得从旧备份重新获得授权；正文、标题、计数、修订、媒体、缓存/索引、报告、事件、导出及公开投影按当前合同重验 |
| 回退 | 回退仍受独立账本和读取屏障约束，不回退到“恢复成功即可开放”的错误方案；仅对明确授权目标操作 |

验证样本先在独立库制作“备份→删除/撤权→恢复”，断言恢复前后的A本人/B他人/匿名读取、历史/导出及附件字节；再覆盖账本缺失/损坏/断档、账本合法过期或截断但备份更旧、重复重放、中途失败、恢复期间新撤权、旧会话/挑战/密码/绑定及账户停用或删除、旧排队任务/通知/outbox外发、预签名附件旁路、对象缺失和清理失败。每例记录隔离状态、重放水位、可读投影及无泄漏结果；真实业务库/真实对象演练单独授权和取证。规格评审及样本通过后才选择实际工程切片，不将本段合同清单视为实现完成。

## 停止条件与交付输出

- 需求、PRD和设计冲突或缺少决定性合同：列明冲突条款，先修正规格并评审，不能按旧代码自行选择答案；不受影响的只读核对和受控样本可继续。
- 发生越权、未准入外发、超预算或被停止作用域仍发新请求：立即停止相关路径并处理硬门槛；未知外部效果先核对，不盲目重试。
- 实施输出须列变更文件/合同、对应US/FR/AC、验证结果、数据迁移/恢复影响、未通过或未执行范围，并取得独立只读审查。没有真实证据保持待验收。
- 更新BACKLOG后按已有授权提交与推送；提交前检查无无关改动、秘密或虚假通过结论。没有团队容量/历史吞吐量时只列依赖次序，不编造工期、人员或故事点。

## 验收与发布门槛

本编号交付先满足FR-10和全部AC，质量方法见[11 质量评测与验收](../requirement/11-质量评测与验收.md)。涉及真实来源/模型/自然窗口/送达的AC须取得相应真实证据；其余模块按自身AC取证，辅助功能先确认用户价值与批次。读界面、工程样本、数据迁移和真实业务验收互不替代。

每项任务将实际结果、证据范围、未冻结参数、阻塞及下一步写入根目录BACKLOG；没有证据则保持待验收。实施需要的提交/推送与真实外部请求按AGENTS及已有授权单独处理。
