### CORE-01 独立账本与恢复屏障切片

覆盖FR/AC-10-01/02、BR-10-01及US-10-01/02中的旧备份恢复反例，执行T-10-03/04；共享身份失效合同引用[PLAN-29 SPEC](29-登录与验证注册.md#spec-开发合同)。目标是恢复后仍执行当前删除/撤权事实，不能以dump/restore成功或临时库校验成功替代开放读取许可。

方案分为R1账本输入验证与隔离重放复演、R2在线独立拒绝账本、R3身份/附件及全入口屏障、R4追赶与切换。先执行R1；它消费固定账本样本，不接管在线删除，不产生开放许可。R2～R4的决定性输入未就绪时不能用R1结果代替它们。完整目标见[设计10恢复方案](../design/10-权限与数据生命周期.md#独立账本与恢复方案)。RPO/RTO及实际保留期仍由容量、许可和演练冻结，不由agent编造。

| 合同 | 实施时必须证明的结果 |
|---|---|
| 独立性与最小化 | 账本不随旧业务备份回退，不被资源FK级联删除；只保留设计允许的最小标识/原因/时间/operation及期限，不存正文/验证码/凭据 |
| 账本保留与备份年龄 | 账本/tombstone覆盖全部仍允许恢复的一致性点；合法清理或截断后，缺完整删除证明的更旧备份拒绝开放，不以“保留期已到”允许复活正文 |
| 写入与失败 | 明确何时删除/撤权生效、持久确认及幂等；覆盖账本写失败、业务提交失败、进程中断和重试，不以双存储顺序调用假装原子 |
| 恢复输入 | 备份身份/一致性点、schema版本、独立账本有效范围及重放高水位都可核对；时间戳本身不充当连续完整性证明 |
| 恢复状态 | 隔离→基础恢复→账本校验→幂等重放→派生物/附件及身份失效复核→允许开放；缺失、损坏、断档、重放或复核失败一律保持隔离 |
| 全入口隔离 | API、Worker、Scheduler、队列/outbox、模型/通知、对象文件直出和缓存均受围栏约束；重放完成前旧任务不得执行或外发，预签名附件不能旁路 |
| 当前事实与追赶 | 恢复期间新发生的删除/撤权纳入最终追赶及切换屏障；旧政策不得覆盖当前更严格政策；明确切换期间写入围栏 |
| 身份与消费者 | 旧会话/未完成挑战不得因恢复重新生效；旧密码/第三方绑定/已删除或停用账户/凭据版本不得从旧备份重新获得授权；正文、标题、计数、修订、媒体、缓存/索引、报告、事件、导出及公开投影按当前合同重验 |
| 回退 | 回退仍受独立账本和读取屏障约束，不回退到“恢复成功即可开放”的错误方案；仅对明确授权目标操作 |

验证样本先在独立库制作“备份→删除/撤权→恢复”，断言恢复前后的A本人/B他人/匿名读取、历史/导出及附件字节；再覆盖账本缺失/损坏/断档、账本合法过期或截断但备份更旧、重复重放、中途失败、恢复期间新撤权、旧会话/挑战/密码/绑定及账户停用或删除、旧排队任务/通知/outbox外发、预签名附件旁路、对象缺失和清理失败。每例记录隔离状态、重放水位、可读投影及无泄漏结果；真实业务库/真实对象演练单独授权和取证。规格评审及样本通过后才选择实际工程切片，不将本段合同清单视为实现完成。

#### R1 账本输入验证与隔离重放复演

**范围与就绪**：覆盖FR/AC/US-10-01/02恢复反例及T-10-03/04的明确子集。实现backups账本快照合同、evidence事务内拒读重放、临时恢复工具和CLI消费者；本切片不更改业务DDL，不增加长期正文库。读入快照是独立账本的交换格式，不是已部署的账本权威库。独立审查通过并以Git提交固定本SPEC后开始代码；人工可信checkpoint和固定快照可作为受控样本，不据此批准生产来源。

**独立账本及后续写入协议**：目标选择独立PostgreSQL实例/专库、独立凭据及备份生命周期，由单一账本事务原子分配连续sequence、追加事件、更新head和检查operation唯一。它不能包含业务资源FK，也不能随业务dump恢复。同机专库只能证明独立回退域；硬件/管理故障域、账本自身备份恢复及部署凭据在R2准入时验证。本轮不建立该权威库或启用写入，不把JSON样本当作持久确认。R2须账本先持久化保守deny，并让所有相应在线读取/采集授权消费此deny后才回写业务投影；业务失败或未知不能撤销deny，只能按相同operation重试。仅业务outbox或两次顺序提交不构成完成。原生身份/来源/账户级事件另冻结规范化版本，R1不猜测映射。

**R1交换数据合同**（所有模型拒绝额外字段，未知版本/动作/原因拒绝）：

| 输入 | 固定字段与约束 |
|---|---|
| snapshot | format_version=`ripplesight.recovery-ledger.v1`；ledger_id UUID；epoch正整数；normalization_version=`resource_uuid.v1`；entries为完整的1..N事件序列，最大10000项 |
| entry | sequence正整数；operation_id、owner_id、resource_id均为UUID；action=`deny_resource`；resource_type匹配`[a-z][a-z0-9_]{0,63}`；reason为user_request/retention_expired/authorization_revoked/source_deleted；occurred_at为有时区时间；previous_digest、digest为小写64位SHA256 |
| trusted checkpoint | format_version=`ripplesight.recovery-checkpoint.v1`；ledger_id/epoch/normalization_version；backup_id、archive_sha256、schema_sha256精确绑定本次备份；head_sequence非负且<=10000；head_digest为可信当前水位 |

文件最多16MiB，必须是600普通文件，拒绝符号链接；checkpoint通过调用者的独立可信通道提供，CLI从指定大写环境变量读取JSON，不从candidate或snapshot复制head，也不把秘密或完整事件输出到日志。checkpoint文件/环境的真实性不是链摘要能证明的，R1人工输入仅用于复演，不具备上线授权效力。epoch由账本权威产生，不接受业务备份回退的epoch。

规范化：UUID输出标准小写带连字符文本；时间转UTC，固定6位微秒并以Z结尾；JSON键排序、ASCII转义、无空格分隔。genesis=SHA256(`ripplesight.recovery.genesis.v1`+NUL+规范化{ledger_id,epoch,normalization_version})；entry.digest=SHA256(`ripplesight.recovery.entry.v1`+NUL+规范化该entry除digest外的所有字段)。首条previous_digest=genesis，后续=前条digest。空序列head=genesis。验证完整序列、每个摘要、同owner的operation唯一及最终可信head；即使重复operation内容相同也不能追加第二条，生产者幂等返回原收据。仅比较时间戳、snapshot自报head或内部链完整均不通过。R1只接受从genesis完整重放，不支持截断/归档或增量游标；R2合法清理须提高最旧可恢复边界，没有覆盖证明的旧备份不得开放。

**隔离与重放**：

1. 先验证candidate与完整快照/checkpoint绑定；缺失、畸形、尾部截断、断号、冲突、错备份/epoch/摘要全部在CREATE前拒绝。R1拒绝所有带证据对象inventory的候选，避免将已撤回附件恢复到当前bucket；附件隔离属R3。
2. 只创建随机新临时库；CREATE时ALLOW_CONNECTIONS=false，撤销PUBLIC的数据库权限后才允许维护连接。非测试复演要求来源与维护角色不同，来源角色不得是superuser或维护角色成员；普通业务角色不得具有CONNECT。测试只使用hotkey_test_*和拥有的临时角色。数据库owner/superuser属于受信维护边界，不能据此声称抵御管理员。
3. 不注册API/Worker/Scheduler，不消费Kafka/outbox，不运行模型、通知、清理或对象适配器；CLI不输出临时库连接信息，不提供promotion/切换命令。旧密码/绑定/会话/挑战和旧任务即使存在于临时库，也没有业务入口。R1不能证明将来真实服务的全入口屏障。
4. 基础恢复先核对原manifest完整性及表计数，然后在一个PG事务重放全部事件（包含checkpoint之前的事件，不能漏掉账本已写而业务未提交的intent）。通过evidence公开合同按owner/type/id精确找资源并锁定；先核对operation是否已指向另一资源，再处理目标缺失或已有拒读的幂等返回，不能用目标缺失跳过冲突。新记录使用原operation/reason/time生成拒读和待处理清理回执；即使没有cleanup_targets也保持pending，不能把“未评估/未执行清理”记成物理完成。既有完成回执不据此新增擦除证据。物理清理不在复演执行，不声称正文或派生物已被抹除。
5. 每个匹配资源重放后核对生命周期可读查询不可得；任一步/提交失败整批回滚，不返回成功水位。重复运行同一批不增加拒读记录。未匹配资源仅表示此恢复快照没有相同身份，不能证明原生身份重采阻断。
6. 成功回执仅包含backup_id、验证范围、指定ledger/epoch/head、匹配资源数及用时；replay_verified只指该有限批次，service_open_permitted固定false。普通verify-restore与maintenance的完整性校验也必须明确integrity_verified和service_open_permitted=false，不再把完整性成功写成泛化restore_verified=true。
7. 成败都关闭连接并删除本次实际创建的临时库；删除失败作为失败返回，不能宣称已清理。R1不存在持久恢复目标或解除隔离动作；中断后遗留目标仍只有维护权限，后续仅按拥有证明处理，不扫描删除别人的库。

**验证矩阵与产物**：

| 起始状态→操作 | 预期与证据 |
|---|---|
| 无对象候选、A/B不同owner、A资源备份后受限→重放 | 原表计数先通过；A资源生命周期拒读，B不受影响；无服务/对象/队列副作用，回执不允许开放 |
| 完整空序列+正确genesis/checkpoint→复演 | 只证明空批次校验，不能据此证明历史删除完整或允许开放 |
| 缺checkpoint、错备份/epoch、断号/尾截断/改字段/未知版本/重复operation→复演 | 在创建库前拒绝，无成功水位 |
| 同批次重复重放、资源已删除/已有指令→重放 | 幂等；不回退政策，不重复创建指令或越owner写入；operation指向别的资源即使新目标缺失也拒绝；无清理目标仍不宣称已擦除 |
| 第二事件/事务提交失败→重放 | 整批回滚；服务保持不可开放；临时目标清理 |
| 原备份含附件→复演 | 创建前拒绝；不调用当前bucket恢复器，不返回字节 |
| 临时库存在→以非维护业务角色检查CONNECT | PUBLIC拒绝；业务角色不可连接；源superuser/维护成员的非测试配置拒绝 |
| 完整性成功、重放成功或清理失败→CLI/维护回执 | 明确区分验证范围；任何情况不产生开放许可；清理失败失败返回 |

R1-A冻结并评审本合同；R1-B实现输入验证、事务内重放及隔离消费者；R1-C执行后端全门禁、真实隔离PG dump/restore反例、CLI/maintenance回执及独立代码审查。所有结果只写BACKLOG。R2在线账本权威接入、R3全入口/身份/对象隔离、R4最终追赶与切换仍须独立SPEC就绪，不因R1通过关闭CORE-01。切换/回退不得把完整性校验当开放许可，也不能激活旧身份或旧预签名链接。

## 停止条件与交付输出

- 需求、PRD和设计冲突或缺少决定性合同：列明冲突条款，先修正规格并评审，不能按旧代码自行选择答案；不受影响的只读核对和受控样本可继续。
- 发生越权、未准入外发、超预算或被停止作用域仍发新请求：立即停止相关路径并处理硬门槛；未知外部效果先核对，不盲目重试。
- 实施输出须列变更文件/合同、对应US/FR/AC、验证结果、数据迁移/恢复影响、未通过或未执行范围，并取得独立只读审查。没有真实证据保持待验收。
- 更新BACKLOG后按已有授权提交与推送；提交前检查无无关改动、秘密或虚假通过结论。没有团队容量/历史吞吐量时只列依赖次序，不编造工期、人员或故事点。
