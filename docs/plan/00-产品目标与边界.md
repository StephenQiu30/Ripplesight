# 00 产品目标与边界

PLAN-00，面向agent的执行交接。业务依据：[00 产品目标与边界](../requirement/00-产品目标与边界.md)；开发交接：[00 产品目标与边界](../prd/00-产品目标与边界.md)；目标方案：[00 产品目标与边界](../design/00-产品目标与边界.md)。故事与用户价值只在PRD维护，当前差距、执行次序及证据只在[BACKLOG](../../BACKLOG.md)。本文件不新增提交推送、真实请求或业务库变更授权。

## 启动输入与就绪检查

实施前必须按[PLAN内嵌SPEC规范](../index.md#plan内嵌specsdd)完善本文件的SPEC开发合同并独立评审，记录PLAN的Git版本和FR/AC/US/T映射。没有就绪SPEC不得开始依赖其合同的代码改动。

1. 读取同编号需求、PRD、设计及[工程规范](../../AGENTS.md)，从BACKLOG选择当前优先级内的一个可独立验证切片；记录起始提交与已有工作区差异。
2. 本切片为治理交付（不新增产品功能），覆盖US-00-01、US-00-02、US-00-03中的明确子集，并关联同序号FR/AC（00为GOV、11为VR）；下面是能力工作包，不要求一次提交实现本编号全部内容。
3. 总体评审输入为“原始OR、08准入、10权限、11质量合同”；核对范围、前置保护、证据性质、版本及待决策。提供方和消费入口可按同一合同准备，不将关联页面全部完成设为前置。
4. 未冻结决策见PRD“假设与开放问题”；仅当它影响本切片的预期行为、数据完整性或验收时停止相关实施。需要真实来源/模型/通知、收费或业务库操作时，先核对现行授权与准入；受控样本准备可继续。

## SPEC 开发合同

本节承载本PLAN各实施切片的可执行规格，不另建SPEC文件。启动时从上述US/FR/AC选定一个切片，依据同编号设计冻结以下合同后再执行工程任务：

- 范围与追踪：明确本次FR/AC/US/T子集、非目标、可消费依赖及未解决决策。
- 行为与不变量：输入输出、状态转换、权限、时间/未知含义、重复及并发结果。
- 技术边界：接口/数据约束与设计引用、事务/锁序/幂等、外部副作用和失败恢复。
- 验证与切换：逐合同场景的起始状态→操作→预期→证据；数据/消费者切换、回退和停止条件。

本节为开发门槛，尚未冻结具体切片合同时不能宣称就绪；不从旧代码补造需求。跨PLAN共享合同引用所属PLAN的SPEC，禁止复制成第二真源。评审版本以Git提交固定，实际结果只写BACKLOG。

#### 全站边距与响应式修正

承接用户对当前页面边距过大、响应式不足的明确修正，覆盖T-00-05及NFR-12，继承已冻结视觉SPEC的业务、权限与副作用边界。几何以[共享外壳约束](../design/00-产品目标与边界.md#外壳与组件约束)为准，覆盖此前固定1280px容器与48px边距；不调整业务合同。断点按正文内容盒宽度计算（不含侧栏与左右padding），覆盖56rem/64rem门槛前后及侧栏拖动/折叠；按正文可用宽度切换阅读/刊物与工作台栏数，页头可换行、首页窄屏搜索可用、加载与内容同几何。全宽布局保留登录表单和长文/说明正文的内层可读行宽，表格内部滚动不视为整页溢出；不能用overflow隐藏裁切内容来通过检查。缩放或拖动侧栏不能卸载编辑器、丢草稿或触发业务写入。

验证在独立回环样本服务与浏览器会话进行：8入口在1440px/390px的正常、空、加载、503、403，正常另查暗色；首页和共用分栏另查768/1024/1920/2560px、侧栏折叠/拖动、键盘与200%缩放等效重排及减少动态效果。正文边界无内容裁切，窄屏控件和恢复动作可达，允许表格内部滚动。按AGENTS §5执行Web/文档门禁与独立只读审查；结果只记BACKLOG。本次没有新增提交授权，文档修正保留为未提交差异，不声称已形成新的冻结提交。

#### 输入、不变量与失败恢复

1. 输入为10个已读取的 Figma 画板上下文/截图、现有生成客户端 DTO 和会话/路由合同。实施前复核当前 Git 差异，保留并行改动；本切片只修改前端及所属设计/PLAN/BACKLOG，不改后端、接口生成物、数据库、部署设置或冻结 App。
2. 无业务写入、采集、模型或通知副作用的新授权。页面读取只消费现有 `src/api`/`request.ts`；布局切换不能新增采集或丢草稿。现有写动作仅重新组合界面，保留校验、预期版本、错误码分支、未知效果和焦点恢复。
3. 正常、空、加载、错误、无权限、过期分别保留；区块错误不扩大为整页空，旧数据只在仍获许可时保留并标过期，401/403不显示旧私有内容。缺指标不补零、不由当前页外推总数，不画示意曲线。
4. 未支持的关注、评论检索、跨类型收藏、排名历史、邮件订阅或24h统计不在视觉切片中伪实现；保留清晰缺口及合法操作。若还原需要改变这些合同，停止相应功能，先完善所属PLAN并独立评审；其他视觉切片可继续。
5. 静态资产仅使用与Figma对应且非空的本地文件；动态来源图像继续来自获许可数据。核对文件、画板位置、调用点及浏览器有效尺寸，禁止将整页截图当产品背景。外部临时素材URL不进入代码。
6. 继续使用现有 Next.js App Router、服务端读取和小范围客户端交互；按Vercel官方文档核对构建、边界及图片处理，不擅自发布、迁移部署、修改环境变量或订阅付费服务。
7. 回退按实际修改文件的差异逐项撤销本切片，保留并行编辑、用户偏好和存储；不执行整工作区reset。不涉及数据迁移或数据库回滚。

#### 冻结与执行门槛

独立只读评审本节及对应共享设计，修复阻断后取得本人明确的本地SPEC提交授权，再以Git提交固定版本；未经授权不提交、不推送。冻结前允许完成设计取证、路由/组件差距核对、文档检查及受控验证准备，不能开始依赖本合同的产品代码改动。后续各页面实施引用同一共享视觉合同；业务合同仍以所属PLAN为准。

## 停止条件与交付输出

- 需求、PRD和设计冲突或缺少决定性合同：列明冲突条款，先修正规格并评审，不能按旧代码自行选择答案；不受影响的只读核对和受控样本可继续。
- 发生越权、未准入外发、超预算或被停止作用域仍发新请求：立即停止相关路径并处理硬门槛；未知外部效果先核对，不盲目重试。
- 实施输出须列变更文件/合同、对应US/FR/AC、验证结果、数据迁移/恢复影响、未通过或未执行范围，并取得独立只读审查。没有真实证据保持待验收。
- 更新BACKLOG后按已有授权提交与推送；提交前检查无无关改动、秘密或虚假通过结论。没有团队容量/历史吞吐量时只列依赖次序，不编造工期、人员或故事点。

## 业务依赖与发布门槛重评

业务顺序为意图→准入/预算→采集/讨论→身份/覆盖→相关排序→事件/事实→自然窗口→评估/消息→本人接收。10权限及11质量贯穿全部阶段。06调度可先开发，07消费链完整后再正式观察，不能把“七日已经通过”设为提醒开发前置。

每个阶段由实现负责人交付合同和产物、独立审查代理只读核对、验收负责人冻结指标并对真实证据负责；具体人选、容量/质量门槛、来源完整名单、首批提醒类型和相对排期在BACKLOG对应决策项确认。不能靠新增文档或测试数量估计完成度。数据库实施前另做字段/DDL约束、真实查询负载、数据映射、恢复及回退设计；本轮不修改运行数据库。
