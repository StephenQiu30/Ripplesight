## 当前实现口径与证据边界

游标以当前会话的服务端 CSRF 摘要签名，并绑定 owner、筛选、页大小、首次查询时刻及最后一条窗口身份；排序固定为 `(due_at, id)` 倒序。后续页只读取首次查询时刻之前持久化且排序键更小的到期事实。列表一次选中至多 100 条，再分别批量读取 Job、attempt、覆盖窗、网络请求尝试、预算、内容观察、热榜快照、标注及当前连接版本/启停状态；不在 Router 执行 SQL。

`coverage_status` 区分 `unattempted/running/confirmed/empty/partial/failed/stopped/analysis_pending`。没有 Job 的请求、页、观察、预算和分析计数为 null；有 Job 且 `requests_sent=0` 时无请求观察数为已证实的 0。热榜只有成功持久化原桶快照才可为 `empty/confirmed`；关键词只在全部覆盖窗有可信 confirmed 证据后确认。未确认时 `gaps` 保守返回整个原窗口及原因，不假装精确知道尾段起点；预算请求尝试无法对齐持久预留/实扣时降为 partial。`last_success_at` 取同 owner、来源、能力且到期点不晚于当前窗的最近成功 Job 完成时刻。预算上限取本 Job 已触及网络请求策略中最紧的上限；预留/实耗按唯一请求尝试计算，缺乏账本证据返回 null。分析状态仅在主题及内容版本身份明确时汇总，否则为 null。

EV-002-017/018 覆盖隔离 PostgreSQL 的受控窗口、运行 OpenAPI、非空关键词内容/标注/多策略预算/多 attempt 的 HTTP 与原始表对账。EV-002-027 先以定时 HN Job 的 `search_scope_invalid` Red 暴露执行器不接受调度追加的 `schedule_key/due_at`；增加严格字段、UTC 到期点和窗口终点校验后，受控及真实 HN 调度→执行→覆盖 API 对账通过。真实 RSSHub `/36kr/hot-list` 保存原桶 8 条快照并与 API 对账。EV-002-029 再核对 Google News 真实定时窗 1 次请求/页、82 条内容及 `partial/unverified_terminal` 缺口。G2 仍缺各场景完整的实施前 Red，G5 仍缺 SearXNG/36Kr 两个关键词来源与五榜逐窗核对，009 的连续 72 小时未验证，因此本 Plan 保持 `in_progress`。
