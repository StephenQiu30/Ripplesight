# 08 平台接入

PLAN-08，面向agent的执行交接。业务依据：[08 平台接入](../requirement/08-平台接入.md)；开发交接：[08 平台接入](../prd/08-平台接入.md)；目标方案：[08 平台接入](../design/08-平台接入.md)。故事与用户价值只在PRD维护，当前差距、执行次序及证据只在[BACKLOG](../../BACKLOG.md)。本文件不新增提交推送、真实请求或业务库变更授权。

## 启动输入与就绪检查

实施前必须按[PLAN内嵌SPEC规范](../index.md#plan内嵌specsdd)完善本文件的SPEC开发合同并独立评审，记录PLAN的Git版本和FR/AC/US/T映射。没有就绪SPEC不得开始依赖其合同的代码改动。

1. 读取同编号需求、PRD、设计及[工程规范](../../AGENTS.md)，从BACKLOG选择当前优先级内的一个可独立验证切片；记录起始提交与已有工作区差异。
2. 本切片覆盖US-08-01、US-08-02、US-08-03中的明确子集，并关联同序号FR/AC（00为GOV、11为VR）；下面是能力工作包，不要求一次提交实现本编号全部内容。
3. 上游业务输入为“00执行边界、10秘密管理”；核对已评审合同的字段、版本、权限、缺失与未知含义。提供方和消费入口可按同一合同准备，不将关联页面全部完成设为前置。
4. 未冻结决策见PRD“假设与开放问题”；仅当它影响本切片的预期行为、数据完整性或验收时停止相关实施。需要真实来源/模型/通知、收费或业务库操作时，先核对现行授权与准入；受控样本准备可继续。

## SPEC 开发合同

本节承载本PLAN各实施切片的可执行规格，不另建SPEC文件。启动时从上述US/FR/AC选定一个切片，依据同编号设计冻结以下合同后再执行工程任务：

- 范围与追踪：明确本次FR/AC/US/T子集、非目标、可消费依赖及未解决决策。
- 行为与不变量：输入输出、状态转换、权限、时间/未知含义、重复及并发结果。
- 技术边界：接口/数据约束与设计引用、事务/锁序/幂等、外部副作用和失败恢复。
- 验证与切换：逐合同场景的起始状态→操作→预期→证据；数据/消费者切换、回退和停止条件。

本节为开发门槛，尚未冻结具体切片合同时不能宣称就绪；不从旧代码补造需求。跨PLAN共享合同引用所属PLAN的SPEC，禁止复制成第二真源。评审版本以Git提交固定，实际结果只写BACKLOG。

**准备到实施的次序**：先核对来源及当前入口安全证据，再分别为确定查询/语言、显式旧帖跟踪、独立相关性和事实状态拆出最小SPEC；各片只以前述实际消费产物为依赖，不要求所有关联页面全部开发完毕。来源未真实准入、阈值未校准只阻塞对应外部验收或依赖这些值的行为，不阻塞通用合同与固定反例准备，也不改做完整账本迁移。

**可复现验证交接**：每片在所属PLAN写明“起始状态→操作→可观察结果→请求/持久化证据”，至少包含跨owner/错引用、撤权或清理后旧版本、分页/深度/上限、缺父、无关/不足/未知、重复和迟到、暂停/退出/到期、模型/目标停用及外部效果未知中的适用项。受控网络仅固定样本，数据库仅自建并清理的独立`hotkey_test_`库；不得触碰业务库或真实提供方。UI按1440/390五态与键盘验证，正式两轮自然运行、七日观察和本人收到提醒分别取真实证据，不由测试或手动发送替代。

**正式开工门槛**：把选定范围、决定性输入与实际消费者写入所属PLAN的具体SPEC，解决评审阻断并绑定Git版本后才能改相应代码。当前交接文档不授予代码解冻、真实请求、业务库升级或部署权限；完成证据、未就绪项及下一步只回填BACKLOG。

## 停止条件与交付输出

- 需求、PRD和设计冲突或缺少决定性合同：列明冲突条款，先修正规格并评审，不能按旧代码自行选择答案；不受影响的只读核对和受控样本可继续。
- 发生越权、未准入外发、超预算或被停止作用域仍发新请求：立即停止相关路径并处理硬门槛；未知外部效果先核对，不盲目重试。
- 实施输出须列变更文件/合同、对应US/FR/AC、验证结果、数据迁移/恢复影响、未通过或未执行范围，并取得独立只读审查。没有真实证据保持待验收。
- 更新BACKLOG后按已有授权提交与推送；提交前检查无无关改动、秘密或虚假通过结论。没有团队容量/历史吞吐量时只列依赖次序，不编造工期、人员或故事点。
